# 钉钉文档导入 E2E 原始数据

本目录只保存原始测试文件，不包含脚本、数据生成器或固定数据库 ID。自动化 E2E 由
`frontend/e2e/tests/knowledge/dingtalk-import.spec.ts` 驱动：真实前端、真实后端和真实
测试数据库，仅通过 mock 钉钉 MCP（`frontend/e2e/utils/mock-provider-mcp.ts`）模拟
钉钉 Provider，不模拟任何 Wegent 接口。

## 文件清单

| 文件                  | 用途                                     |
| --------------------- | ---------------------------------------- |
| `钉钉_产品说明_v1.md` | 单篇导入、文件夹导入、删除安全、来源失效 |
| `钉钉_产品说明_v2.md` | 删除旧文档后重新导入新副本               |
| `钉钉_接口规范.md`    | 批量部分失败与原地重试                   |
| `钉钉_归档说明.md`    | 文件夹递归展开为平铺文档                 |
| `测试对象与权限.md`   | 用户、知识库、目录和权限配置             |

## 与 mock 目录的对应

- `E2E_项目资料/`（`imp-root`）＝ `项目资料/`，包含 `E2E_产品说明`（`imp-product`）、
  `E2E_接口规范`（`imp-api`）和子文件夹 `E2E_归档`（`imp-sub`）；
- `E2E_归档/` 包含 `E2E_归档说明`（`imp-archive`）；
- `E2E_格式展示/`（`imp-formats`）单独包含 PDF、普通表格和 AI 表格，验证 PDF 可选、
  两类表格缺少各自配置时不可选，不混入三篇在线文档的批量导入场景；
- mock MCP 通过 `/mcp-control/config` 支持正文覆盖（v1 → v2）、读取失败注入、
  节点隐藏（来源失效）和正文响应暂停／放行（删除安全）。

每个场景独立建立并清理最小数据（知识库、同步节点），名称带唯一前缀，不依赖其他场景。

文件下载契约由后端 Provider 测试覆盖；本套 E2E 的真实索引闭环使用在线文档，
不宣称覆盖 PDF 下载到检索的完整链路，也不为本地 mock 放宽 HTTPS 或 SSRF 校验。
