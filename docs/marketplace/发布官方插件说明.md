# 发布官方插件到云端市场

插件目录信息存储在 MySQL 的 `plugins` 和 `plugin_releases` 中，经过扫描的
不可变 ZIP 存储在配置的 S3/MinIO 对象存储中。不要手工插入 Release 数据。

## WeWork 官方插件

WeWork 自研插件的源码位于：

```text
curated-plugins/wework/<plugin-slug>
```

发布命令：

```bash
cd backend
uv run python scripts/publish_official_plugin.py \
  ../curated-plugins/wework/<plugin-slug> \
  --slug <plugin-slug> \
  --listing-type plugin \
  --visibility public \
  --featured-rank 1 \
  --created-by-user-id 1 \
  --commit-sha "$CI_COMMIT_SHA" \
  --build-url "$CI_JOB_URL" \
  --publisher release-bot
```

官方插件统一使用：

```text
source_type=native
source_provider=wework
owner_user_id=NULL
```

同一 `slug + version + SHA256` 可幂等重试；同版本不同内容会被拒绝，不能覆盖
已经发布的 ZIP。

## 第三方开源镜像

第三方插件不进入 `curated-plugins/`。Backend 保存上游配置和确定性适配器，
定时从上游下载、扫描并默认直接发布 Release；高风险上游可切换为人工审核。

GitHub 镜像初始化：

```bash
cd backend

uv run python scripts/configure_github_connector.py --admin-user-id 1
uv run python scripts/configure_openai_github_mirror.py

# 可选：改为扫描后进入人工审核
uv run python scripts/configure_openai_github_mirror.py \
  --sync-policy review_required
```

第二条命令可在空数据库创建 GitHub 插件和上游记录，并立即同步一次。同步结果
默认扫描通过后直接设置 `latest_release_id` 并出现在市场中；指定
`review_required` 时才进入 Submission 审核队列。后续由 Celery Beat 每 6
小时检查一次上游。

## 前置条件

1. MySQL 已完成迁移。
2. S3/MinIO 插件对象存储已配置。
3. Redis、Celery Worker 和唯一的 Celery Beat 实例正在运行。
4. GitHub Connector 所需 OAuth 环境变量已配置。

## 验证

```sql
SELECT id, slug, source_type, source_provider, status, latest_release_id
FROM plugins;

SELECT plugin_id, version, status, scan_status, storage_key
FROM plugin_releases
ORDER BY id DESC;

SELECT plugin_id, marketplace_name, remote_plugin_id, sync_policy,
       last_seen_version, last_error
FROM plugin_upstreams;
```
