# 发布官方插件到云端市场

插件目录信息存储在 MySQL 的 `plugins` 和 `plugin_releases` 中，经过扫描的
不可变 ZIP 存储在配置的 S3/MinIO 对象存储中。不要手工插入 Release 数据。

> EchoID 企业内部上手步骤见：[发布EchoID插件.md](./发布EchoID插件.md)。

## WeWork 官方插件（两仓分流）

WeWork 自研插件按目标市场 Tab 分两个源码仓维护（布局均对齐
[openai/plugins](https://github.com/openai/plugins)）。**两仓内容不同，不是互为镜像**；
发布时用 `--visibility` 决定进哪个 Tab，前端不按 git URL 分流。

| 源码仓 | `--visibility` | Wework Tab |
| --- | --- | --- |
| [github.com/wecode-ai/wework-plugins](https://github.com/wecode-ai/wework-plugins) | `public` | Wework官方 |
| `git.intra.weibo.com/weibo_rd/common/wecode/wework-plugins` | `workspace`（默认） | 企业内部 |

仓库结构（两仓相同）：

```text
.agents/plugins/marketplace.json
plugins/<plugin-slug>/
  .codex-plugin/plugin.json
  skills/ | commands/ | hooks/ | ...
```

本地或 CI 检出后，每个插件目录为 `<checkout>/plugins/<plugin-slug>`，必须包含
`.codex-plugin/plugin.json` 与能力文件。源码仓只服务开发、评审与发布；
Backend / Wework 运行时不会扫描它。

建议与 Wegent **同级**分别检出，避免互相覆盖，例如：

```bash
# Wework官方（公开仓）
git clone https://github.com/wecode-ai/wework-plugins.git ../wework-plugins-public

# 企业内部（内网仓）
git clone ssh://git@git.intra.weibo.com:2222/weibo_rd/common/wecode/wework-plugins.git \
  ../wework-plugins
```

### 数据初始化（仅 Wework官方 / 公开仓）

空库或重建市场时，用下面脚本一次性发布公开仓全部插件（`visibility=public`）。
**不包含**内网仓企业内部插件。

```bash
cd backend

# 默认从同级 wework-plugins-public/plugins 读取；也可用 --plugins-dir / 环境变量
uv run python scripts/seed_wework_public_plugins.py

# 只打包扫描
uv run python scripts/seed_wework_public_plugins.py --dry-run
```

当前固定发布：`dingtalk`、`lark`、`product-design`、`wecom`。

### 发布到 Wework官方 Tab（单个插件）

```bash
cd backend

uv run python scripts/publish_official_plugin.py \
  ../wework-plugins-public/plugins/<plugin-slug> \
  --slug <plugin-slug> \
  --listing-type plugin \
  --visibility public \
  --featured-rank 1 \
  --created-by-user-id 1 \
  --commit-sha "$CI_COMMIT_SHA" \
  --build-url "$CI_JOB_URL" \
  --publisher release-bot
```

### 发布到企业内部 Tab

```bash
cd backend

uv run python scripts/publish_official_plugin.py \
  ../wework-plugins/plugins/<plugin-slug> \
  --slug <plugin-slug> \
  --listing-type plugin \
  --visibility workspace \
  --featured-rank 1 \
  --created-by-user-id 1 \
  --commit-sha "$CI_COMMIT_SHA" \
  --build-url "$CI_JOB_URL" \
  --publisher release-bot
```

官方插件统一使用：

```text
source_type=native
source_provider=wework
owner_user_id=NULL
```

同一 `slug + version + SHA256` 可幂等重试；同版本不同内容会被拒绝，不能覆盖
已经发布的 ZIP。

## 第三方开源镜像

第三方插件不进入上述两个 `wework-plugins` 仓。Backend 保存上游配置和确定性适配器，
定时从上游下载、扫描并默认直接发布 Release；高风险上游可切换为人工审核。

GitHub 镜像初始化：

```bash
cd backend

uv run python scripts/configure_github_connector.py --admin-user-id 1
uv run python scripts/configure_openai_github_mirror.py

# 可选：改为扫描后进入人工审核
uv run python scripts/configure_openai_github_mirror.py \
  --sync-policy review_required
```

第二条命令可在空数据库创建 GitHub 插件和上游记录，并立即同步一次。发布身份为
`source_provider=wework` + `visibility=public`（Wework官方 Tab），上游仍取自
`openai/plugins`。同步结果默认扫描通过后直接设置 `latest_release_id` 并出现在
市场中；指定 `review_required` 时才进入 Submission 审核队列。后续由 Celery Beat
每 6 小时检查一次上游。

## 前置条件

1. MySQL 已完成迁移。
2. S3/MinIO 插件对象存储已配置。
3. Redis、Celery Worker 和唯一的 Celery Beat 实例正在运行。
4. GitHub Connector 所需 OAuth 环境变量已配置。

## 验证

```sql
SELECT id, slug, source_type, source_provider, visibility, status, latest_release_id
FROM plugins
ORDER BY visibility, slug;

SELECT plugin_id, version, status, scan_status, storage_key
FROM plugin_releases
ORDER BY id DESC;

SELECT plugin_id, marketplace_name, remote_plugin_id, sync_policy,
       last_seen_version, last_error
FROM plugin_upstreams;
```
