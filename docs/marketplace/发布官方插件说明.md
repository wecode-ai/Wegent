# 发布官方插件到数据库

## 问题说明

你在本地启动后看不到 GitHub 等官方插件，是因为这些插件需要先发布到数据库中。插件数据不是硬编码的，而是存储在 MySQL 数据库的 `plugins` 和 `plugin_releases` 表中。

## 解决方案

### 方法一：运行发布脚本（推荐）

官方插件源代码位于 `curated-plugins/` 目录，你需要运行发布脚本将它们发布到数据库：

```bash
# 进入 backend 目录
cd backend

# 发布 GitHub 插件（需要先启动数据库）
uv run python scripts/publish_official_plugin.py \
  ../curated-plugins/openai/github \
  --slug github \
  --listing-type plugin \
  --visibility public \
  --featured-rank 1 \
  --created-by-user-id 1

# 如果你有其他官方插件，类似地发布
# uv run python scripts/publish_official_plugin.py \
#   ../curated-plugins/openai/gitlab \
#   --slug gitlab \
#   --listing-type plugin \
#   --visibility public \
#   --featured-rank 2 \
#   --created-by-user-id 1
```

**参数说明：**
- `source`: 插件源代码目录路径
- `--slug`: 插件的唯一标识符（URL-friendly）
- `--listing-type`: `plugin` 或 `skill`
- `--visibility`: `public`（所有人可见）或 `workspace`（需要授权）
- `--featured-rank`: 特色排序，数字越小越靠前
- `--created-by-user-id`: 创建者用户 ID（通常是管理员用户，ID=1）

**前置条件：**
1. MySQL 数据库已启动并运行迁移
2. 对象存储（MinIO/S3）已配置（在 `.env` 中）
3. 至少有一个用户存在（user_id=1）

### 方法二：批量发布所有官方插件

创建一个批量发布脚本：

```bash
#!/bin/bash
# 文件名: publish_all_official_plugins.sh

cd backend

# 遍历 curated-plugins 目录下的所有插件
RANK=1
for plugin_dir in ../curated-plugins/openai/*/; do
  if [ -f "${plugin_dir}/.codex-plugin/plugin.json" ]; then
    plugin_name=$(basename "$plugin_dir")
    echo "Publishing plugin: $plugin_name"
    
    uv run python scripts/publish_official_plugin.py \
      "$plugin_dir" \
      --slug "$plugin_name" \
      --listing-type plugin \
      --visibility public \
      --featured-rank $RANK \
      --created-by-user-id 1
    
    RANK=$((RANK + 1))
  fi
done

echo "All plugins published!"
```

使用方法：
```bash
chmod +x publish_all_official_plugins.sh
./publish_all_official_plugins.sh
```

### 方法三：手动插入数据库（仅用于开发测试）

如果你只想快速测试，可以手动在数据库中插入一条记录：

```sql
-- 1. 插入插件记录
INSERT INTO plugins (
  name, display_name, slug, 
  owner_user_id, 
  status, visibility, listing_type,
  source_type, source_provider,
  summary, description_md, 
  featured_rank,
  created_at, updated_at
) VALUES (
  'github', 'GitHub', 'github',
  1,
  'published', 'public', 'plugin',
  'native', 'wegent',
  '查看仓库、Issue、Pull Request 和 Actions，并在团队执行变更。',
  '连接到 GitHub 仓库进行代码管理和协作。',
  1,
  NOW(), NOW()
);

-- 2. 获取插件 ID（假设是 1）
SET @plugin_id = LAST_INSERT_ID();

-- 3. 插入一个虚拟的 release 记录（仅用于显示）
INSERT INTO plugin_releases (
  plugin_id, version, 
  storage_key, sha256, size_bytes,
  status, scan_status,
  manifest_json, interface_json,
  published_at, created_at, updated_at
) VALUES (
  @plugin_id, '1.0.0',
  'dummy-storage-key', 'dummy-sha256', 1024,
  'ready', 'passed',
  '{"name": "github", "version": "1.0.0"}',
  '{"displayName": "GitHub", "category": "开发工具"}',
  NOW(), NOW(), NOW()
);

-- 4. 更新插件的 latest_release_id
UPDATE plugins 
SET latest_release_id = LAST_INSERT_ID() 
WHERE id = @plugin_id;
```

**注意：** 这种方法插入的数据不完整，只能用于显示测试，无法真正安装使用。

## 验证

发布成功后，重启前端或刷新页面，应该能在插件市场看到 GitHub 插件了。

检查数据库：
```sql
-- 查看已发布的插件
SELECT id, name, display_name, slug, status, visibility, featured_rank 
FROM plugins 
WHERE status = 'published';

-- 查看插件的 release
SELECT r.id, r.plugin_id, p.name, r.version, r.status, r.scan_status
FROM plugin_releases r
JOIN plugins p ON p.id = r.plugin_id
WHERE r.status = 'ready';
```

## 常见问题

### Q1: 运行脚本时报错 "User not found"
**A:** 确保数据库中至少有一个用户（user_id=1）。你可以通过注册接口创建用户，或者手动插入：

```sql
INSERT INTO users (user_name, email, password_hash, is_active, created_at, updated_at)
VALUES ('admin', 'admin@wegent.local', '$2b$12$...', 1, NOW(), NOW());
```

### Q2: 脚本运行成功但前端看不到插件
**A:** 检查以下几点：
1. 插件的 `status` 是否为 `'published'`
2. 插件的 `visibility` 是否为 `'public'`
3. 插件是否有 `latest_release_id`
4. Release 的 `status` 是否为 `'ready'`，`scan_status` 是否为 `'passed'`
5. 前端是否已重启或刷新

### Q3: 对象存储配置问题
**A:** 检查 `backend/.env` 文件中的配置：
```
PLUGIN_STORAGE_TYPE=minio
PLUGIN_STORAGE_ENDPOINT=localhost:9000
PLUGIN_STORAGE_ACCESS_KEY=minioadmin
PLUGIN_STORAGE_SECRET_KEY=minioadmin
PLUGIN_STORAGE_BUCKET=plugins
```

如果本地没有 MinIO，可以临时设置为本地文件系统模式（需要修改代码支持）。
