# Wework 本机管理高级设置解锁

## 目标

默认精简应用 Tab 的“本机管理”页面，只展示本机依赖检测和快捷操作。以下区块归入隐藏的高级设置：

- 启动环境变量
- 连接诊断
- 本机插件
- 最近输出

## 解锁交互

页面标题“本机管理”保持原有视觉样式，不增加可见入口或提示。

用户在 3 秒内连续点击该标题 5 次后：

1. 立即展示全部高级设置区块。
2. 显示轻量 toast：“已开启高级设置”。
3. 将解锁状态写入 `localStorage`。

超过 3 秒未完成 5 次点击时，点击计数重置。高级设置已经开启后，继续点击标题不再重复提示或改变状态。

标题需要支持鼠标和触摸点击，但不伪装成常规按钮，也不加入键盘焦点顺序，因为该交互是刻意隐藏的发现机制。

## 持久化

使用 Wework 专属、语义明确的 `localStorage` key 保存布尔解锁状态。

应用重启、页面刷新和版本升级后继续展示高级设置。清除应用数据或完整卸载应用后，浏览器存储被删除，高级设置恢复默认隐藏。页面不提供重新隐藏的入口。

读取或写入存储失败时不阻断页面：

- 读取失败时按未解锁处理。
- 写入失败时，本次运行仍保持已解锁。

## 页面结构

`LocalManagementPage` 接收高级设置是否开启以及标题点击回调。标题之后的基础区块始终渲染；四个高级区块由一个共同条件控制，并保持现有顺序、布局、功能和测试属性。

隐藏状态下不渲染高级区块，避免环境变量表单、插件操作和日志内容出现在 DOM 中。

## Toast

代码库当前没有统一 toast 组件。此功能使用页面内轻量提示实现，不新增通知依赖：

- 固定显示在页面右下区域。
- 使用现有 Calm UI 色彩和圆角。
- 包含 `role="status"` 与 `aria-live="polite"`。
- 自动消失，不需要关闭按钮。
- 仅在首次成功解锁时显示。

## 测试

更新 `wework/src/App.apps.test.tsx`，覆盖：

1. 默认不渲染四个高级区块。
2. 3 秒内点击标题 4 次仍保持隐藏。
3. 第 5 次点击后展示全部高级区块并显示 toast。
4. 解锁状态写入 `localStorage`。
5. 页面初始化时存在持久化状态则直接展示高级区块。
6. 超出点击窗口后计数重置。
7. 已解锁时再次点击不会重复触发 toast。
