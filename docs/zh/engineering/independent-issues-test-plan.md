# 独立事项与协作导航验收

## 环境和数据

使用统一桌面 runner 的隔离 Electron、真实 Executor、Rust/Python 混合后端、临时 MySQL 和 Redis。只允许模型服务使用现有模拟。每个 checkpoint 自行准备用户和项目，不依赖此前运行的状态，不连接个人项目或生产租户。

准备创建者、受邀参与者和无关用户三个账户；只有创建者拥有目标项目。独立事项创建前后读取真实项目目录，确认没有创建隐藏项目。测试数据由统一云端夹具销毁；截图、日志和认证状态只保留在测试输出目录，不提交。

## 用户故事

| 故事                                       | 操作                                                 | 预期结果及负向覆盖                                                                                               |
| ------------------------------------------ | ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 作为员工，我想直接发起一件公司里的事       | 协作 → 新建事项，填写标题和描述并保存，不选择项目    | 事项持久化；项目数量不变；初始参与者为空；其他账户详情和评论读取均为 404                                         |
| 作为创建者，我想找同事一起处理             | 编辑 → 搜索同事 → 邀请参与 → 选择该同事负责 → 保存   | 参与者可读取并评论，在分配给我的和我参与的出现，在我创建的不出现；不能删除或增加邀请                             |
| 作为创建者，我要收回共享权限               | 编辑 → 移除参与者 → 保存                             | 同时清除该成员的负责人分配；撤销后的详情、评论和写入都被拒绝，历史评论不被删除                                   |
| 作为用户，我要快速找到相关工作             | 依次打开分配给我的、我创建的、我参与的               | 服务器在分页前按当前身份筛选；本地身份别名正确；切换范围不显示上一范围的数据，迟到响应不覆盖当前页面             |
| 作为用户，我要归档后再恢复事项             | 归档 → 关闭详情 → 查看已归档的独立事项 → 打开 → 恢复 | 归档记录在对应列表可见，恢复后回到活动列表；失败不伪装为空结果                                                   |
| 作为创建者，我想将事项纳入正式项目         | 关联项目，阅读权限提示，选择目标项目并确认           | 同一事务保留事项与讨论，分配项目编号，打开原有项目详情；不自动授予原参与者项目权限；没有目标项目编辑权限不能迁移 |
| 作为创建者，我要删除一件不用继续的事       | 删除事项 → 确认删除                                  | 参与者删除被拒绝；创建者确认后，该事项和讨论不可再读取；取消不改变数据                                           |
| 作为现有用户，我要继续使用首页和项目       | 打开首页、右侧助理、项目树；打开本地及空间内远程项目 | 复用 main 的原有首页、发起区、助理与详情标签；项目不重复，默认空间和业务空间保持 main 原有分组规则               |
| 作为协作管理员，我要找到原有配置           | 展开或收起协作管理，打开四个目录                     | 执行设备、模板、智能体、协作小组复用原目录和权限；不增加个人助理侧栏入口                                         |
| 作为并发协作者，我不能覆盖别人刚保存的内容 | 两个写入携带同一个事项版本；跨账户或排序复用游标     | 只有一个写入提交，另一个返回冲突；分页不重不漏，游标不能跨账户、范围、排序或归档条件复用                         |

## 验证入口

- 桌面故事：`pnpm --filter wework e2e:desktop --segment collaboration-personal-issues`。
- main 项目导航回归：`collaboration-space-project-tree`；首页请求和状态回归：`collaboration-home-preload`，均复用原 checkpoint。
- Rust API：`cargo test --manifest-path backend-rs/Cargo.toml -p wegent-backend-rs --lib personal_issues`；真实 MySQL 套件由现有 Backend Rust CI 的 MySQL 服务通过 `--ignored` 显式执行。
- 本地分页：`cargo test --manifest-path executor/Cargo.toml -p wegent-local-task-store my_work --lib`。
- Python 云端查询：`cd backend && uv run pytest tests/services/test_my_work_pagination.py tests/test_collaboration_permission_guard.py`。
- 前端定向覆盖：导航、首页、创建者分页、请求隔离、晚到响应与刷新失败保留结果。

执行记录以对应 PR 的实际命令结果和 CI 为准；测试计划本身不代表已完成真实桌面验证。失败必须保留原始日志并定位根因，不通过重试、延长通用超时或放宽断言取得通过。

## 并行测试性能证据

渲染层和 Electron 测试保持并行。Electron 命令复用 `run-with-resource-logging.mjs` 采集 runner 的 CPU、内存及 I/O 压力，并通过 Node 文件调用跟踪和 `node-async-resource-diagnostics.mjs` 记录各测试 worker 的待完成文件请求、慢请求、事件循环延迟与 CPU 时间。即时 JSONL 写入可在 Vitest 终止 worker 前保留证据；不记录文件路径、参数或内容。证据进入现有 `wework-test-evidence` CI artifact，不提交测试输出，也不通过扩大超时或重试替代根因分析。

同页的数据源故障集中在一个页面告警中，项目事项与独立事项分别保留重试入口；云端不可用不得阻塞本地事项或排序。复用原有 `collaboration-first-use` 真实桌面场景验证这一边界，不修改其单一告警断言。Linux CI 会按实测耗时重新分配 checkpoint，确认用例执行应读取 checkpoint 名称对应的运行日志，而非仅根据目录中的默认分片编号判断。
