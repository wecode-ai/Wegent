# 协作工作树验证计划

## 环境与边界

使用隔离 Electron、真实本地 Executor 和 runner 创建的 Git 仓库。仅模拟模型响应；项目配置、任务、Git 目录、快照由实际实现处理。不使用个人工作目录或修改个人 Git 配置。

自动回归入口：`pnpm --filter wework e2e:desktop -- --segment collaboration-worktree-policy`。该 checkpoint 注册于桌面 runner 和 Core CI 分片，单独运行时自行建立项目、执行环境和任务，不依赖先前 checkpoint。

## 用例

| 用例       | 步骤                                          | 预期                                                |
| ---------- | --------------------------------------------- | --------------------------------------------------- |
| 共享目录   | 初始化项目，选择共享目录并保存，创建任务      | 持久化 project 策略，实际任务不使用 worktree        |
| 切换策略   | 改为独立工作树并保存                          | fingerprint 和已就绪设备保持不变                    |
| 新任务隔离 | 创建独立任务                                  | workspaceKind 为 worktree，路径不同，真实 .git 存在 |
| 继续任务   | 向该任务发送后续消息                          | 任务 ID、目录不变，任务数量不增加                   |
| 智能体调度 | 分别在共享、独立策略下分配 Issue 给本地智能体 | 与手动会话使用相同策略，独立任务目录互不相同        |
| 取消回收   | 点击归档并回收，然后取消                      | 文件与目录仍存在                                    |
| 回收       | 写入未跟踪文件，确认回收                      | 目录移除，显示恢复入口                              |
| 恢复       | 点击恢复工作树                                | 原路径及未跟踪文件内容恢复，不自动运行任务          |

策略默认值、非 Git 项目、共享策略请求、环境配置持久化、本地队列和后端调度另有单元测试。工作树不可用时由执行预检显式阻止启动，不回退到共享目录。任务状态通过 Issue 关联和运行时查询读取，不以普通侧栏是否包含执行目录作为判断依据。

## 证据与清理

保留 runner 的执行日志、失败快照及关键步骤截图于 `wework/test-results/`，不提交这些产物。runner 退出时停止隔离进程；单独运行 ai:verify 后必须 stop 会话。PR 中记录实际通过的命令和未完成的验证，不把测试计划视为通过结果。
