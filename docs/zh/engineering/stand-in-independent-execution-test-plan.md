# 分身独立运行验证

## 用户故事与验收

作为 Wework 用户，我希望分身本身就是可配置职责的特殊智能体，创建或编辑时无需再选择另一个智能体。已有分身自动解除旧绑定，保留自身配置、身份、历史及原有授权范围。

- 创建、编辑和项目摘要不显示智能体选择或引用信息，也不加载个人或项目智能体目录。
- 分身只使用自身职责、显式模型及参数、设备、工作目录和连接，不继承其他智能体的提示词、技能、插件或策略；未指定模型时沿用独立分身默认规则。
- 旧项目绑定先与已选范围取交集，保留排除、开关、确认策略、版本和启用时间，再清除绑定。读取和保存均幂等，迁移不扩大权限。
- 保留默认云设备、明确设备选择、本机到云端的显式迁移、草稿恢复和会话身份。

## E2E 用例

使用现有桌面 checkpoint runner；仅模型服务响应为测试数据，Electron、Executor、Codex、SQLite、项目和原生确认链均使用真实实现。

| 用户场景             | 前置条件与步骤                                                         | 验收与 CI checkpoint                                                                             |
| -------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 新建独立分身         | 隔离本机项目；从项目入口创建、取消、重新打开并保存职责                 | 无智能体选择；取消不持久化；只连接当前项目；`stand-in`                                           |
| 旧绑定自动迁移       | 在隔离 SQLite 写入历史项目绑定及全项目选项；读取两次并重新打开设置     | 精确保留身份、版本、职责及确认策略；范围收敛到原所属项目；数据库持久化与重复读取一致；`stand-in` |
| 迁移后执行和标签扇出 | 为旧智能体配置独有提示词；迁移后分配新 Issue，再创建带标签的旧格式角色 | 实际模型收到分身自己的职责，未收到旧智能体提示词；每个匹配角色只执行一次；`stand-in`             |
| 云设备独立执行       | 真实远程 Executor 已获项目授权；创建独立云端分身并分配 Issue           | 无选择器和绑定字段；执行属于远程设备；本机配置不泄漏；不继承同项目智能体提示词；`stand-in-cloud` |
| 独立模型与工作目录   | 配置本机模型及代码目录，接收来源工作                                   | 模型和目录可配置；来源读取、网络、原生一次确认、拒绝与提权边界保持现有断言；`stand-in-workspace` |
| 错误恢复             | 保存前并发修改配置；取消或重试；设备离线时保留草稿                     | 版本冲突不覆盖；保留输入；离线不改选其他设备；现有桌面场景及聚焦组件测试                         |

三个 checkpoint 均已注册到现有 core CI 清单，由共享 Linux 分片规划器均衡调度；实际执行分片以 CI 规划结果和 checkpoint 日志为准，不新增 CI 任务。默认云设备相关组件测试和 `stand-in-cloud-device` checkpoint 保留主分支覆盖。跨存储同名项目、排除项、暂停来源、个人绑定、主分身绑定、无效旧引用和原子失败由 Rust 持久化契约测试覆盖。

## 执行与清理

项目视图导航通过共享助手在同一次 renderer 操作中选择当前可用的标签或下拉框。CI 里程碑回归的控制记录和失败快照证实，分开检查布局与点击会在响应式重排后等待已经卸载的标签。此修复保留场景断言与超时，并用组件测试覆盖控件替换和单次选择。

CI 周边回归继续复用原有场景与断言：`streaming-conversation-switching` 保留 520 个进度项和原有等待时限，结构化块事件进入既有 16ms 批次，逐项保序并在终态前全部刷新；`plugin-legacy-upgrade` 继续使用已交付的历史安装器，后端仅在实际发送的插件快照仍匹配当前期望时确认旧协议回执，防止迟到回执把新版本错误标记为已安装。快照仅在服务端保存，不进入旧设备的通信协议或公开响应。

聚焦命令：`pnpm --filter wework e2e:desktop --parallel-segments stand-in,stand-in-workspace`；远程场景沿用相同 runner 的 `--segment stand-in-cloud`。默认单 checkpoint 并发，复用同一构建产物。

测试使用 runner 的独立目录、账号数据和进程；结束时沿用既有 `finally` 清理。运行结果、完整失败日志及截图仅保存在本地 `wework/test-results/`，不提交。实际结果记录在 PR 验证说明中；远程环境不可用时明确报告，不能以组件测试冒充云端 E2E。
