# 分身独立运行验证

## 用户故事与验收

作为 Wework 用户，我希望分身本身就是可配置职责的特殊智能体，创建或编辑时无需再选择另一个智能体。已有分身自动解除旧绑定，保留自身配置、身份、历史及原有授权范围。

- 创建、编辑和项目摘要不显示智能体选择或引用信息，也不加载个人或项目智能体目录。
- 分身只使用自身职责、显式模型及参数、设备、工作目录和连接，不继承其他智能体的提示词、技能、插件或策略；未指定模型时沿用独立分身默认规则。
- 旧项目绑定先与已选范围取交集，保留排除、开关、确认策略、版本和启用时间，再清除绑定。主分身原本没有项目接入时不新增接入，也不阻断其他账号的读取。读取和保存均幂等，迁移不扩大权限。
- 保留默认云设备、明确设备选择、本机到云端的显式迁移、草稿恢复和会话身份。

## E2E 用例

### 单实例绑定、停止与换绑的用户故事

作为用户，我希望一个 Wework 实例只绑定一个本机或云端分身。我要换绑或迁移时，必须先停止整个当前分身，并取消其正在执行和排队的任务；停止失败不能绕过限制。分身内的主身份和场景角色共享这一生命周期，但不影响普通任务和其他账号。

| 用户故事             | 前置条件与操作                                             | 验收与覆盖                                                                                         |
| -------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 首次从项目打开分身   | 实例尚未绑定，云设备在线；打开指向本机分身的项目链接       | 首次绑定尊重明确链接；已有绑定不能被链接覆盖；组件测试与 `stand-in-cloud`                          |
| 活动实例不可直接切换 | 已绑定本机或云端分身；查看页头、角色设置和首次引导         | 不出现设备切换框，角色创建仍落在绑定设备；`stand-in-cloud-device`、`stand-in-workspace`            |
| 先停止，再换绑       | 真实云端 Codex 会话正在等待模型响应；在页头确认停止        | 模型连接实际取消，原生投影为 cancelled，整个分身停止后才出现换绑入口；`stand-in-cloud-device`      |
| 取消失败保持锁定     | 当前云设备离线；停止后重载页面，再恢复设备并重试           | 持久保留 stopping，不自动选其他设备；确认停止后才能换绑；`stand-in-cloud-device`                   |
| 保留身份与历史       | 本机创建角色、对话和记忆；停止后绑定云端，再绑定原本机分身 | 不复制其他设备的角色；原历史与记忆保留；`stand-in-cloud-device`                                    |
| 保留原有运行边界     | 显式换绑后配置模型、目录、Git 来源和项目接收范围           | 保留原有权限、原生拒绝、接收回执和并发跨设备去重断言；现有 model、Git、workspace、cloud checkpoint |

停止后迁移用例继续由 `stand-in-cloud-device` 执行：先取消确认，检查目标没有写入；再迁移所选角色到已经停止的真实云设备，检查职责与角色记忆落到同一副本、目标原配置保留、旧分身持续停止，副本暂停且不带源设备目录或来源授权，最后才切换绑定。失败和重试由迁移组件、工具函数及运行时契约交叉覆盖。

Rust 聚焦契约另外覆盖：一次取消同一任务的所有排队输入及活动回合、取消超时必须等真实停止确认、取消清理不能被处理锁阻塞、停止中不可恢复或修改配置，以及拒绝过时绑定版本。停止完成后只允许追加禁用的便携迁移副本，不能覆盖已有配置、携带设备权限或伪造恢复开关。组件测试覆盖停止确认期间绑定变化、未保存编辑确认和后台页面迟到读取。共享助手通过现有 checkpoint 清单映射到原有 CI，不增加任务或重试策略。

使用现有桌面 checkpoint runner；仅模型服务响应为测试数据，Electron、Executor、Codex、SQLite、项目和原生确认链均使用真实实现。

| 用户场景             | 前置条件与步骤                                                         | 验收与 CI checkpoint                                                                             |
| -------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 新建独立分身         | 隔离本机项目；从项目入口创建、取消、重新打开并保存职责                 | 无智能体选择；取消不持久化；只连接当前项目；`stand-in`                                           |
| 旧绑定自动迁移       | 在隔离 SQLite 写入历史项目绑定及全项目选项；读取两次并重新打开设置     | 精确保留身份、版本、职责及确认策略；范围收敛到原所属项目；数据库持久化与重复读取一致；`stand-in` |
| 迁移后执行和标签扇出 | 为旧智能体配置独有提示词；迁移后分配新 Issue，再创建带标签的旧格式角色 | 实际模型收到分身自己的职责，未收到旧智能体提示词；每个匹配角色只执行一次；`stand-in`             |
| 云设备独立执行       | 真实远程 Executor 已获项目授权；创建独立云端分身并分配 Issue           | 无选择器和绑定字段；执行属于远程设备；本机配置不泄漏；不继承同项目智能体提示词；`stand-in-cloud` |
| 独立模型与工作目录   | 配置本机模型及代码目录，接收来源工作                                   | 模型和目录可配置；来源读取、网络、原生一次确认、拒绝与提权边界保持现有断言；`stand-in-workspace` |
| 错误恢复             | 保存前并发修改配置；取消或重试；设备离线时保留草稿                     | 版本冲突不覆盖；保留输入；离线不改选其他设备；现有桌面场景及聚焦组件测试                         |

三个 checkpoint 均已注册到现有 core CI 清单，由共享 Linux 分片规划器均衡调度；实际执行分片以 CI 规划结果和 checkpoint 日志为准，不新增 CI 任务。默认云设备相关组件测试和 `stand-in-cloud-device` checkpoint 保留主分支覆盖。跨存储同名项目、排除项、暂停来源、个人绑定、主分身绑定、无效旧引用和原子失败由 Rust 持久化契约测试覆盖。

## 执行与清理

项目视图导航通过共享助手在同一次 renderer 操作中选择当前可用的标签或下拉框。CI 里程碑回归的控制记录和失败快照证实，分开检查布局与点击会在响应式重排后等待已经卸载的标签。此修复保留场景断言与超时，并用组件测试覆盖控件替换和单次选择。

CI 周边回归继续复用原有场景与断言：`streaming-conversation-switching` 保留 520 个进度项和原有等待时限，复用共享会话缓存的结构化事件合批发布，逐项保序并在终态前全部刷新；`plugin-legacy-upgrade` 继续使用已交付的历史安装器，后端仅在实际发送的插件快照仍匹配当前期望时确认旧协议回执，防止迟到回执把新版本错误标记为已安装。快照仅在服务端保存，不进入旧设备的通信协议或公开响应。

同步回执的聚焦回归同时检查单插件合并不会清除其他待卸载记录，以及派发和记账使用同一设备版本覆盖。流式处理测试检查订阅异常不影响其他订阅和终态，并保留快照内容更新前后的状态变化。

聚焦命令：`pnpm --filter wework e2e:desktop --parallel-segments stand-in,stand-in-workspace`；远程场景沿用相同 runner 的 `--segment stand-in-cloud`。默认单 checkpoint 并发，复用同一构建产物。

测试使用 runner 的独立目录、账号数据和进程；结束时沿用既有 `finally` 清理。运行结果、完整失败日志及截图仅保存在本地 `wework/test-results/`，不提交。实际结果记录在 PR 验证说明中；远程环境不可用时明确报告，不能以组件测试冒充云端 E2E。
