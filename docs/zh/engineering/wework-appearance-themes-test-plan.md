# Wework 命名主题与验收

## 体验与边界

外观设置分别保存浅色、深色主题，系统模式使用对应选择。基准为本机 ChatGPT Desktop
26.1029.70936（24905）的 29 个名称、44 个变体，验收清单独立于实现，防止目录遗漏。
另提供 Wework 原版明暗配色并默认选择，共 30 个名称、46 个变体。原版背景为浅色 `#ffffff`、
深色 `#181818`，强调色为 `#2563eb`；复用原版语义调色板和侧栏透明度。
Tokyo Night 使用背景 `#1a1b26`、正文 `#a9b1d6`、强调色 `#7aa2f7`。

终端 ANSI 色板独立于代码高亮：Wework 及未提供专属终端色板的主题保留原有 xterm
16 色，不能用函数名、字符串或运算符颜色替代 ANSI 蓝、绿、青色。专属终端色板继续跟随
对应主题；切回 Wework 后，zsh 目录和 Git 提示符恢复原有青蓝与蓝色。

主题覆盖 Wework 自有界面：桌面外壳、标签、侧栏、所有设置页、登录和授权、插件市场与管理、
应用、自动化、交互收件箱、项目空间、看板、Issue、项目智能体编辑、菜单和弹窗，以及
分离窗口、快速窗口、进程查看器和系统拖拽面板。启动流程、启动配色、恢复和错误文档沿用 upstream。
代码、差异、终端 ANSI、Markdown、富文本、文件预览工具栏与交互可视化共用语义颜色。
Wegent 来源的远端“智能体”内容不参与主题覆盖，其 Wework 外壳仍跟随主题。
图片、文档纸张、单元格自带格式、视频、品牌图标、二维码和网页内容保留内容原色。

命名主题切换保留字体、字号及背景图配置。`wework.appearance` 的 schema 2 保存主题 ID
和明确的颜色覆盖，不保存完整解析调色板；旧版本默认调色板快照迁移为 Wework，用户改色继续保留。
新配置和恢复默认均选择 Wework；已保存的命名主题选择及覆盖不受默认值变更影响。
主窗口保存明暗两份宿主快照，供原生工作区和进程查看器窗口使用；启动动画不消费命名主题。
辅助窗口只消费外观，不回写主窗口配置。共享协作包的 Web 默认主题不依赖 Wework 选择。

## CI 验收矩阵

运行环境使用现有 Core desktop runner 的隔离 Electron、真实 Executor、Core DSH、存储和 PTY。
仅模型服务使用确定性响应；不模拟桌面窗口、文件系统或项目服务。
每个 checkpoint 独立创建所需数据，runner 结束时清理隔离目录和进程。

| 用例                      | 前置条件与步骤                                                                    | 预期及证据                                                                        |
| ------------------------- | --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `appearance-themes` 目录  | 独立清单枚举 17 个浅色、29 个深色选项；逐项在真实设置选择器选择                   | 30 个名称无遗漏，46 个变体全部应用；保存每个变体截图、实际背景/文字与 JSON 证据   |
| Wework 默认与恢复         | 新配置确认明暗默认值，核对两种原版配色；遍历主题后点击恢复默认                    | 明暗选择均为 Wework；背景、强调色及侧栏透明度与原版一致；保留恢复后的截图         |
| 持久化                    | 分别选择 Proof / Tokyo Night，重载 renderer，再重启 Electron                      | 两个选择独立保留；Tokyo Night 三个基准颜色一致；切换浅色恢复 Proof                |
| 设置页                    | Tokyo Night 下依次打开全部 20 个内置及 Git 插件设置路由                           | 页面标题可读、背景与主题一致，每页截图                                            |
| 工作区与弹层              | 打开插件市场/管理、应用、自动化、交互收件箱、任务首页与设置菜单                   | 实际界面跟随同一主题；包含空态、不可用状态和 portal 截图                          |
| `local-file-preview`      | 在真实本地项目打开、切换、编辑文件、打开上下文菜单及浏览器工具栏                  | Tokyo Night 下编辑器、树和工具栏主题一致；原文件操作回归与截图继续通过            |
| `office-file-preview`     | 在真实文件服务打开 PPTX、DOCX、XLSX，滚动、切换任务和恢复预览                     | 工具栏与容器跟随 Tokyo Night，文档内容保持原色；保留原有功能断言与截图            |
| `collaboration-first-use` | 在真实本地空间创建项目、Issue 并选择负责人                                        | 项目、创建弹窗、Issue 属性与富文本在 Tokyo Night 可用；原持久化断言与截图继续通过 |
| `background-terminals`    | 真实工具启动后台进程，读取输出，切换明暗，再停止进程                              | 终端内容与 16 色 ANSI 跟随主题；保留滚动、PTY 生命周期及截图                      |
| `application-menu`        | 从原生菜单打开独立进程查看器；主窗口在 Tokyo Night / Matrix 间切换                | 独立窗口实时继承命名主题，变更不需重启；另验证原有语言、明暗和窗口交互            |
| `streaming-content`       | 真实工具写入可视化，修改计算器输入，再切换两个深色命名主题                        | iframe 来源和输入值不变，结果继续响应；仍保持 sandbox 隔离                        |
| 单元与契约                | 目录、迁移、坏数据、模式、storage 事件、覆盖与重置、Pierre 代码/ANSI/可视化、宿主 | 正常、失败及恢复路径；所有新测试由现有 renderer/host CI 收集                      |

checkpoint 定义位于 `wework/e2e/desktop/catalog/`，主题相关路径同时选中对应的内容和窗口回归。
截图与诊断保存在 `wework/test-results/`，由现有 CI artifact 上传；不提交生成日志或截图。
外观图库截图必须保留，不受其他场景的精简截图模式过滤。
