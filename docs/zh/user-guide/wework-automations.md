# Wework 自动化

Wework 自动化可以按固定时间、固定间隔或指定时间启动 Codex Runtime
任务。入口位于 Wework 左侧边栏的“已安排”，无需开启实验性功能。

## 本地模式

本地自动化保存在当前设备的 Executor 数据目录中，由本机 Executor
调度和执行。

- 用户只需选择项目，不需要输入文件系统工作目录。从当前项目或任务创建时，
  Wework 会自动带入对应项目；项目为“无”时，每次新任务都会使用独立工作区，
  不会归入当前项目。
- 项目存在由 Wework 管理的工作树时，项目选择器会同时列出主工作区和各工作树；
  选择工作树后，定时任务会直接在该工作树目录中运行。
- 不需要连接 Wegent，离线时仍可创建、编辑、停用和运行。
- Wework 退出期间错过的周期任务会记录为“已跳过”，不会集中补跑。
- Wework 退出期间错过的一次性任务会在下次启动后补跑一次。
- 同一个自动化已有任务运行时，新触发会记录为“已跳过”，避免并发修改同一工作区。
- 配置和运行记录不会自动同步到云端。

## 云端模式

“云端”包含 Wegent 云设备和远程 Docker 设备。选择设备后，自动化配置会保存到该设备
的 Executor，由该 Executor 负责调度和执行；Wework 不需要在触发时保持打开。

- 设备必须在线、运行兼容版本的 Executor，并使用 Claude Code Shell，才能创建自动化。
  离线或版本不兼容的设备仍会显示，但不可选择。
- 远程 Docker 宿主机需要在计划执行期间保持运行并能连接 Wegent。
- 配置和运行记录保存在所选 Executor 上，不会在本机、云设备和远程 Docker 设备之间
  自动同步或迁移。
- 自动化保存后，“运行位置”和设备会锁定。如需改到另一台 Executor，请重新创建自动化。
- Executor 停止期间错过超过一分钟的周期任务会记为“已跳过”；错过的一次性任务会在
  Executor 恢复后补跑一次。

## 计划类型

- **固定时间**：使用 Cron 表达式和 IANA 时区，例如工作日早上 9 点为
  `0 9 * * 1-5`。
- **按间隔**：按分钟、小时或天重复运行。
- **仅一次**：在指定时间运行一次，完成调度后自动停用。

## 持续目标

开启“持续完成目标”后，Wework 会将“任务说明”作为 Codex 的持续目标，而不只是
一次普通消息。Codex 可以继续推进任务，直到通过目标状态明确标记为已完成或受阻。
该设置同时适用于“每次新建任务”和“现有任务”，保存后会随自动化配置持久化。

## 对话方式

- **每次新建任务**：每次运行创建独立的 Codex 任务，适合日报、巡检和定期分析。
- **现有任务**：从已固定、可继续的本地、云设备或远程 Docker 任务中选择一个目标，
  后续运行会持续向该任务追加消息。普通历史任务和仅在当前页面打开的任务不会自动成为
  候选；需要先在侧边栏将任务置顶。离线或版本不兼容设备上的任务会保留在列表中，但
  不可选择。

## 查看详情

打开“已安排”时，Wework 会在首次加载后显示第一条任务的详情。点击详情右上角的关闭
按钮后，详情区域会保持关闭；需要再次查看时，点击列表中的任务即可重新打开。

自动化任务默认无人值守执行。若 Codex 请求人工输入，Wework 不会猜测答案，而是将
运行标记为“需要关注”。
