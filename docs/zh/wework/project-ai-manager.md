# 项目 AI 管理者

项目空间默认启用一个项目 AI。它负责检查整个项目的 Issue、建立任务、分派负责人、追踪进展和提出调整。Issue 负责人负责执行、状态推进和交付。项目 AI 不代替负责人完成 Issue，也没有删除 Issue、改项目设置或管理成员的权限。

打开项目看板，点击底部的**项目 AI**入口，即可展开与任务详情共用的输入组件，查看对话和回复。对话中的关联 Issue 可以直接打开详情；也可以通过“查看 Issue”选择项目中的任务。新建项目有可用智能体时自动启用项目 AI。本地空间优先使用当前设备智能体；云端空间使用已绑定 Wegent Team 的项目智能体。没有可用智能体时，进入**项目设置 → 项目 AI**选择智能体。管理指令、触发条件和开关也在此设置；本地空间离线时仍可使用。

## 触发与对话

一个项目只有一个项目 AI，但可以设置多个触发条件：Issue 创建、添加 Tag、状态变化和 Cron 定时。看板底部入口可随时发起对话。Owner 和 Maintainer 可以要求项目 AI 修改 Issue；其他项目成员可以查询和讨论，运行中的写入工具会被服务器拒绝。

“自动处理”与项目 AI 分别配置。两者的事件触发范围相交时，保存会返回冲突；运行时同一事件优先选中一个项目 AI 规则，避免同一事件启动两个管理者。项目 AI 自己创建的 Issue 不会再次触发项目 AI。

## Issue 权限边界

项目 AI 可以读取、搜索、创建、评论、编辑和分派本项目 Issue。新建 Issue 先不指定负责人，随后单独分派。未分派 Issue 的普通字段调整可直接执行。

已有负责人的 Issue 更换负责人时，项目 AI 提出待确认操作，由 Owner 或 Maintainer 决定。对进行中的 Issue 调整范围或机器人负责的 Issue 状态时，也会生成待确认操作；人类负责人确认自己的 Issue 范围变动，机器人负责的 Issue 由 Owner 或 Maintainer 确认。人类负责人通过自己的工作操作推进状态，项目 AI 可以评论提醒。确认时检查 Issue 版本；如果 Issue 已变化，旧提议不能继续执行，需要重新评估。

每次运行都有独立记录，列出执行和待确认操作、关联 Issue、状态与时间。项目 AI 的查询可以正常完成，无须为了结束运行而虚构分派或交付。
