# 项目 AI 管理者

项目空间默认启用一个项目 AI。它负责检查整个项目的 Issue、建立任务、分派负责人、追踪进展和提出调整。Issue 负责人负责执行、状态推进和交付。项目 AI 不代替负责人完成 Issue，也没有删除 Issue、改项目设置或管理成员的权限。

打开项目看板，点击底部的**项目 AI**入口，即可展开任务 Composer。点击 Composer 内任意控件后，面板固定展开，只能用关闭按钮收起。消息使用任务会话的展示组件；关联 Issue 可直接打开详情，右上角可打开完整任务。新建项目有可用智能体时自动启用项目 AI。本地空间优先使用当前设备智能体；云端空间使用已绑定 Wegent Team 的项目智能体。管理者智能体、管理指令和开关位于**项目设置 → 协作成员 → 项目管理者**，该页签排在其他协作成员页签之后。本地空间离线时仍可使用。

## 触发与对话

一个项目只有一个项目 AI，但可以在**项目设置 → 自动处理**中配置多个管理者触发条件：Issue 创建、添加 Tag、状态变化和 Cron 定时。看板底部入口可随时发起对话。Owner 和 Maintainer 可以要求项目 AI 修改 Issue；其他项目成员可以查询和讨论，运行中的写入工具会被服务器拒绝。

普通自动处理规则和项目管理者触发规则统一列在“自动处理”。两者的事件触发范围相交时，保存会返回冲突；运行时同一事件只启动一条规则，避免同一事件启动两个管理者。项目 AI 自己创建的 Issue 不会再次触发项目 AI。

手动对话与事件触发都创建普通任务执行。云端由后台调度，Wework 未打开时也可执行；本地项目由本机执行器处理。项目管理者的运行按项目串行，等待执行器、运行中、完成和失败分别显示。

## Issue 权限边界

项目 AI 可以读取、搜索、创建、评论、编辑和分派本项目 Issue。新建 Issue 先不指定负责人，随后单独分派。未分派 Issue 的普通字段调整可直接执行。

已有负责人的 Issue 更换负责人时，项目 AI 提出待确认操作，由 Owner 或 Maintainer 决定。对进行中的 Issue 调整范围或机器人负责的 Issue 状态时，也会生成待确认操作；人类负责人确认自己的 Issue 范围变动，机器人负责的 Issue 由 Owner 或 Maintainer 确认。人类负责人通过自己的工作操作推进状态，项目 AI 可以评论提醒。确认时检查 Issue 版本；如果 Issue 已变化，旧提议不能继续执行，需要重新评估。

每次运行都有独立记录，列出执行和待确认操作、关联 Issue、状态与时间。项目 AI 的查询可以正常完成，无须为了结束运行而虚构分派或交付。
