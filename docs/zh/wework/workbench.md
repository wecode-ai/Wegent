# 代码工作台

## 使用顶部标签页

Wework 桌面版使用顶部标签页承载任务、项目空间、智能体和其他功能页面。点击侧边栏链接时，页面会在当前标签页内切换；只有点击顶部 **+** 或使用标签页菜单中的明确新建操作时，才会创建新的标签页。

开启实验性功能时，首次打开主窗口会显示任务、工作空间和智能体三个默认标签页；关闭实验性功能时不显示工作空间标签页。每个标签页都是独立的工作实例：两个任务标签页分别保留自己的对话和未发送草稿，两个项目空间标签页分别保留自己的项目与路由，两个智能体标签页分别保留自己的页面状态。切换标签页不会把另一个标签页的内容同步过来。

任务和项目空间标签页在切换到后台后会保留已经打开的界面实例，而不是在每次返回时重新创建。未发送草稿、当前项目、看板路由和面板状态因此可以立即恢复，后台标签页也不会重复启动工作台运行时。输入框所需的 Codex 应用目录由首个任务工作台统一预热；输入框挂载或标签页切换不会再次请求目录。项目空间看板只在用户从 Issue 创建运行任务时按需加载任务输入框的模型和技能目录，避免普通看板浏览承担完整任务工作台的启动成本。

标签页较多时，标签列表会水平滚动，顶部 **+** 和最右侧的反馈按钮始终保持可见。标签页也可以通过右键菜单移动到独立窗口。移动成功后，原窗口会移除该标签页；新窗口只包含被移动的标签页及其状态，不会再次创建三个默认标签页。创建新窗口失败时，原窗口中的标签页保持不变。

任务页与插件、云端工作等功能页面共用标题栏下方的全宽桌面内容容器。因此在同一标签页内切换页面时，左侧栏的位置与外观保持一致，不会因页面类型不同而发生位置跳动。页面仍可在该容器内绘制各自的内部外观。

## 使用工作空间管理 Issue 和任务

顶部的 **工作空间** 标签页用于浏览看板、Issue 及其关联任务。它与任务标签页相互独立，分别保留当前看板、路由和界面状态。

从其他页面点击顶部固定的 **工作空间** 标签页会进入 **我的任务**；已经位于该标签页时再次点击则保留当前看板。即使本机和云端都存在系统生成的 `default-work-items` 空间，侧边栏也只展示一个逻辑上的 **我的任务**，避免出现两个同名入口。

在工作空间中选择 **新建 Issue** 会打开轻量输入界面，而不是任务表单。用户先选择要放入的看板，再用自然语言描述要推进的事情；第一行作为标题，其余内容作为描述。创建后 Issue 默认进入所选状态列并立即打开详情，标题、参与者和执行步骤可以随后补充。看板顶部和每个状态列也提供相同的新建入口。

用户不做任何设置时，新任务会默认选择 **我的任务**。发送消息后，Wework 自动创建工作项、关联运行任务，并持续同步运行状态；已有任务也会自动补齐到 **我的任务**，因此这里展示的是任务页的另一种看板视图，而不是一份独立任务列表。

每个运行任务至少关联一个由系统维护的 **我的任务** Issue。用户还可以把任务额外关联到一个本地或云端项目空间 Issue；界面展示任务上下文时优先使用用户选择的 Issue，没有用户关联时才回退到系统 Issue。系统 Issue 始终保留，并持续同步运行状态、任务标题和归档状态；取消额外项目空间关联不会把任务从 **我的任务** 中移除。Issue 可以独立存在而不关联运行任务，因此普通项目空间看板不等同于任务列表。

泳道按实际执行状态更新：明确排队但尚未开始的任务进入 **待开始**，正在运行的任务进入 **进行中**；任务成功结束、停止、取消或失败后均进入 **待确认**。成功结束只表示运行已结束，不会自动验收为已完成。确认结果后，用户可以手动将卡片移动到 **已完成**。待确认卡片会显示关联任务和最终 AI 回复的前三行，方便直接判断是否需要继续修改。已经归档的运行任务不会继续出现在已完成泳道；已完成泳道提供批量归档入口，并在工作区仍有未提交改动时要求再次确认。

将鼠标悬停在看板卡片任意位置，可以打开任务进展浮层。浮层直接复用任务会话组件，展示当前已加载的完整会话，并使用默认收起的同一输入框；消息加载、实时更新、继续对话和附件行为均与任务页一致。普通预览状态下，只要指针仍在卡片或浮层内，浮层就会持续显示；移出两者、滚动外部看板或按下 `Esc` 后关闭。点击输入框等交互区域后，浮层会固定显示，直到点击右上角关闭按钮或按下 `Esc`。

输入框上方的工作项入口会显示看板名称和工作项编号。打开菜单可以查看下一步、关联任务数和参与者，并可在统一右侧工作区查看详情。选择 **在工作项看板中查看** 会定位到对应工作项并保留原任务标签页；如果同一项目的看板标签页已经打开，Wework 会直接复用该标签页，避免重复加载相同看板，否则会新建看板标签页。

本地项目不会各自创建看板。任务统一进入 **我的任务**，并携带项目字段；项目视图可以基于同一份工作项数据按项目筛选。

## 从外部系统创建 Issue

云端工作空间的维护者可以在 **管理 > 外部任务接入** 中生成 Hook 地址。将该地址配置到 GitHub、GitLab、Sentry、Grafana、告警平台或其他支持 HTTP 回调的系统后，外部事件会确定性地转换为当前工作空间收集箱中的未指派 Issue。创建成功后，现有的 `task.created` 自动化规则仍会继续执行。

Hook 地址本身包含访问凭据，应按密钥管理，不要写入公开仓库或日志。地址泄露时选择 **轮换地址**，旧地址会立即失效；暂时停止接收时可以禁用 Hook。当前仅 Wework 托管任务的云端工作空间支持该能力。

内置适配器直接识别 GitHub Issue 的 `opened`、`reopened` 事件，GitLab Issue 的 `open`、`reopen` 事件，以及 Sentry 和 Grafana 的未解决告警。关闭、解决或无法确定标题的事件不会创建 Issue，但会记录接收结果。相同的外部事件 ID、投递 ID 或请求正文只会处理一次。

其他系统不需要实现 Wework 专用协议，可以直接发送 JSON、表单或纯文本。通用 JSON 至少提供 `title`、`subject`、`summary`、`name` 或 `message` 之一：

```bash
curl -X POST '<Hook 地址>' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: incident-2026-08-16-001' \
  -d '{
    "title": "生产环境支付失败",
    "description": "错误率超过阈值，请排查并恢复服务",
    "url": "https://monitor.example.com/incidents/001"
  }'
```

纯文本请求会使用第一行作为标题、完整正文作为描述。单次请求正文不得超过 1 MiB。服务返回 HTTP `202`，响应中的 `status` 为 `created`、`duplicate`、`ignored` 或 `failed`；`created` 响应还会包含新建 Issue 的 `loop_item_id`。

## 在 Issue 和运行任务之间往返

Issue 详情的“执行记录”区域会列出关联的 Wework 运行任务。点击其中一条记录会在统一工作区中并排显示 Issue 上下文和任务对话；需要完整执行界面时，再选择 **打开完整任务**。看板标签页与任务标签页分别保留自己的路由和界面状态。

看板卡片只展示 Issue，不额外创建 PR/MR 卡片。关联任务存在 PR/MR 时，执行记录左侧的任务图标会替换为 PR/MR 状态图标；任务页的项目侧边栏复用同一状态与交互。运行中的任务始终显示；已停止任务只在关联 PR/MR 仍开放时保留。PR/MR 已合并、已关闭或尚未创建时，已停止任务不再占用执行记录。

状态查询由任务实际所在设备的 Executor 执行。本地任务直接使用本机已经登录的 `gh` 或 `glab`，不需要为看板另外配置 REST 任务认证。Wework 按代码仓库批量查询关联分支，并将结果保存在本地缓存中，避免任务较多时逐条请求；可见页面会定期刷新，重新聚焦应用后也会检查最新状态。

PR/MR 检查失败、合并冲突或 Merge Queue 异常时，状态菜单提供 **让 AI 继续修复**。该操作继续原运行任务的会话并附带异常上下文，不会新建另一条任务。已关闭的 PR/MR 不提供继续修复入口。

## 使用项目侧边栏

点击项目名称可以展开或收起该项目的运行任务。收起的项目显示闭合文件夹图标；展开后图标会改为打开的文件夹，方便识别当前展开状态。

新建任务会立即显示在所属项目的任务列表顶部。已经通过拖拽保存顺序的任务继续遵守手动顺序；新任务获得持久化顺序后，也会按同一项目顺序稳定显示。

## 使用 IM 通知

IM 通知是正式功能，无需开启“实验性功能”。侧边栏账户区域的消息气泡入口用于设置离开电脑提醒；打开一个运行任务后，标题栏中的 **继续到私聊** 可以将该任务绑定到可用的 IM 私聊。

离开电脑提醒弹层会显示当前投递会话。已连接云端时，**更换会话** 与开启或关闭提醒的主操作会在同一操作行中完整显示，便于直接调整会话或提醒状态。

绑定成功后，Wework 发送的切换提示会显示当前任务标题，不会显示 `runtime-xxx` 形式的内部任务标识。后续任务回复也会继续发送到所选私聊。

## 拖拽任务分屏

从侧边栏拖拽任务到工作台中的上、下、左、右区域，可以在对应方向创建任务分屏；拖到中央区域则会替换当前区域的任务。指针进入工作台后，侧边栏会停止任务排序和自动滚动，避免侧边栏的拖拽效果抢占分屏操作。将指针移回侧边栏后，可以继续调整任务顺序。

分屏会保存为一个会话组。组内任务在侧边栏显示相同的 **分屏 N** 标记；点击任一成员会恢复整个分屏组并聚焦该任务。点击组外任务只会切换到单任务视图，不会替换组内任意分屏；之后仍可从任一成员返回该组。可以保留多个分屏组，但同一任务同一时间只属于一个组。关闭分屏直到只剩一个任务时，该组会自动解散。

分屏区域高度较低时，空闲输入框会自动收缩为单行文本和右侧发送按钮，隐藏附件、快捷短语、模型等功能控件。点击或聚焦输入框会通过动画展开完整输入区；点击输入区外部后再次收缩。存在附件、代码评论、模式设置或其他待处理上下文时，输入区会保持展开，避免隐藏当前操作。

## 开始新任务

新任务页使用紧凑的建议按钮帮助选择任务方向。点击一个方向后，可以继续选择更具体的提示；选中的提示会写入下方输入框，仍可在发送前编辑。

项目选择、消息输入、快捷短语和模型选择位于同一个输入面板中。输入框获得焦点时会显示蓝色边框，项目、附件、快捷短语和模型设置不会因新任务页的简化布局而减少。

## 使用弹窗快速输入

Wework 弹窗在没有运行任务时使用固定高度的紧凑输入面板。输入内容超过三行后，文本会在输入框内部滚动，底部的附件、模型和发送控件保持在弹窗可视范围内。

## 文件与终端

右侧工作区用于浏览项目文件、预览内容和审核变更。多目录项目会在文件标签中显示文件夹选择器；切换文件夹只改变文件树和预览根目录，不会改变任务、终端或对话使用的执行目录。

助手回复中的本地文件和目录链接可以直接在文件标签中打开。文件链接可以定位到指定代码行；目录链接会将该目录设为文件树根目录。在 macOS 桌面版中，文件标签的“打开”和“打开位置”操作同时支持文件与目录。

使用 `Command+J` 打开或关闭底部工作区面板。打开面板不会自动创建新终端；已有终端会按任务保留，切回任务时直接恢复。

点击底部标签栏的 **+**，可以根据当前设备能力选择 **Terminal**、**IDE** 或 **桌面**。Terminal 从当前项目目录启动，Worktree 任务从对应工作树启动；IDE 在系统默认浏览器中打开；桌面能力可用时在 Wework 内置浏览器中展示。

排查切换任务后终端未重绘时，前端日志会记录终端类型、任务与会话标识、激活阶段、xterm 行列数、容器尺寸和隐藏状态；不会记录终端输出、命令或工作区路径。

排查 `[Terminal connection failed]` 时，按同一个会话标识串联 `Local terminal start`、`Local terminal connection`、` Electron local terminal attach` 和 `Local terminal close` 日志。日志会记录宿主进程、子进程、任务、工作区路径、连接阶段和关闭原因，从而区分输出监听、退出监听、原生 attach、会话不存在和主动关闭等情况。上述日志不记录终端输入、输出、执行命令或环境变量内容。

## 展开右侧工作区

打开右侧工作区后，点击标题栏中的 **展开面板**，可以让文件、预览或审核内容占满主工作区。展开文件、浏览器等非聊天工作区时会隐藏任务输入框；展开临时聊天时只保留临时聊天自己的输入框。展开状态会按对话保存。

在展开状态下仍可收起左侧栏，使窗口只显示右侧工作区。点击右上角的 **恢复面板**；已有对话时，也可点击展开工作区底部的 **最近一条**，返回对话与右侧工作区并排显示的布局。关闭右侧工作区或关闭其最后一个标签时，展开状态也会自动结束。

## 查看执行过程

任务运行时，对话会显示正在使用的工具和当前进度。已完成的工具调用会折叠为摘要，可以展开查看命令或修改过的文件。

## 浏览长对话

当对话内容超过当前视口时，消息区左侧会显示历史发言导航。导航固定在对话视口中央，不会随消息内容滚动；点击标记可跳转到对应发言，将指针悬停在标记上可预览用户请求和助手回复摘要。

助手回复仍在流式增长时，导航会保留当前发言的激活状态，等待消息区完成新的布局测量后再更新，避免底部跟随滚动期间标记短暂熄灭或跳到其他发言。

## 切换对话与恢复位置

切换对话时，桌面工作台会保存运行状态、最近消息、右侧工作区标签和面板状态；切回后会立即恢复离开时的工作区。文件标签会恢复离开前选中的文件及其实际目录，包括从助手消息打开的工作区外绝对路径；审核标签会恢复所选审核范围和已经加载的 Diff。普通对话不会保留隐藏的完整页面 DOM，以限制长对话带来的 WebView 内存增长。

包含运行中 Terminal 或 Wework 内置浏览器的对话页面会保持挂载。Terminal 进程、标签和输出缓冲会继续保留，内置浏览器的页面、地址和标签状态也会保持；关闭对应资源后，页面即可释放，仅保留可恢复的面板状态。隐藏对话不会响应当前对话的快捷键或浏览器打开事件。

首次打开的对话会定位到最新消息。已经停留在底部的对话切回后仍保持底部；如果之前浏览到历史消息，则恢复与底部的相对距离。长对话只挂载视口附近的消息，并复用已测量的消息高度，减少滚动时的 WebView 内存增长。

消息、滚动位置和消息高度缓存都有数量上限。归档任务时会立即移除该任务的缓存；再次打开已被缓存淘汰的任务时，Wework 会从本地运行时重新读取完整记录。

## 使用回复中的选中文本

在助手回复中选择一段文本后，可以将其添加到当前对话输入框，或在侧边栏中基于该文本继续提问。回复仍在流式输出时也可以使用这些操作；后续内容更新不会关闭已经打开的文本操作菜单。

任务运行期间显示在工具调用上方的过程文本也属于可选回复内容。选择其中的文本后会显示相同的操作菜单，可以直接添加到当前任务的输入框。

## 审核本轮变更

支持的 Git 任务完成后，助手消息下方会显示本轮文件变更，包括文件数量和增删行数。点击 **审核** 可查看完整 Diff、筛选文件、切换自动换行和复制 `git apply` 命令。

审核内容从执行任务的设备读取，因此设备需要保持在线。

## 撤销本轮变更

点击 **撤销** 后，Wework 会先检查反向补丁能否安全应用。后续修改与本轮内容冲突时，工作区不会被强制覆盖。撤销只处理当前轮产生的变更。

## 完成 Git 工作流

在提交或创建 Pull Request 前建议：

1. 审核所有变更文件。
2. 运行与改动相关的测试和格式检查。
3. 检查工作区是否包含临时文件或敏感信息。
4. 确认提交信息和目标分支。
5. 推送分支并创建 Pull Request。

归档 Worktree 任务前，先处理未提交修改；强制归档会移除对应工作树。
