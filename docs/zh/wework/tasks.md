# 与 AI 协作

## 描述任务

一条有效的任务说明通常包含目标、范围、约束和验收方式。例如：

```text
为用户设置页增加语言选择：
- 支持中文和英文；
- 复用现有设置组件；
- 选择后立即生效并持久化；
- 补充相关单元测试。
```

复杂任务可以先要求 AI 调研并给出方案，确认后再实施。

## 添加上下文

你可以在输入区添加文件、图片、代码位置和应用快照。应用快照会截取当前前台窗口，并在获得系统辅助功能权限时附带窗口文本。

发送本地图片后，Wework 会在消息中保留图片预览。关闭并重新打开 Wework 或切换到其他会话后，返回原会话仍可查看该图片；如果原始本地文件已被删除，预览将无法恢复。

输入 `/` 可以选择可用 Skill。插件安装后，其 Skills、命令或工具会出现在对应任务能力中。

## 将对话加入项目空间看板

开启实验性功能后，可以通过输入框的 **+** 菜单选择 **项目空间**。选中的空间会以 **加入看板 · 项目空间名称** 显示在输入框底部，让你在发送前确认本次对话将进入哪个看板。发送第一条消息后，Wework 会创建对应看板任务并关联当前对话；本地项目设置的自动加入空间也会通过同一控件明确显示。

对于已经启动的任务，可以在右侧 **环境** 面板中选择 **关联项目空间**，将当前项目或当前任务关联到本地、云端项目空间，或者在空间中快速新建任务。选择本地空间时操作保存在当前设备；选择云端空间时使用云端协作数据。

## 管理项目空间自动化

项目空间提供 **自动化** 管理入口，集中配置机器人成员并跟进执行队列。机器人可以成为项目任务负责人：被指派后自动领取任务，在本地或指定设备执行，并把执行结果或失败原因写回任务评论 Thread，提交结果供人工验收。

执行队列展示机器人任务的流转状态（待处理、排队中、已领取、执行中、失败待重试），并支持按关键词搜索任务。已完成的自动执行会以评论形式保留在任务详情中，人工可以基于评论验收，或要求机器人继续修改。

本地项目空间的机器人只能绑定本地或随行 App 设备执行；云端设备仅可用于云端项目空间的机器人。本地执行队列由本机 App 每 3 秒领取一次，执行中的任务会持续续租，任务异常中断后会在租约到期后自动重新排队，避免任务卡死在“执行中”。

### 在本机部署云端设备（开发测试用）

云端项目空间的机器人可以绑定云端设备执行。本地开发时，可以用仓库脚本把本机执行器注册成一个
`device_type=cloud` 的“云端设备”，从而在本机直接验证云端设备分发链路：

```bash
bash executor/scripts/dev-cloud-device.sh start    # 启动并保持在线（可重复执行）
bash executor/scripts/dev-cloud-device.sh status   # 查看运行与在线状态
bash executor/scripts/dev-cloud-device.sh restart  # 重启（会重新构建/拉起最新代码）
bash executor/scripts/dev-cloud-device.sh stop     # 停止
```

- 默认设备 id 为 `cloud-device-dev`（可用 `DEVICE_ID` 覆盖），注册后出现在设备列表的“云端设备”中。
- 脚本会自动构建最新 executor、从 `backend/.env` 读取密钥签发 30 天 token，并使用独立的
  executor home 与 Codex home（不读取个人 Codex 凭据）。
- 创建机器人时执行环境选择“云端”、执行设备选择 `cloud-device-dev`，指派任务后即在本机按
  云端设备协议执行并写回评论与执行记录。
- 运行数据与日志位于 `~/.wegent-executor-cloud-device/`。

## 选择模型和设备

模型决定任务使用的 AI 能力，设备决定代码和命令在哪里执行。本地模型只能用于本机设备；云端模型和设备需要先连接 Wegent。

打开输入区的模型选择器后，如果当前只有一个模型分组，Wework 会直接展示该分组中的全部模型；如果存在多个分组，请先选择分组，再从展开的二级菜单中选择模型。

会话启动后仍可在官方 GPT/Codex 模型和第三方模型之间切换。选择不同模型时，Wework 会先显示确认提示；确认后，新模型从下一条消息开始生效。

如果已有上下文包含原 provider 生成的加密推理或压缩状态，executor 会在切换请求中自动移除这些不可移植字段，避免目标模型报 `invalid_encrypted_content`。普通消息、工具结果和其他可移植上下文会继续保留。

## 任务运行中的控制

任务运行时有三种发送方式：

| 操作               | 快捷键                         | 适用场景                   |
| ------------------ | ------------------------------ | -------------------------- |
| 当前回复结束后发送 | `Enter`                        | 补充下一步要求             |
| 引导当前回复       | `Command/Ctrl + Enter`         | 调整正在进行的工作方向     |
| 打断并立即发送     | `Command/Ctrl + Shift + Enter` | 当前方向错误，需要马上停止 |

打断会停止当前回复，但已经完成的文件修改和命令不会自动回滚。

## 使用分身监督

在新的 Codex 对话或已有 Codex 任务输入区的 **+** 菜单中开启 **监督**。主 AI 工作期间，执行器会在后台定时读取最近的 AI 进展，并使用独立的只读轻量调用检查目标偏移、遗漏约束、破坏性操作和明显的阻塞循环。监督是正式功能，无需开启“实验性功能”；巡检不会 fork 原任务，也不依赖任务界面保持打开。

- **先建议**：在输入框上方显示纠正建议，由你决定是否发送。
- **自动纠正**：发现明确偏差时，运行中直接引导当前回复，空闲时像你在输入框发送要求一样开启后续回复。

监督配置属于当前任务。你可以单独指定巡检模型；巡检频率可选 10 秒、30 秒、1 分钟或 5 分钟。Wework 会在当前设备记住最近一次保存成功的巡检模型和频率，并在配置新任务监督时自动恢复。你还可以在“设置 → 上下文”中设置全局监督原则；首次开启任务监督时会自动带入，并允许针对该任务修改。

监督启动后，右侧 **环境** 面板会显示监督状态和下次巡检时间。选择 **立即巡检** 可以跳过等待时间并马上检查当前进展；正在巡检时该按钮会暂时禁用，避免同一任务并发执行多个监督检查。

## 查看处理过程

AI 回复中的“已处理”区域会按实际创建时间从上到下展示工具调用。即使执行器的事件到达顺序发生变化，较早创建的命令、文件操作或其他工具仍会显示在较早位置，便于按照真实执行过程阅读和排查任务。

已完成的处理活动会按类型汇总：终端命令和 Node.js REPL JavaScript 调用计入“命令”，MCP 等其他能力计入“工具”，文件读取和编辑则使用各自的分类。展开处理区域后，点击某一行或右侧箭头可以查看详情。折叠行使用便于阅读的短名称；详情中会显示完整工具名称、调用输入和返回输出。没有输入或输出的状态型活动不会显示无意义的展开按钮。

计划模式生成的计划属于回复主体，不会收进已完成回复的“已处理”折叠区域；恢复后台任务或重新打开会话后，计划也会保持直接可见。普通命令、文件操作和工具调用仍按上述规则汇总和折叠。

## 管理会话

任务可以继续对话、重命名、复制到其他设备或归档。项目会话显示在所属项目下；没有项目的会话显示在独立对话列表中。已归档会话可以在设置中恢复或删除。

在一条已完成的 AI 回复下，将指针移到消息操作区并选择“在新任务中继续”，可以从该轮创建独立任务。新任务保留截至所选回复的对话上下文并使用同一工作区；原任务及该轮之后的消息不会被修改。正在生成、已取消或无法映射到 Codex 轮次的回复不显示此操作。

当你在消息底部切换到其他会话时，Wework 会保留“跟随最新消息”的状态。即使原会话在后台继续输出，切回后仍会显示最新内容；如果你在切换前主动向上滚动，Wework 则会恢复原来的阅读位置。
