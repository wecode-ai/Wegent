# MCP 应用

Wework 可以在 Codex 任务的工具结果旁运行 MCP 应用。应用由 MCP 服务提供 HTML，通过标准 MCP Apps 协议与宿主交互。

## 声明界面

在工具定义的 `_meta.ui.resourceUri` 中声明资源 URI，并通过 `resources/read` 返回 HTML：

```json
{
  "name": "show_dashboard",
  "inputSchema": { "type": "object", "properties": {} },
  "_meta": { "ui": { "resourceUri": "ui://dashboard/app.html" } }
}
```

```json
{
  "contents": [
    {
      "uri": "ui://dashboard/app.html",
      "mimeType": "text/html;profile=mcp-app",
      "text": "<!doctype html><html>...</html>",
      "_meta": {
        "ui": { "csp": { "connectDomains": [], "resourceDomains": [] } }
      }
    }
  ]
}
```

宿主同时接受旧的 `ui/resourceUri`、`openai/outputTemplate` 和结果 `_meta` 中的资源引用。`text/html+skybridge` 通过 `window.openai` 兼容桥接入同一条宿主链路。

只有调用记录、工具定义或结果元数据声明了 UI 资源时，才加载 MCP 应用。普通 MCP 工具没有 UI 资源时不显示应用卡片；即使重开历史会话时来源服务或工具已被移除，也不显示“应用不存在”。已声明 UI 资源的应用仍会报告来源失效或资源加载错误。普通调用不能使用应用专属的工具、资源或上下文接口。

## 通信和生命周期

应用完成 `ui/initialize` 与 `ui/notifications/initialized` 握手后接收工具输入和结果。结果的 `content`、`structuredContent` 和 `_meta` 保持分离；宿主不会把 `_meta` 添加到模型上下文。

会话刷新时，内容相同的工具结果不会重复发送给已初始化的应用，避免覆盖应用通过工具回调更新的状态。结果内容或错误状态实际变化时仍发送更新。

应用可以调用来源服务的工具、读取资源、发送对话消息、更新模型上下文，以及请求内联、全屏或画中画显示。只读 Issue 执行视图不提供应用发送会话消息的能力，回复仍通过 Issue 发起。其他对话消息需要用户确认。应用工具调用通过来源绑定的 Codex 原生通道执行；宿主不会根据工具注解额外逐次弹窗。`visibility: ["app"]` 的工具只供应用调用，`visibility: ["model"]` 的工具不会向应用开放。

虚拟列表移除工具行时，宿主使用保留状态的 DOM 移动停放页面，保留页面状态和正在进行的请求。关闭应用或离开任务时，宿主清理协议连接和临时文档。模型上下文按来源调用保存在任务中，并以不可信应用数据的身份用于后续消息。

重开历史会话时，已声明界面的工具调用仍显示应用卡片；来源服务不可用时显示错误和重试入口，不会静默消失。冷恢复根据当前执行器设备和原任务重新绑定执行身份，再恢复对应工具配置；读取保存状态不会重复执行页面中的业务操作。

桌面工作区同时支持对话内联卡片与右侧应用标签。应用请求 fullscreen 时使用右侧工作区容器；展开和收回移动同一个沙箱节点，保留页面输入、登录状态和进行中的请求。关闭右侧标签时，支持内联的应用返回对话；仅支持 fullscreen 的应用保留文档并收起为重新打开入口。关闭应用本身才释放文档。

## 会话内生成的 HTML

交互页面按需使用。用户可以要求纯文字、直接执行或交互页面；AI 根据用户偏好和
选择候选、编辑输入、管理多项结果等需要决定展示方式。业务工具可直接调用，只有
调用 `present_interaction` 才生成这类卡片。新增业务工具按统一目录注册输入、返回契约
和执行逻辑后，即可被页面发现并绑定，无需新增专用页面或桥接适配。

生成界面默认采用高信息密度布局，规则同时进入工具指引和 `visualize` 技能。简单
结果使用一个紧凑列表或表格，桌面端每行展示名称、关键状态或时间、小操作按钮，
不用逐项大卡片、分栏面板或重复标题。少量结果不能因为大留白、内部滚动或人为分页
而跨越多屏；内部 ID、长描述等次要信息按需展开。默认桌面字号下，简单行高以
36–44px、按钮高以 28–32px 为参考，随内容换行和用户字号自然增高；44px × 44px
触控目标用于移动端。相关表单字段合理分列，保留判断所需上下文和可读性，用户明确
要求其他布局时遵循其偏好。展开或重开卡片使用保存的 HTML；新规则用于后续生成。

`present_interaction` 复用上述宿主，在会话内加载 AI 按当前场景生成的 HTML，
并在脚本运行前注入 `window.wework`。页面通过 `callTool` 调用绑定的真实工具，
通过 `navigate` 打开已有功能，通过 `state` 和异步 `setState` 恢复、保存卡片状态。

`callTool` 返回解包后的业务数据：优先读取 MCP 的 `structuredContent`，没有时
解析唯一的 JSON 文本结果。无法解析时抛出 `invalid_tool_result`，不返回协议包装。
解析保留 JSON 数组、标量和空值，不对业务数据强加定时任务对象结构。
所有 `wework_control` 业务能力都在同一份目录中声明 `inputSchema` 和 `outputSchema`。
`list_capabilities`、`describe_capability` 和 HTML 绑定工具使用同一份契约，覆盖会话、
归档恢复、目标、监督、模型、运行状态及自动化。生成代码应读取各能力的实际字段，
不能套用另一种业务的结果结构。选择交互页面后的统一流程为发现能力、查询当前数据、生成表单或
候选操作、执行真实工具、展示结果并保存状态；没有对应操作的功能使用已注册导航。

保存成功和重新打开必须使用同一个 `render(state)`。工具成功后立即展示简洁的
业务结果，再保存同一份状态；不要将原始 JSON 作为结果提示。卡片状态保存失败
不会撤销已完成的业务操作，应保留成功结果并单独提示状态保存失败，禁止自动重试
或重新启用创建按钮。超时或结果格式异常时，应通过读取工具核实实际结果。

## 安全边界

- 执行器从任务中的真实调用确定来源服务，不接受页面指定其他任务、服务或插件。共享服务还按连接器和账号隔离。
- HTML 使用独立的本机来源，不共享工作台的 DOM、Cookie、存储或桌面宿主接口。
- 资源 CSP 通过响应头实施。未声明的网络和子框架请求默认禁止；HTTP 仅用于显式声明的本机开发来源。
- 页面消息同时校验来源窗口和来源地址，发送方向也绑定来源地址。导航到其他地址后不能继续使用原应用的宿主通道。
- 应用元数据和更新的上下文不能授予权限。执行器校验工具可见性；界面确认不能扩大插件和账号范围。

## 验证

```bash
pnpm --filter wework e2e:desktop --segment mcp-apps
```

该 checkpoint 使用真实 Electron、执行器、Codex 和标准输入输出 MCP 服务，仅模拟模型响应，并由桌面 CI 调用。验证范围包含资源读取、初始化、私有结果元数据交付、应用专用工具、模型上下文、显示模式切换、跨调用隔离、连续非只读工具调用、作用域拒绝和资源清理。普通工具回归还会禁用来源服务、重启真实 Codex 服务并重开历史会话，验证不会出现应用错误卡片，且应用专属调用仍被拒绝。

每个文档使用独立的 `codex-sandbox://<id>.web-sandbox.oaiusercontent.com/mcp-app.html` 来源。Electron 在本地处理此自定义协议，不查询该域名、不请求 OpenAI 服务，也不远程执行页面。宿主在启动前将协议注册为标准安全协议，文档响应继续执行资源声明的 CSP。

Executor 转发应用元数据时保留 JSON 对象键的原始顺序，避免改变应用用于清单摘要校验的序列化字节。桌面回归通过真实工具回调验证清单摘要在整条桥接链路中保持一致。
