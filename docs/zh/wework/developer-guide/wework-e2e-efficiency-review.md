# 桌面 E2E 用例与耗时精简审查

本次以固定提交 `d13154ab65` 的 **254 个非分组用例注册项**（251 个 JSON 声明及发布套件动态注册的 3 项）为基线，逐项审查耗时、重复验证和功能重要性，实际删除 **77 项（30.31%）**，保留 177 项。删除包含普通 UI 矩阵、重复场景、宿主别名和死注册；没有通过重组完整流程来替代删除。安全子断言继续由现有宿主执行，表中的保留覆盖不表示完整替代被删除的 UI 组合。

统计曾先遗漏部分 JSON 注册项，再遗漏发布套件动态注册的 `app-rollback`、`app-rollback-recovery`、`app-upgrade-recovery`，现统一按固定提交的完整 254 项计数，目标提高到 77 项，三项发布门禁全部保留。最新 main 另外新增的 `connection-observation-storage`、`issue-reference-open`、`paste-image-send`、`runtime-load-performance`、`task-completion-notifications` 不混入旧基线；当前完整目录 182 项（179 个 JSON 声明及 3 个动态发布项）。`clipboard-history-image` 因 main 新增粘贴后立即发送覆盖而恢复保留，已撤出删除数量。

## 并行度

[PR #4767](https://github.com/wecode-ai/Wegent/pull/4767) 已合入 main（`6841963d00`）。Linux Core、Windows Core、Linux Cloud 均使用 `CORE_RUNNER_SCALE=1.5`；完整逻辑矩阵分别从 10、10、8 台扩展到 15、15、12 台，每台 runner 的 worker 上限保持 4。性能基准、独占资源和共享准备组继续隔离；部分选择按可分配检查点扩容。

## 耗时证据与统计边界

- 基线调度权重来自同一固定提交的 [Linux 时长表](https://github.com/wecode-ai/Wegent/blob/d13154ab65/.github/ci/wework-linux-checkpoint-durations.json) 与 [Windows 时长表](https://github.com/wecode-ai/Wegent/blob/d13154ab65/.github/ci/wework-windows-checkpoint-durations.json)。Linux Core 使用成功样本的保守统计值，Windows 表保留各条目的历史测量及来源；这些不是本轮新实测。
- 近期列只采用 [运行 44283945561](https://github.com/wecode-ai/Wegent/actions/runs/44283945561) 中已经成功完成的检查点。该运行整体被取消，不能据此宣称整套 CI 通过；同一项有多个成功值时显示范围。
- `—` 表示没有相应成功耗时证据，不按零成本处理，也不据此推断当前平台是否选择该用例。
- `stand-in-startup-recovery`、`project-sidebar-chat`、`goal-resume-route`、`collaboration-local-status-automation`、`responses-api-gateway`、`connector-account-switch` 是宿主别名或死注册清理，没有独立 CI 耗时收益。删除比例是注册项比例，不是运行时间降低比例。
- 历史耗时不能相加后当作新的墙钟提速；runner 排队、准备成本、并发竞争和本轮实际执行仍需分别观察。
