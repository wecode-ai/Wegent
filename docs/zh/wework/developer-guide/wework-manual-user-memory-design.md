# Wework 全局用户偏好提示词设计

状态：已实现（第一版）。日期：2026-11-20；更新：2026-11-21。

[English](../../../en/wework/developer-guide/wework-manual-user-memory-design.md)

## 背景

Wework 桌面端目前没有一条跨本地、云端和远程执行器生效的用户偏好提示词。用户希望把“回复要简明”“文档里不要乱用 emoji”“推理和 agent 交互可以用自造词或英文，但注释、commit message 和 PR 必须用人类工程师可理解的表达”这类个人偏好固定下来，而不是每次重复说明。

现有 `ContextSettingsPage` 的 Wework 自定义指令偏 Codex 配置语义，且不适合作为跨执行器的用户偏好载体。第一版补一个最小能力：一个全局用户偏好提示词，由 Wework 在每次请求前注入。

## 目标

- 提供一个单一的全局用户偏好提示词。
- 用户可在 GUI 中手动编辑。
- 本地、云端和远程执行器收到同一份提示词。
- 创建、续聊、打断续聊和运行中引导都注入最新内容。
- 实现尽量小，不新增数据库、Backend API 或执行器存储。

## 非目标

- 不做环境记忆、分层记忆、执行器本地记忆或跨端合并。
- 不做自动提取、整理、去重或定时复盘。
- 不做账号级云端同步。
- 不提供语义检索。
- 不修改 Stand-in 记忆。
- 不把偏好提示词当作权限、认证或审批依据。

## 数据模型

在 `AppPreferences` 中新增一个字段：

```ts
interface AppPreferences {
  userPreferencePrompt: string;
}
```

规则：

- 默认为空字符串。
- 保存前去除首尾空白。
- 最大 4000 字符；GUI 输入框限制输入长度，持久化层拒绝读取超限的已保存值。
- 不拆分多条记录，不维护版本，不绑定设备或环境。
- 与其他桌面偏好一起原子读写；旧版本缺省时读取为空。

## GUI

在“设置 → 上下文”中新增一个“用户偏好提示词”区块：

- 一个多行文本框。
- 保存按钮只在内容变化时可用。
- 保存失败时保留用户输入并显示错误。
- 空态提示用户可以写沟通风格、文档风格、代码注释和提交信息等稳定偏好。
- 不提供独立设置页，不新增导航入口。

## 注入

Wework 在构造以下请求时读取最新偏好：

- `RuntimeTaskCreateRequest`
- `RuntimeSendRequest`
- 运行中引导请求

若提示词非空，写入：

```ts
additionalContext["wework.user-preferences"] = {
  kind: "application",
  value: userPreferencePrompt,
};
```

约束：

- 不修改 `system_prompt`。
- 不按设备类型过滤。
- 每轮发送前重新读取，运行中的旧轮次不被改写。
- 远程和云端执行器收到同一份内容。
- 空提示词不注入该字段。

## 提示词维护

第一版只提供两个输入命令：

- `/remember <preference>`：把一行偏好追加到现有提示词末尾。
- `/memory`：打开“设置 → 上下文 → 用户偏好提示词”。

命令规则：

- 只做纯文本追加，不解析结构、不自动改写已有内容。
- 追加后下一轮生效，不创建模型轮次。
- 超过 4000 字符时拒绝追加并保留原输入。
- 删除、修改和整理仍在 GUI 中完成。

## 安全边界

- 偏好提示词是用户数据，不是权限授予。
- 注入文案保持 `kind: application`，不伪装成用户消息。
- 不保存凭据、令牌、API Key 或会话文件内容。
- 用户显式请求、项目指令和 Wework 自定义指令优先于该偏好。
- GUI 删除不会修改历史会话文本。

## 测试

只做聚焦单元和组件测试：

- 偏好规范化：缺省、空白、超长拒绝和非法类型。
- GUI：编辑、保存、保存失败、空态和输入长度限制。
- 命令解析：合法追加、空内容、超长拒绝；/memory 打开设置页。
- 请求构造：创建、续聊和引导请求注入 `wework.user-preferences`。
- 注入层不按设备类型过滤，因此本地、云端和远程请求由同一路径生成同一字段。
- 空提示词不注入字段。
- 修改提示词后下一轮生效，历史轮次不变。
- 创建请求注入时同时保留异步准备后的附件 ID 和附件对象。

如后续实现需要真实桌面交互验收，再按仓库策略显式运行 `ai:verify`。
