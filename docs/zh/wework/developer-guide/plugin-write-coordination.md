# 插件认证与安装的写入协调

插件使用 Redis 插件级租约和现有业务记录上的 CAS，不新增表、列或索引，不使用 MySQL 命名锁。设备回执事务在更新账号同步状态前，用 `FOR UPDATE` 锁定本次要修改的设备安装行；不同插件的安装、更新、卸载和认证可以并行，同一插件的写入相互协调。

## 锁的身份与期限

普通操作的 key 为 `wegent:plugin-write:{user_id}:{InstalledPlugin.name}`，不包含设备号，因为多台设备修改的是同一账号安装记录。首次安装使用现有的稳定名称派生规则；重装或历史名称的安装先查找已有记录，取得其真实名称的租约，再重新核验身份。

Python 复用公共 `DistributedLock.owned_lock`，Rust 使用相同 key、随机 owner token 和 Redis NX 协议：

```python
distributed_lock.owned_lock(
    f"wegent:plugin-write:{user_id}:{installation_name}",
    expire_seconds=180,
    blocking_timeout=3,
    redis_client=plugin_redis_client,
)
```

- TTL 为 180 秒；正常事务完成后按 token 立即释放，不等待 TTL。
- 获取单个插件的租约最多等待 3 秒，业务处理预算仍为 20 秒。Python 保留每 10 秒的有界续租，Rust 不启动续租任务。
- 保存点结束不释放根事务的租约。批量业务修改按身份排序，失败时回滚整笔事务并释放已取得的租约，不保留部分撤权或卸载；设备回执按插件分别提交。
- 所有权校验、续租和释放均比较 token。旧请求不能释放后来请求的锁；Redis 不可用时明确失败，不无锁执行。
- 不持有覆盖整个账号插件操作的 Redis 用户锁。账号策略编辑使用 `@account-policy` 专用租约；缺失的账号同步状态首次创建使用 `@sync-init` 专用租约。它们不包住日常安装、更新和卸载流程。

业务或网络超时不等于数据库事务已结束。TTL 180 秒为短事务提供较大的异常余量；进程退出且未释放锁时，同一插件可能等待接近剩余租期，其他插件使用独立 key。

## 复用现有持久化记录

账号期望状态仍在 `kinds` 的 `InstalledPlugin/default` 记录中；设备实际安装状态仍在 `plugin_device_installations` 中。

同步状态保存在原有 `kinds` 记录：`user_id=当前账号`、`kind=PluginSyncState`、`namespace=plugin-sync`、`name=account`。JSON 继续保存 generation、设备水位、每实例每插件的请求顺序和最新受理标记，以及 `creationRevisions[安装名称]`。不新建 `plugin_states`，不运行全量或按需数据搬迁。

`InstalledPlugin.spec.writeRevision` 保护认证、安装和设备记录的共同提交；安装意图的 `spec.revision` 在安装、更新和卸载等期望状态改变时推进。现有记录缺少版本时按 0 处理，正常写入时递增，不批量回填。

首次安装尚无安装行时，在该插件 Redis 租约下读取对应的创建计数，提交时只比较该插件的槽位。不同插件的元数据使用 JSON 路径合并；它们可能短暂争用同一同步记录的数据库写锁，但不跨下载、适配器或 IPC 等待持有该行。

快照先读取同步版本，再读取期望状态并 CAS 发布 generation。设备回执核对 generation、水位、安装意图和当前期望状态，迟到回执不能直接恢复已经卸载的安装。正常认证只校验真实账号策略，不递增共享偏好版本；只有编辑自动授权开关才修改该版本。

## 首次初始化的约定边界

`PluginSyncState` 和 `ConnectorAuthPolicy` 第一次创建由 180 秒 Redis 元数据租约协调；已有记录使用 CAS。

本方案明确接受以下残余风险：如果数据库 COMMIT 未决或进程停顿跨越租约到期，后继初始化仍可能查空并再次插入。无数据库唯一约束时，TTL 和续租都不能证明首次创建严格唯一。发现重复记录时拒绝自动选择，需要人工核对处理。该边界需要人工审查确认，不能把普通并发测试通过表述为极端提交故障已被消除。

## Native 与后台同步

沿用 V2 同步协议及 HTTP 本机操作入口。新版桌面执行器按插件准备包，并只在短暂的 manifest 发布阶段共享元数据锁；相同目标的 HTTP／Socket 重复投递复用准备结果，分别核验各自 generation。目标变化、更新和卸载继续终止旧目标的等价范围。

桌面持久化缓存将目录元数据编码与逐插件安装状态分开；目录未变化时复用已有编码，安装、卸载和受理回执仍在同一次同步存储写入中保存。目录以 256 项为一块，仅元数据变化的块需要重新编码；冷启动复用已保存的编码，避免每个插件完成都重复压缩整份目录。首次加载或真正更新大目录仍有编码开销。

Native 的包摘要和激活内容扫描复用已有 `ring` 依赖计算 SHA256，避免 Debug 构建的软件哈希耗时放大发布锁等待。摘要格式、完整文件读取、文件身份与修改时间核验以及篡改检测保持一致。

普通插件操作不取得本机完整对账队列。完整对账串行合并扫描证据，等待期间不持有短 journal 租约；前台操作到来时，旧计划在提交前重新核验。刷新遇到 `plugin_local_sync_busy` 时沿用有界暂缓机制，前台安装、更新和卸载可以继续。

幂等的本机安装意图和后台设备准备可在 20 秒重试窗口内重试 `plugin_write_busy` 与 CAS 冲突；每次重试先回滚并关闭原会话，再重新读取当前意图，不重放已执行的设备 RPC。后台只读检查不申请插件写租约，没有其他目标设备时不创建待同步记录；源设备回执仍负责清理设备别名记录。

Native 与注册回执的查询、租约获取和事务共用 20 秒截止时间。同批插件独立推进，某个插件持续繁忙时，其他无争用插件仍可入库。批量获取租约不等待繁忙的后续插件，每次 Redis 请求受绝对截止时间约束，失败时释放已经取得的租约；超时返回前仍等待正在进行的清理完成。

共享回执 flush 先按主键顺序锁定本次更新、删除的设备安装行，再按资源标识锁定待插入行的已有记录，最后执行账号同步状态 CAS 和设备写入。行锁等待发生在取得账号状态写锁之前；CAS 失败时仍不会发出后续设备写入。别名整理与待同步准备也先处理设备行，元数据发布只更新账号状态；Python 插件写入在修改数据前取得相同插件租约，避免跨入口反向持锁。

MySQL 如果以 1213 中止插件同步事务，事务层先回滚并释放原会话，再从新会话重建快照，沿用和账号状态 CAS 冲突相同的重试预算。

本地落盘结果先保存到 journal，再请求服务端确认。确认暂时失败时，保留实际安装结果、已受理操作和 `reconcilePending`，不建立当前确认凭证并显示待确认提示；后续自动检查或手动刷新重新核验并确认。存在已注册源设备时，只有确认完成后才返回 `localCompleted`；尚未注册设备的本机操作仍独立于设备回执执行。迟到或失去所有权的回执不能覆盖新的安装意图。

自动认证保留启动、重连、插件清单变更和本机登录／退出事件触发，以及 300 秒、每进程 ±30 秒抖动的补充巡检。准备和只读状态查询不占整批插件写租约，凭据提交时才取得目标安装的租约。

Native 授权写请求携带 `X-Wegent-Plugin-Auth-Contention: 1` 时，前置查询、插件租约、首次账号策略租约及写入前的所有权校验共用 200 毫秒截止时间，每个键尝试一次。Redis 确认租约已占用时，携带 `X-Wegent-Plugin-Auth-Result: 1` 或 `2` 的请求收到 HTTP 200 和可重试业务码 `plugin_write_busy`，仅协商短取锁预算的客户端收到带标记的 503。若 Redis 的取锁回执在截止时间内未返回，且服务端能确认写事务尚未开始，协商 `X-Wegent-Plugin-Auth-Result: 2` 的请求收到 HTTP 200 和可重试业务码 `plugin_write_lease_timeout`。这两个 HTTP 200 业务响应均携带 `success:false`、`retryable:true` 及响应头 `X-Wegent-Plugin-Auth-Contention: busy-before-write`。启用短预算但未协商版本 2 的请求在回执超时时仍收到无标记的 503。取锁回执超时可按 `outcome=redis_set_reply_unknown`（回执未知）与 `outcome=redis_set_reply_late`（截止后确认取得）单独统计。依赖故障和事务结果未知沿用原有错误响应。

服务端先为迟到回执预留清理名额，再发送一次 `SET NX PX`，给初始租约 1 秒有效期。在 200 毫秒预算内收到确认后，服务端原子校验 token 和剩余有效期，并将租约延长至 180 秒，再进入写事务。迟到的初始回执只触发按 token 清理。初始回执始终未知时，租约最多自 Redis 执行 `SET` 起占用 1 秒。清理名额已满或续期未获确认时，协商版本 2 的客户端收到 `plugin_write_lease_timeout`，可分别按 `redis_cleanup_capacity_exhausted` 和 `redis_lease_promotion_not_confirmed` 统计。续期已生效且无法确认或释放的租约仍由 Redis 到期清理。已开始的事务遵循原有提交保护。

Executor 对同一次前台操作最多发出三次 HTTP 请求，争用重试和结果确认共用这个额度及原调用截止时间。

- **写前争用。** 普通占锁的重试须在首发后一秒内发出。收到取锁回执超时的业务码后，争用重试窗口延至首发后三秒，第三次争用尝试最早在首发 2.7 秒后发出。前台重试期间显示处理中。在已发请求均确认未写入的情况下，耗尽预算后提示稍后重试。支持续期补交的收尾操作收到写前重试标记时，只要账号、后端和设备密钥均一致，就可在原预算内用续期后的令牌补交原结果。
- **写入回执丢失。** 对 `oauth.finish` 等支持幂等补交的收尾请求，若接近截止时间仍未收到响应且还有请求额度，Executor 可在原会话内用相同操作 ID 和请求体并行补交一次。补交可以在三秒争用窗口结束后发出，两笔请求共用原调用截止时间。任一请求的成功回执都可确认结果。服务端校验账号和目标后重放已记录的成功结果，同一结果只递增一次安装版本，最多发布一次凭据变更通知。两笔均已发出时，会等到另一笔回执或原调用截止时间再判定失败。若两笔均明确在写入前被拒绝，返回繁忙提示。截止时仍无法确认结果则保留传输失败。

登录触发的登记有独立调度容量。会话或 Socket 恢复可用时立即唤醒前台调度，发现失败的目标仍按其原定时间重试。普通巡检最多同时执行四个插件的登记，运行时准备在取得登记名额前进行。同一插件中新加入的连接器也可独立准备，实际写入仍串行。临时发现失败保留该目标的前台登记预约。账号切换后，旧任务的结果不写入新会话的预约或退避状态。巡检沿用现有退避并重新读取状态。Socket 请求沿用原有协议。

排查 Native 授权的争用、503 或慢请求时，用 `api.log` 的请求 ID 在 Rust `info.log` 中找 `Native plugin authorization finished`。预期争用记录为 `outcome=lock_busy_before_write`，在启用业务响应后仍可单独统计。按 `operation`、`failure_stage` 和 `outcome` 核对前置 MySQL 查询、Redis 取锁、授权事务、事务内 Redis 所有权校验、解锁及通知的耗时。标为 `mixed` 的阶段包含 MySQL 和 Redis 调用，事务内所有权校验的耗时是事务耗时的子集。依赖故障用 `failure_dependency` 标记，可用 `mysql_error_kind` 和数字 `mysql_errno` 区分已识别的 MySQL 错误。

## 部署与已有开发库

旧用户锁与插件锁不是同一协议。切换 Python／Rust 写入进程前，先停止受理并排空旧插件事务，再统一切换，避免新旧锁协议混跑。

从 main 部署本方案无需新增协调表或执行数据迁移；正常启动仍执行 main 已有的数据库迁移。

若开发库曾运行本 PR 的有表版本，切换前保留备份，并使用旧版本 `e677c1a84` 的原生迁移工具执行 `wegent-backend-rs db downgrade b1c2d3e4f5a6`。它把新表水位和最新回执合并回旧 Kind 后删除新表，同时保留 main 的分享链接迁移。核对迁移版本后再启动无表版本。不要直接清空新表或手动 stamp 跳过回写；本次代码修改不自动操作开发或线上数据库。

## 验证

复用现有插件单元测试、真实 MySQL／Redis 集成测试和桌面检查点，不新增 CI 作业。检查不同插件同时持有 180 秒租约、同插件竞争与 CAS、首次普通并发、账号隔离、重复投递、迟到回执、后台认证及完整对账与前台操作的隔离。

真实 Redis 用例检查 PTTL，HTTP 身份用例继续接入 `test_plugin_write_races_mysql.py`；桌面沿用 `plugin-write-coordination` 和本机同步检查点。首次初始化跨租约的严格唯一性不属于本方案保证范围。

本机 HTTP 的真实 MySQL/Redis fixture 同时检查 Native 和注册入口中“同批 A 持续被锁时 B 仍入库”、连接池等待和行锁超时后的租约清理。慢 Redis 的截止时间由虚拟时钟单元测试覆盖；确认中断和恢复接入现有 `plugin-write-coordination` 桌面检查点。
