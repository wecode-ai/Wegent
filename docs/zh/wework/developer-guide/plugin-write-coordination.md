# 插件认证与安装的写入协调

安装、更新、卸载、认证和设备回执复用插件 Redis 租约与数据库 CAS。
不同插件不共用用户写锁；同一插件的多设备操作使用同一账号安装身份。

## 身份与状态

- `kinds/InstalledPlugin/default` 仍是安装期望状态；`plugin_device_installations` 保存各设备执行结果。
- 新增 `plugin_states`，通过唯一键 `(user_id, plugin_key)` 保存该插件的创建计数、同步 generation、设备水位、最新受理标记和请求顺序。
- `plugin_key` 沿用安装名称派生规则，首次安装前可计算；`installed_kind_id` 绑定原安装行。目录修复重命名时先按原安装 ID 查状态，保留版本和回执。
- 不修改公共 `kinds` 的列或索引，不增加独立操作账本；不使用 `FOR UPDATE` 或 `GET_LOCK`。

## Redis 租约

key 为 `wegent:plugin-write:{user_id}:{InstalledPlugin.name}`。设备号不能分割此锁，
否则两台设备会同时改变同一账号安装。历史名称修复时也取得原身份的租约。

TTL 为 30 秒，单插件争锁最多等待 3 秒，事务预算为 20 秒。Python 每 10 秒续租；
Rust 复用现有有界租约。所有权检查、续租和释放都比较持有者 token；失去租约的旧请求不能释放新租约。
事务提交、回滚或关闭后释放，保存点结束不释放。

批量目标按身份排序，多个目标不逐个等待忙锁；失败时先回滚再释放已取得的租约。
网络下载、认证适配器和设备 RPC 均在数据库写事务之外。新版协议按插件并行准备；
本机共享配置的生成和比对复用发布短锁，包下载、解包和文件校验仍在锁外并行执行。

## 首次创建与 CAS

首次安装先原子插入该插件状态。数据库唯一键把同一身份的竞争保持到 COMMIT 或回滚；
即使 Redis TTL 先到期，也不能插入第二条状态。不同插件竞争不同唯一键，可独立提交。
Python 使用已有的有界初始化连接池，数据库等待超时后明确失败，不无限占用业务连接。

安装行、创建计数 CAS、安装 ID 绑定和业务变更在同一安装事务提交。
旧首次安装只能在原创建计数仍匹配、绑定 ID 未被其他安装占用时提交。
软卸载保留安装与状态；重装继续沿用水位，不能被旧安装或迟到回执恢复。

已有安装使用两个版本：`spec.revision` 表示安装意图；`spec.writeRevision` 保护安装、认证及设备结果的共同提交。
内容替换同时比较两个版本；事务内已成功推进写版本后不重复推进。
状态 JSON 由 revision CAS 或独立设备路径的原子合并写入；水位取最大值，不能回退。
保存点回滚恢复预期版本；失败事务的“已写入”标记不能绕过后续 CAS。

## 同步协议

新版协议 V3 的快照先捕获插件元数据版本，再读取安装意图，最后逐插件 CAS 发布。
`plugin_sync.revisions[安装ID]` 为逐插件 generation，`intentRevisions[安装ID]` 为安装意图 revision。
`complete=false`，卸载目标通过 `removed_plugins` 明示，不能以快照中缺席来删除其他插件。

新状态从历史 V2 generation 基线起步，之后独立递增，避免切换时接纳历史迟到消息。V2 快照同时抬高所覆盖插件的 generation 下界，保证客户端升级到 V3 后能超过旧水位。
完整 Skills/MCP 同步使用独立的 `@capabilities` 顺序流；普通插件操作不触碰它。
V2 快照使用 `@legacy-v2` 聚合 generation，并在发布前 CAS 校验各插件版本。日常插件写入不更新账号聚合行。
新协议的普通插件操作不创建或推进账号聚合同步状态。

回执落库检查插件 generation、设备水位、当前安装意图 revision 和实际期望状态。
数据库冲突仅重试数据库事务，不重新执行已经成功的设备操作。
已提交的安装不会因为后续回执暂时未落库而被报告为安装事务失败。

## 自动授权偏好

`ConnectorAuthPolicy/plugin-auth/account` 继续保存真实账号偏好。
只有修改账号开关才取得专用策略租约并递增策略版本；安装、更新和卸载不依赖该偏好。
认证提交用条件空更新验证读取的策略版本，保证禁用或撤权不会被并发认证覆盖。

首次策略创建使用同一新表中的 `@account-policy` 唯一身份，身份与策略在同一短事务提交。
普通认证不写该初始化身份。重复策略或非法版本明确失败，不任取一条、不重置用户偏好。
云端自动授权只获取确实缺少设备授权的插件租约，已授权、已撤权或未连接的插件不会被批量锁住。
Socket 认证复用当前事务查询插件作用域并初始化策略，避免持有业务连接时再次等待同一连接池。

## 迁移、部署与验证

迁移 `a5b6c7d8e9f0` 将旧活动同步 Kind 拆为插件状态并保留水位和最新回执。
建表前检查歧义和非法计数；回滚合并最大水位和最新回执，再恢复旧 Kind、删除新表。
后端切换前需排空旧进程的插件写事务，Python 与 Rust 同步切换；旧后端不能在迁移后继续写原 Kind。
旧桌面由新后端的 V2 协议服务。生产迁移和部署不属于本地验证。

回归覆盖真实 MySQL COMMIT 跨 Redis 租约到期、同插件防重、不同插件独立提交、失效事务 CAS、
安装/更新/卸载、认证和迟到回执。复用既有 Backend MySQL CI 与桌面
`plugin-write-coordination`、`plugin-registration-coordination` 场景；验证结果以当前提交对应的证据为准。

排查时按 `user_id`、`plugin_scope`、`session_id`、`operation` 与 `held_ms` 对齐租约日志。
`plugin_write_busy`、Redis 不可用、租约失效和 CAS 冲突是不同阶段，不能将其统一当作锁泄漏。
