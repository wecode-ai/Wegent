02 · 架构边界

控制面回答“应该是什么”，运行面回答“现在是什么”

Wework 云端控制面

  • 市场目录、来源、权限与推荐排序
  • 全部历史 Release 与最新指针
  • 账号期望版本、投稿、审核、镜像任务
  • 设备 pending / installed / failed
签名 URL
同步事件
逐插件结果

本地 Codex 运行面

  • 下载、SHA256、Manifest 校验
  • 原子暂存与更新失败回滚
  • Codex App Server 安装与卸载
  • 本地创建、Token 与 MCP 密钥

关键口径：云端接口完成 ≠ 当前设备已安装；App Server 回执才是设备事实。

03 · 数据归属

该上云的可治理，该留本地的保持私有

数据位置原则
市场 Plugin / ReleaseMySQL稳定身份 + 不可变版本
ZIP / 图标 / 截图MinIO / S3私有 Bucket + 10 分钟签名 URL
账号安装意图kinds/InstalledPlugin复用现有 CRD，不存 ZIP
设备执行结果plugin_device_installations按设备记录 actual 与 error
本地创建插件wework-personal发布前绝不上云
Token / MCP 密钥本机安全存储不进包、不进日志
skill_binaries 只保留旧 Skill；V2 Release 全部迁移到对象存储，避免 16MB 上限和按用户复制 ZIP。

07 · 本地创建与发布

“创建”与“发布”是两次明确动作

创建：始终本地

描述需求→标准 Plugin→wework-personal→我创建的
my-skill/
├── .codex-plugin/plugin.json
└── skills/my-skill/SKILL.md

发布：显式上云

本地检查→签名直传→服务端扫描→人工审核

审核通过生成不可变 Release；本地原件不被市场版本替换，后续修改发布新 SemVer。

09 · 迭代路径

按“数据 → 安装 → 市场 → 发布”降低切换风险

P0.1底层重构五张表、对象存储、迁移工具、旧路径退役
P0.2安装闭环签名下载、Codex Manifest、设备状态、失败回滚
P0.3受控市场唯一云端目录、来源 Badge、手动更新、精选镜像
P1创建与发布单 Skill Plugin、直传扫描、审核、内部白名单

发布顺序：Backend / Executor 先上线，Wework UI 后上线；迁移核验通过后再关闭旧 Kind。

10 · 风险与验收

完成的定义：失败可见、版本可回退、来源可追溯

安全ZIP 穿越、敏感文件、展开体积、SHA、Manifest、签名过期
版本新装最新、旧装手动更新、失败保留旧版、Release 不可变
设备在线成功、离线 pending、逐插件错误、重启后状态一致
发布创建不上云、审核前不可搜、驳回后新版本重投
权限普通用户无任意 Marketplace；无权限不能取下载 URL
验证Alembic 往返、Backend、Executor、Wework、真实 Tauri E2E
建议立即以 GitLab Engineering 作为第一条精选镜像验收样本：它同时覆盖上游同步、鉴权、版本更新、企业域名和真实开发场景。
