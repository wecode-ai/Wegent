# 我的助理

从 Wework 左侧栏选择 **我的助理**。启用[协作体验预览](./collaboration-experience.md)时，这里会打开新版助理中心。关闭预览后，同一入口显示原有助理页面。已配置的助理、来源和处理记录会保留。

## 在 Issue 中持续协作

指派 Issue 或在评论中 @ 成员，会唤醒该成员已开启、连接此项目、匹配标签且允许自动处理的助理。
也可以 @ 自己：助理会接收，但不会给自己发送人员提醒。
同一个助理在同一个 Issue 中沿用已有会话；重新指派不会清空历史，也不跳过新的权限核对。
改派、取消指派、删除原提及或暂停自动接收后，仍可继续和重试已有会话，公开回复也会继续同步。
手动启动助理不要求 Issue 指派给自己，也不会自动更改负责人；自动接收配置用于筛选新工作，不限制用户主动操作。项目与 Issue 的实际访问和执行权限仍需有效。
首次启动失败时，可以在原 Issue 重试，无需删除会话或重新指派。已有原生会话会被续接，尚未建立会话时会在原任务上重新启动。最近一次启动失败的错误码、脱敏错误信息和时间会持久保存，重试或重启后仍可通过会话查询的 `startup_failure` 查看。
较多步骤的分派工作默认交给原生子代理执行，无需在任务里额外要求“使用子代理”；默认助理负责协调、核验并简洁回复，简单问题直接回答。通常只发布简短接单和完成结果，必要时说明阻塞、提问或请求原生审批；常规工具与子代理进度不逐条发布为评论。子代理执行期间仍可输入和发送评论，后续唤醒按顺序处理。
直接回复助理评论时不必再次 @，回复会交给该原助理。私人聊天、推理和工具过程不会同步到评论区。

Issue 中的助理回复以“所属用户 (助理名称)”署名，例如“张三 (助理)”，便于区分不同用户的助理。成员姓名暂不可用时显示用户编号；成员信息加载后显示姓名。

## 助理聊天与桌面通知

从 **协作 → 我的** 可在右侧 **助理** 标签查看按助理划分的任务列表；点击任务在右侧继续原任务会话。首页只展示 Issue 相关助理任务，**助理设置** 打开已有配置；点击 **对话** 进入协作聊天。未连接看板时先显示连接引导。首页固定保留助理标签和一个 Issue 详情标签；打开另一个 Issue 会替换当前详情，重新打开仍保留草稿，私人助理聊天不会自动发布到 Issue。

上一条回复结束、或后台结果刚触发新回复时，可以继续发送要求；消息会按当前回合状态送入原会话。

发送消息后，等待助理首段回复时会显示三个点。首段正文到达后，回复立即显示，输入框恢复发送按钮。即使子代理还在后台运行，也可以继续发送跟进。

此聊天样式用于“我的助理”的默认助理及你添加的助理对话：每条原生 AI 消息独立展示，后台执行前的确认语与执行后的结果不会合并。聊天中不显示内部“引导对话”或“执行 X 秒”；普通任务和代码会话的执行过程展示保持不变。

运行时对助理身份会话和协作 Issue 的助理会话启用原生 subagent v2，包括恢复已有会话；普通任务保留默认配置，明确配置的 single 协作模式仍禁用子代理。原生权限、来源范围与审批约束保持不变。

执行设备离线或不允许当前设备访问时，仍可打开 **管理助理**，在 **在哪里处理** 选择其他设备。保存期间设备选项暂时不可用。

从 **左侧栏 → 我的助理** 打开默认助理或你添加的助理对话。你的消息显示在右侧灰底气泡，AI 回复显示为左侧无边框正文。收到后续回复后，已回答的普通问题摘要会自动隐藏。原生 subagent 在后台执行时，输入框仍可发送下一句话；新消息送入同一个主会话，不停止原子代理，也不等待普通任务队列。发送失败保留内容和附件。待回答问题和权限确认仍通过原卡片处理，聊天消息不会代替授权。独立任务只用于确实需要单独会话、工作区或生命周期的工作，不是保持聊天可用的前提。

桌面端输入框上方的 **开启桌面助理通知** 提示提供 **打开通知设置**、**不再提示** 和 **暂时关闭**。打开通知设置会进入系统通知设置（macOS、Windows）及 Wework 铃铛的统一设置；请允许系统通知，并检查“助理主动提醒”的系统通知开关。Linux 需自行在桌面环境的通知设置中允许。打开设置不代表权限已经授予。暂时关闭仅作用于当前应用会话；不再提示按账号保存在当前设备，只隐藏提示，不关闭通知。也可随时从顶部 **铃铛 → 通知设置 → 助理主动提醒** 调整。

**我的助理** 旁的数字统计各助理对话中的未读 AI 消息，不统计内部 subagent 数量或任务完成次数；超过 99 显示 **99+**。阅读前台助理对话会清除该对话的未读，后台或隐藏窗口不会自动标为已读。一轮助理回复结束后最多弹出一条桌面通知，显示最终回复。由助理汇报的后台任务通过助理会话发送结果。默认助理的弹窗标题为「我的助理」，点击返回对应设备、账号和助理对话；切换账号不会沿用其他账号的计数。系统拒绝通知时，消息仍保留在会话和通知中心。

<a id="assistant-teams"></a>

创建助理时，可以创建新的 Team，也可以选择已有 Team。选择已有 Team 后，助理直接使用它的提示词、Bot 和协作模式。需要为这个助理修改这些配置时，确认复制 Team，再将修改保存到副本。取消复制会保留原来的 Team 和配置。在 **管理助理 → 运行环境** 中修改设备或工作目录无需复制 Team。

## 组建助理团队

在 **我的助理 → 团队 → 创建团队** 中填写团队名称，选择牵头助理与成员，并按需填写团队内职责。同一个场景角色可以加入多个团队，各团队分别保存分工。牵头助理使用当前设备的主助理或该设备上的场景角色，其他成员可以使用已配置的执行设备。

保存后，从 **团队** 列表打开团队，直接在团队对话中交办。牵头助理按团队成员和分工委派工作，结果回到团队对话。团队对话与助理自己的对话分开；更换牵头助理后，以新牵头助理开启对话。

从 **团队** 列表可以编辑或删除团队。删除团队后，成员仍可单独使用，也可继续参与其他团队。

### 在项目中采用我的助理团队

1. 在 Wework 桌面端打开你有权管理的项目，进入 **项目设置 → AI 配置 → 协作小组**，点击 **采用我的助理团队**。在 **选择本人团队** 中选中要采用的团队。
2. 为负责人和每个成员分别 **选择项目智能体**。每个岗位需要不同的项目智能体。云端项目会预选能唯一匹配到同一 Team 的智能体；手动选择时，核对智能体名称旁的编号。缺少对应智能体时，先到项目的智能体设置中添加并授权，再返回此处。
3. 再次点击 **采用我的助理团队** 确认。保存后，可把项目 Issue 指派给该协作小组。你在个人团队对话里使用自己的账号；项目 Issue 由绑定的项目虚拟成员按项目授权执行，个人连接和审批权限保留在个人账号。

**维护与重新绑定。** 在 **我的助理 → 团队** 编辑名称、负责人、成员和职责。在项目小组中可编辑描述、阶段和执行要求。来源新增岗位或小组提示需要重新绑定时，由来源团队所有者回到 **采用我的助理团队**，选中原团队，补齐项目智能体或处理重名后再次确认。项目会复用原小组。

**离线使用。** 本地项目可以离线采用本设备保存的团队。引用工作区智能体的岗位需要该智能体已获项目授权；设备私有 Team 可以通过所选项目智能体运行。如果本机只有远端岗位的名称和设备路由，请先将该岗位导入本机，并在来源团队选用本地岗位。云端项目保存绑定需要连接云端；需要从成员设备导出执行定义时，该设备也须可连接。导出内容包含 Bot 提示词。[项目智能体与协作小组](./projects.md#agent-capabilities)

## 分享助理或团队

从 **我的助理 → 分享 → 分享助理或团队** 选择要分享的助理或团队，搜索并选中接收人，然后点击 **发送分享**。勾选 **允许接收人复制** 后，对方可从 **我的助理 → 分享 → 他人分享给我** 点击 **复制到我的助理**。连接、执行设备和工作目录由接收方在自己的助理中配置。

接收人可在 **他人分享给我** 里点 **直接使用** 开启独立对话，之后点 **打开对话** 继续。分享者维护配置，开始新一轮执行时会读取当前版本。 在 **我分享的** 中选择 **撤回分享**，结束接收人的使用权，已创建的副本仍由接收人管理。

复制两个包含同一来源助理的团队时，所在设备会复用该助理的已有副本。收到新版后，可在 **他人分享给我** 点击 **更新团队** 或 **更新到分享版本**，确认后采用新的分工或提示词。

## 把工作交给其他助理

在 **我的助理** 对话中交代工作时，可以直接点名你添加的助理。未点名时，职责匹配明确的工作可以自动分派。多位助理职责重叠且选择会影响结果时，助理会先询问。一个请求可以拆为多项工作，接手的助理也可以把需要其他专长的部分继续分派。

开发助理交付初稿后，派出任务的助理可以把评审意见交回原任务。你也可以等结果返回，再在同一对话里说“让开发助理继续修改刚才的初稿”。开发助理会在原任务里接着做，沿用此前的对话、工作区和任务权限。一个助理可以同时处理多个独立任务。分配助理可以查找本会话此前直接委派的任务。如果有多份初稿，可以用任务标题指明要修改哪一份。

在原对话的消息流中展开 **委派任务** 卡片，可查看接手助理、进度和失败原因。点击右上角的 **助理详情**，在浮层的 **进行中的委派** 中查看当前分工。点击对话右上角的 **任务与委派**，在右侧同一列表查看该助理的任务和委派记录。委派结束后，卡片保留在历史消息及右侧记录中。任务提出可直接回复的问题时，可以在卡片内作答。点击任务可打开该助理的独立会话，查看完整记录和处理原生权限审批。每位助理使用已保存的模型和工作目录，助理的长期对话可继续使用。任务结果逐级回传，由接单助理在原对话汇总。

跨设备委派使用同一 Wework 账号下为助理设置的执行设备。设备离线时，任务显示 **等待设备上线**。设备上线并接单后，可以从原对话打开任务记录。

有先后顺序的工作会显示 **等待前置任务**。前置任务完成后，后续接手的助理会收到其结果。前置任务失败或被取消时，后续任务显示 **前置任务未成功**。在失败分支旁选择 **重试**，可在原任务中重新执行该分支，其他分支保留进度和结果。

在任务卡内选择 **取消分支**，停止该分支及其子任务，其他分支继续执行。选择 **取消整项委派** 可停止此请求中的所有未完成分支。已完成的结果仍可打开。设备离线时，卡片显示 **等待设备上线确认取消**。

## 助理档案逐项操作

1. 左侧栏打开 **我的助理**，选择要配置的助理，点击右上角 **助理详情**，在浮层底部选择 **管理助理**。
2. 在 **设置** 中编辑 **助理名称** 和 **职责**。在 **运行环境** 区域可直接选择 **执行设备**；点击带右箭头的 **运行环境** 行，可设置该设备可用的模型和工作目录。不同助理可选择不同设备。
3. 在连接来源中安装/授权应用，选择接收范围及处理方式，保存后才启用。定时事项从该助理连接页的日历/定时交办进入，不是全局云端连接设置。
4. 在详情浮层的 **近期活动** 查看执行记录的状态与时间。工作在同一浮层只读预览，返回恢复列表位置；需要回复、审批或完整工作区时选择 **在工作区打开对话**。人工问题仍在统一的 **待你处理** 和原工作中处理。
5. 删除你添加的助理时，在其设置中选择 **删除助理** 并确认目标。删除与暂停来源不同；如需保留助理并临时停止接收，可调整来源设置。

项目选择列表打开时，按 `Escape` 只关闭列表并回到原触发器；当前设置位置和未保存修改会保留。再次按 `Escape` 时，才执行当前设置页原有的返回或放弃确认。

进入助理时，页面先读取引导状态，读取期间显示页内提示。只有确认尚未完成设置后，才自动打开首次引导；已完成设置时直接进入助理。读取失败时可在提示中重试。

首次读取实例绑定期间只显示加载状态，不会提前提示账号不匹配。同一次应用会话内，切换到任务或看板后再返回，保留已加载的助理界面，配置在后台刷新；离开助理时暂停工作列表与配置提案轮询。切换账号或云端服务时不会沿用上一账号的页面数据；只有读取到实际绑定后，才提示是否需要连接原账号。

可以在任务侧边栏打开带 **Beta** 标识的 **我的助理**，持续交代工作、追问进展，或请 AI 拟定新助理。顶部直接展示默认助理和已添加的助理，方便切换。默认助理的对话与具体工作的执行记录分别保存；切回默认助理后，可以继续原来的对话。

**默认助理**可以统筹和分派工作。点击顶部 **添加助理**，在默认助理对话中说明职责，并确认配置。要填写名称和 **职责**，从对话中的 **高级模式** 打开表单，点 **添加助理** 保存。每位助理都有自己的长期对话，可以直接找它，也可以请默认助理把相关工作交给它。右上角的详情浮层展示名称、接收状态、待处理事项、设备和近期活动，不展示头像和输出内容；**近期活动** 按时间从新到旧显示工作线程与执行时间，只预览最近三条，左侧图标表示执行状态，选择 **查看全部活动** 打开完整列表。在 **管理助理 → 连接 → 日历** 查看和编辑定时安排。工作在浮层内只读预览，底部的 **在工作区打开对话** 进入完整会话。

## 执行设备与旧档案恢复

登录同一云端账号的其他设备也能看到已同步的助理。要从其他设备给运行在桌面 Wework 上的助理发消息，执行设备需开启个人任务远程访问。新消息在助理配置的设备上执行。

连接云端账号后，从 **左侧栏 → 我的助理** 直接打开账号的默认助理。各端读取同一个 solo Team 及其 Bot 和 Ghost。如果账号尚未创建默认助理，Wework 优先检查本机保存的助理档案。确认导入后再打开助理，执行设备默认沿用原设备。没有可导入的档案时进入首次设置。

在 **助理详情 → 管理助理 → 运行环境** 中选择 **执行设备**，云端账号按助理保存选择。默认助理会立即切换到所选设备，你添加的助理在点击保存后对新任务启用新设备。若默认助理此前记录的是其他桌面客户端的本地私有设备，当前客户端会选用可用的云设备或本机执行环境，并保留原来的云端设置。助理列表跟随已保存的设备配置，已有任务、排队工作和同一 Issue 的已有会话继续在原设备处理，助理历史仍按各任务原来的地址打开。

助理归属按当前登录账号的用户 ID 判断；切换登录账号会直接加载对应账号的云端助理，更换云端地址或修改用户名也会保留同一用户 ID 下的设备档案。不同部署中的相同用户 ID 会被视为同一所有者，不提供跨部署账号隔离。云设备仍由当前连接校验归属和在线状态。所选云设备离线时，助理页显示设备离线提示并保留该设备选择。

更换助理设备后需要重新选择模型和工作目录，并确认目标设备上的来源账号和项目可用。系统不会复制凭据、搬移旧任务或重写旧会话。离线设备不可新选；目标保存失败时保留当前草稿。若目标启用结果无法确认，页面要求刷新目标助理，系统不会同时恢复原设备接收新任务。切换默认助理或已添加助理的执行设备均无需先停止原设备上的助理。

要停止默认助理当前执行设备上的助理，打开 **我的助理**。启用协作体验预览时，在助理中心顶部点击 **停止助理**。关闭预览时，选择默认助理，打开 **助理详情 → 管理助理**，在设置面板左下角点击 **停止助理**。然后确认停止。这会停止该设备上的接收，并取消该设备上的默认助理对话、助理对话、正在执行和排队中的派生任务。其他设备上的助理、归属不同用户 ID 的助理和普通任务不受影响。不同部署中的相同用户 ID 按上述规则共享本机助理归属。停止完成后，页面提供恢复该设备或切换到其他执行设备的入口；配置、记忆和历史保留，重新启用原设备会恢复原有接收开关。

设备离线、取消失败或执行进程尚未确认停止时，该设备保留 **停止中** 状态；恢复连接后可使用 **重试停止**，也可直接切换到其他在线执行设备继续使用默认助理。发起对已注册远程设备的停止请求时，账号先保存停止意图，同账号的其他客户端刷新后也可查看及重试；目标设备确认停止后才清除相应意图。本机停止意图保存在本机。**停止助理** 针对默认助理当前执行设备。设备离线且绑定仍处于运行状态时，离线提示处也提供停止入口。

发现待处理的旧档案或旧运行设备时，「我的助理」会提供迁移或恢复入口。设备已经停止时，可选择 **恢复此设备上的助理**。需要迁移档案时，选择 **迁移档案**（默认助理或你添加的任一助理）和目标设备，再点击 **迁移到此设备** 并确认。对于待处理的旧绑定，Wework 会请求停止旧设备上的助理并取消其任务。只有旧设备确认停止后才开始复制；旧设备无法连接或未能确认停止时，默认助理的恢复使用账号已有的云端定义。只有账号没有云端助理时才初始化默认定义。复制已添加的助理需要旧设备确认停止。复制成功后，Wework 打开已导入助理的设置。如果仅恢复云端助理且未复制档案，则返回 **我的助理**。

迁移保留旧档案、记忆和会话历史，在目标追加该档案的职责、模型设置及可见记忆。已添加助理的副本保留原协作标签。默认助理的副本标签列表为空，启用前需重新检查接收过滤规则。副本保持暂停，设备目录、项目/来源授权和安排需要重新配置后启用。迁移默认助理会将其执行设备切换到目标设备。复制已添加的助理时，默认助理的执行设备保持原样。如果旧设备停止后复制失败，可重试。若切换设备后目标启动确认失败，保留目标选择以便停止和恢复，不会自动重启旧助理。目标本来就处于停止状态时，只允许追加无设备权限的停用副本，不能借迁移改动原有配置或恢复开关。迁移时，带有原设备来源证据的学习案例保留在原设备。

旧设备重新连接后，打开助理时以云端定义为准，在本地备份冲突的定义。在 **默认助理 → 助理详情 → 管理助理 → 下载助理定义备份** 中，可以导出此前发现的冲突定义，包括原来的名称、职责和设备。

首次设置且没有可导入的已有档案时，从项目入口打开明确设备上的助理，会按已验证的链接设备选择初始执行设备。导入已有档案时保留其原执行设备。

在 **我的助理** 页面点击左侧任务栏的 **看板**，或在任务视图菜单中选择 **看板**，会打开个人任务看板。

协作项目顶部的 **我的助理** 同样带有 **Beta** 标识，可直接为当前项目配置助理，无需开启实验性功能。

## 连接 IM 对话

已登记的钉钉、Telegram、Discord 或微博机器人私聊发送 **`/standin`**（或 **`/mode standin`**）即可进入助理模式。没有指定助理的私聊会使用账号默认执行设备上的默认助理。请在 [个人默认执行环境](./devices.md#collaboration-device-defaults) 选择在线设备。首次使用机器人时，根据平台提示授权并发送 **`/bind`** 登记私聊。发送 **`/chat`** 返回 Wegent 聊天，**`/mode`** 查看当前模式。

新消息进入该助理已有的长期对话。Codex 正在执行时，新消息直接进入当前轮；空闲时开启新一轮。来源与审批要求随消息保留。旧的 task 模式迁为助理模式，旧的 IM 任务绑定会解除，旧任务和对话历史保留；任务页不再提供“继续到私聊”。在助理模式中引用任务通知或追问任务卡片时，所引用任务仅作为当前助理的资料，不会改变助理绑定或模型。任务通知订阅控制前台提醒；账号已有 IM 私聊连接由助理和任务共用，无需重复选择。同步、异步业务问题采用相同交互：引用问题回复时直接交回原任务；普通消息由助理结合待答问题和近期对话理解，明确回答时提交给原任务，无关聊天照常处理，有歧义时先确认。

## 手动设置与对话调整

点击默认助理设置中的 **运行环境** 进入二级页，可查看设备并选择本地项目、工作区和模型。点击左上角可返回设置并保留草稿。新工作的默认目录和模型，以及助理聊天新回合的模型，使用保存后的设置。

在 **助理详情 → 管理助理** 中设置各助理的职责和工作来源。默认助理的设置若显示 **私人偏好**，可以填写你希望它怎么和你交流，例如「用中文回复，先给结论，再列待办」。点击 **保存设置** 后，助理只在与你私聊时参考这些偏好。处理钉钉群消息等外部工作时，助理按 **助理职责** 行事。偏好可以随时修改或清空，修改后需再次保存。

从普通助理会话点 **添加助理** 进入默认助理对话，点 **管理助理** 在当前助理会话调整职责。可以选择输入框上方的提示，发送后与助理确认细节。点 **高级模式** 可打开手动表单。AI 生成变更提案后，确认卡直接显示在当前会话中，列出受影响的助理、来源范围和处理方式。检查后点击 **确认并应用** 才会保存并生效；成功后，会话显示 **配置已应用** 及实际变更，失败则保留确认卡和错误提示。助理的新增群保存到该助理的连接中，不会同时扩大默认助理的来源范围，可切换到对应助理的设置查看。也可以从 **助理详情 → 待确认配置** 打开同一提案；关闭弹窗不代表确认或拒绝，卡片仍在会话中。可以继续追问、调整提案，或选择 **暂不应用**。设置已被其他操作修改时，旧提案不能覆盖新设置。

主界面提供对话、输入框、助理切换及 **添加助理**，右上角保留 **助理详情** 入口。详情浮层顶部显示工作接收设置。执行设备状态和近期活动也在这里查看。工作来源在 **管理助理** 中配置。有连接、设备或后台处理问题时，顶部显示 **待处理事项**。选择 **详情** 打开 **连接与运行状态**，查看完整记录和可用的重试操作。待确认配置也从顶部打开。如果后台评估因账号不匹配被拒绝，选择 **检查云端连接** 打开连接设置，核对当前连接的账号，再返回 **连接与运行状态** 重新检查。在近期活动中选择 **查看全部活动** 可打开完整列表；设置页直接显示 **记忆** 入口，不再堆叠这些入口。停止操作独立放在设置面板左下角。设置主页面、连接页面、来源详情都有明确入口和返回上级按钮；页头 **设置层级** 路径可直接返回设置或连接，不会绕开未保存内容的确认。后台主动更新使用独立标识，不显示为你发送的消息。

## 后台主动提醒

所有已连接来源共用提醒判断：与你相关的重要信息、紧急事项，或有具体证据支持的进度可能异常，都可以主动提醒，不要求一定需要你采取行动。提醒说明发生了什么、为什么现在值得关注、来源与时间，并区分已知事实、推断和不确定性。进度异常不要求已经确诊，但要能结合已知预期说明风险信号；仅仅缺少更新、旧问题的当前状态未知，或消息自称紧急，不足以触发提醒。已解决或被新状态替代的问题不能当作当前风险重复播报，重要的新里程碑或结果仍可提醒。

同一事项的相关事件合并判断，参考近期已发提醒跨批次避免重复；只有新增证据改变重要程度、紧急程度、进度判断或应对方式，才再次提醒。普通状态变化和重复投递保持安静，不为制造提醒而扩权或新建核实任务。有来源主题标识时一并保留账号和来源用于关联；缺少标识时不编造，以已有证据作语义判断。这是模型判断策略，不是实时状态的独立校验保证。你明确要求的报告、提醒、定时安排和已授权工作的执行仍沿用原流程，不会因此被静默忽略。

## 查看、编辑和遗忘助理记忆

<a id="stand-in-memory-controls"></a>

<a id="assistant-learning"></a>

**助理自主学习**是每个身份独立保存的实验性设置，默认关闭。在 **设置 → 通用 → 实验性功能** 显示实验功能后，打开 **我的助理 → 选择助理 → 助理详情 → 管理助理**。设置底部的 **助理自主学习** 区域包含学习开关和 **自主学习报告**。修改学习开关后需保存，关闭学习后仍可查看已有报告。隐藏实验性功能会收起整个区域，已保存的学习设置仍然保留。来源范围、代回复方式和发送审批在连接设置中管理。

学习复用记忆整理安排。各助理从自己的直接对话、当前已授权且能读取复盘证据的连接，以及自己可访问的工作事项中学习。收件箱邮件、GitHub/GitLab 已订阅的讨论可以提供来源观察。只提供采集事件的连接也能参与：复盘使用已按该助理、该次授权接收到的原始记录。只订阅状态变更时，复盘范围也仅限收到的状态事件。原生记录能核实作者和上下文时，也可以形成示范、肯定或纠正案例。没有代回复的记录也可以提供本人示范。读取和保存证据都要核实当前来源权限。云端工作事项的公开评论可在核实后计入返工；为遵守会变化的项目权限，长期保存的只有关联标识。

在当前身份的 **管理助理 → 记忆** 选择 **今日复盘** 或 **近七天复盘**，查看 **需要改进**、**做得好的**、**我的示范** 和 **来源观察**。单条可核实的来源事实只进入该助理、该来源的近期经验。展开 **查看工作案例** 可核对原话；**全部记忆** 可编辑或遗忘记录。

同一处的 **已回复请求的返工 · 跨版本累计** 区分两种数字。能核实助理实际发出的原答和你随后对同一请求的补答、纠正或解释，就计入已确认返工，一件事多次补答计一次。跨版本返工率另要求能核实当时的 Ghost、Memory 版本，且完整复盘首次回复后的 24 小时。仅接入收件箱、只读群内 @ 消息、缺页或没有可验证的身份等情况不能据此推断零返工。Codex 的版本记录包含本轮注入和发送前额外检索的记忆。Claude 执行目前缺少对应的上下文投递凭据。

版本比较使用同一助理在两个版本下都处理过的会话，显示各版本的已回复请求数，以及各会话返工率变化的中位数和 95% 区间。有足够记录时，也可以比较同一个 Ghost 下不同 Memory 版本的表现。版本标识来自实际使用的内容，相同内容再次使用会归入同一版本。这些数字描述已回复请求中的返工变化，无法衡量漏答或你在这些来源上的全部工作量。两个复盘页签均显示跨版本累计；当前结果与最近一次后台核验一致时，也会显示核验时间。日常核验静默运行。

近七天的案例和来源观察可用于后续答复。之后仍可在有权访问该来源时查看或遗忘。每个账号分别保留最近采集的 1000 个回复案例和 1000 条来源观察。达到上限时只替换同一类中最早采集的记录。普通记忆的容量单独计算。

积累独立案例后，执行设备在隔离的模型会话中比较原职责与候选职责，看改动能否改善答复并保留原来做对的事情。案例充足时，最多用六组独立事件提炼候选，再用另外六组比较答复。初评达到门槛后，助理用同一对拟答交换顺序复评。至少一例两次都改善，其他案例均无退步且依据充分，才会提出建议。回放只生成拟答。值得采纳的建议出现在该身份的 **待确认配置**，可查看文字改动、来源依据和对比结果，确认后才更新职责；在 **管理助理 → 自主学习报告** 中可查看并撤回仍适用的修改。默认助理的来源工作可使用助理职责，私人偏好仍由身份会话使用。关闭学习会停止新增案例和评测，已保存的记忆仍可管理。离线评测目前使用执行设备可用的 Codex 模型。

打开 **管理助理 → 自主学习报告** 可查看该身份在当前执行设备上的已完成迭代次数、当前职责评分、最近一轮优化前后的评分和建议状态。评分根据独立案例中胜出和持平的结果折算为百分制。优化后评分对应候选职责，采纳后当前评分才会更新。没有可比结果时显示「暂无」。

开启并保存该助理的自主学习后，可在报告中点击 **立即学习一轮**，用该助理已收集的案例启动一次评估，随后可点 **刷新报告** 查看结果。新案例仍由后台复盘收集。案例不足、可用案例已评估，或有学习正在运行时，报告会提示原因。职责建议仍需确认后才会应用。

「能力复测」展示理解意图、核实信息、判断准确、建议可执行和表达清晰。每个维度按该维度有可比分数的案例折算为百分制。至少三项可评时显示雷达图，一至两项可评时显示同刻度对比线。证据不足和不适用的维度保留状态，真实的零分保留分值。助理以盲评的整体胜负决定是否提出改进建议。建议可直接处理时，可从报告打开「查看改进建议」。也可在助理详情的「待确认配置」中按顺序处理。

默认助理记忆面板的“遗忘规则”也列出尚未关联新规则的“旧版遗忘指纹”，显示遗忘时间和指纹短标识。旧版没有保留事实原文或作用域，因此显示“作用域未知”，不会推测或恢复内容，也不会提供给模型或显示在项目专属面板中。选择“删除规则”并确认仅移除该指纹；一条旧记忆可能有多个指纹，其他限制保持不变。仍被新规则引用的指纹不能单独删除；并发变更需重新加载后再操作。

从 **左侧栏 → 我的助理 → 助理详情 → 管理助理 → 记忆** 打开记忆面板，先确认当前执行设备。

不必每次说“记住这个”。助理可以从当前已授权的正常对话中提取有持续价值的信息，例如稳定偏好、反复出现的约束、长期目标和可复用的决定。引用、假设、助手建议及其他人的事实不能直接变成关于你的记忆；来源内容也不能授予新的权限。

记忆搜索按响应大小分页；单条记录过长时会分块读取，不会因此跳过该条或挡住后续记忆。续读期间记录或可见范围变化，需要重新搜索，不能把旧页与新页拼成同一条证据。

会话历史整理读取用户和助手的可见文本。已授权来源的原生记录也可作为证据。工具输出中的原始执行过程及隐藏推理不会直接作为来源记录写入。

暂停助理接收新工作，不会撤销已保存的来源授权，这些信息仍可参与记忆。要停止整理，请暂停记忆整理安排；要撤销某个来源，请移除其授权。自动整理仅开放经来源与运行身份校验的记忆读写和进度工具，不开放 Shell 或外部写操作。

记忆整理任务默认不显示在左侧任务栏，包括运行中和已结束的记录。可从 **我的助理 → 默认助理 → 助理详情 → 管理助理 → 连接 → 日历 → 助理记忆整理** 查看运行记录并打开原任务；隐藏不影响后台整理或历史记录保存。

记忆整理和自主学习在后台静默运行。运行结果可从日历查看，职责改进建议可从该身份的 **待确认配置** 查看。

会话和外部连接的历史分别读取。某个外部来源不可用时，其他来源仍可继续整理，该来源的未完成进度可在下次续读。排查时，可按日历运行记录中的运行 ID 在执行设备日志里查找 `stand-in memory connection`，查看来源类型、读取阶段、耗时和错误码。

启用默认助理后，执行设备会自动创建一次 **助理记忆整理** 安排，默认每 6 小时检查一次。可从 **我的助理 → 默认助理 → 助理详情 → 管理助理 → 连接 → 日历 → 助理记忆整理** 查看周期和运行记录，并暂停、修改或删除。已暂停或删除的安排不会被后台自动重建。整理使用独立会话，不占用当前对话；执行设备和模型必须可用。完成后可从运行记录打开原任务查看结果；整理不会为了回报结果而自动启动具有普通工具权限的默认助理对话。

后台整理保留原文证据和作用域，按分页读取会话及长消息。尚未读完或保存失败的会话不会推进完成进度。纠正或遗忘后，后台整理不会从同一旧证据重建该条记忆；遗忘不会删除原始会话。同时按用户选择保留最小化遗忘规则，记录被排除的简短事实及作用域，不保留原始对话、文件或证据摘录。规则不是有效记忆；助理读取规则后，应按含义避免重新学习同一事实，但不能把同一主题下的新事实一并排除。精确指纹由程序校验，跨表述的语义判断由模型执行，尚不能据此承诺识别所有语义相同的内容。可在记忆面板下方展开“遗忘规则”，查看简短事实及作用域；选择“删除规则”并确认后，后续整理允许重新学习，取消不生效。删除规则不会立即恢复有效记忆，也不会影响其他规则。读取或删除失败时保留已有数据，并提供单独的重新加载入口。真实模型的跨表述语义效果仍需持续验证。

有保存原文证据的记录会显示 **查看来源证据**。展开可查看证据片段、来源标识，以及它是用户原话、助手原话还是来源记录。助手原话不代表用户事实。没有保存证据的记录不显示此入口；展开证据不会重新读取来源或修改记忆。

在面板中修改内容或作用域后，旧原文不再作为新记忆的证据展示；后台重新取得相符证据时可补齐。仅打开记录或不改内容地保存不会清除已有证据。

<a id="stand-in-model-selection"></a>

## 模型选择

助理设置中的模型选择支持云端模型和执行设备上的本地自定义模型。云端模型使用执行设备连接的 Wework 云端账号；本地自定义模型使用该设备的 provider 配置和认证。助理创建的具体工作沿用已保存的模型选择。切换执行设备后，请确认该设备具有对应模型的配置和访问权限。

在 **我的助理 → 选择助理 → 助理详情 → 管理助理 → 运行环境** 中打开运行环境设置，选择模型和思考档位后保存。我的助理聊天从下一条消息起使用档案的新设置，当前执行回合不会重启。档案改动不会改变已有工作任务的工作目录或会话。

在 **协作 → 我的 → 助理** 中点击 **对话**，即可在聊天输入框中临时切换模型。首次发送前直接生效；支持按会话路由的执行设备会在原会话切换 Provider，保留原会话标识、历史和草稿。较旧的执行设备可能显示兼容提示，此时下一条消息会在当前助理聊天中开启新会话；当前回合结束后再切换即可。临时选择仅作用于这段聊天。

助理聊天目前仅支持具备操作审批能力的 Codex 运行时。如果档案中保存的是 Claude Code 模型，请在运行环境设置中选择可用的 Codex 模型并保存，再继续聊天。

当前模型不可用时，可以在聊天页点击 **重新加载模型**。如果旧会话无法读取模型提供方，或档案模型与旧会话不兼容，可以选择 **使用新会话继续**。确认后，下一条消息会在同一个助理聊天中开启新会话，历史和草稿会保留。

<a id="stand-in-task-permissions"></a>

## 助理任务权限

打开 **我的助理 → 选择助理 → 助理详情 → 管理助理 → 运行环境**，在 **任务默认权限** 选择 **只读**、**工作区** 或 **完整访问**，然后保存。默认是只读。完整访问沿用普通对话的启用确认和高危命令审批选项。

你主动交办后由助理创建的 Codex 任务，在创建时采用接手助理已保存的权限模式。打开该任务的完整对话，可在底部权限菜单单独调整，从你提交的下一轮起生效。当前回合的审批仍可在原卡片处理。未设置权限的已有委派任务默认只读。后台续办和由 Issue、连接或日历触发的工作使用各自的执行策略。

将助理迁移到另一台执行设备后，新设备上的任务默认权限为只读。保存迁移后，可打开新设备上的助理重新配置任务默认权限。

<a id="stand-in-source-session-policy"></a>

## 连接钉钉和协作项目

连接页按来源展示 **已配置** 和 **可添加**，同一来源的群聊、邮箱或项目合并为一行；其他来源入口始终可见。每行显示接收范围、当前状态和下一步操作。已有范围不代表正在接收：协作项目未开启接收时仍保留范围摘要，并标明 **未开启接收**。日历位于独立的 **定时交办** 区域。

可以在顶部按应用名称或已配置的范围名称搜索，或点击 **已配置** 只看已有来源；点击 **全部来源** 恢复完整目录。计数按来源计算，筛选不会改变助理的配置。

在 **我的助理 → 助理详情 → 管理助理 → 连接 → 协作项目** 中，点 **添加接收范围 → 项目和独立事项**，即可搜索和勾选具体项目。也可以接收所有参与项目的事项，或排除指定项目。**独立事项** 是页面上的固定选项，可单独勾选，接收分配给你的独立事项。要跨项目接收参与人名单里有你的事项，可以在 **添加接收范围** 中选择 **我参与的事项**。**接收全部** 包含以上范围以及以后加入的项目。项目事项可在分配给你时触发，云端项目还支持在评论中被 @ 时触发。同一个助理只处理一次匹配多个范围的事件。

进入来源详情后，按提示安装插件或登录，再选择接收范围和处理方式。在远程执行设备上运行的来源需要到该设备完成授权。来源暂不可用时，仍可查看并移除已有接收范围。删除本设备的邮箱账号后，其他助理原有的收件范围会显示「邮箱账号不可用」。重新添加邮箱账号并选择新的接收范围后，可以恢复接收。返回连接目录或助理设置首页会保留当前草稿；保存后才生效，取消退出时确认放弃。项目标签输入后按 Enter 添加。未完成或超长的标签会阻止保存并保留输入；返回、关闭或关闭接收前需确认放弃草稿。修改范围或处理方式后，页面提示保存后生效；邮箱账号验证成功也需要保存助理设置才会开始接收新邮件。

GitHub 和 GitLab 登录后，点 **添加接收范围**，选择 **个人事件** 或 **仓库事件**。个人事件按账号选择，仓库按搜索结果逐项勾选。GitLab 自托管账号需要填写实例地址。范围修改进入草稿，统一保存后生效。

邮箱账号验证后，点 **添加接收范围**，选择收件箱，保存助理设置后开始接收新邮件。

<a id="dingtalk-delegation"></a>

### 连接钉钉

首次引导、默认助理和已添加助理共用钉钉连接页。点 **添加接收范围**，一次选择 **全部消息**、**群聊** 或 **私聊**。**全部消息** 包含可访问群聊的每条新消息和所有联系人发来的新私聊。要只收全部私聊，添加 **私聊 → 全部私聊**。选 **指定群聊** 或 **指定联系人** 才显示搜索。返回后可点已选范围修改或移除。群聊可选 **每条新消息** 或 **仅 @ 我**。私聊收到每条新消息时触发。在范围详情页点 **放弃**，或点左上角返回，会丢弃本次修改。在范围详情页点击 **保存接收范围** 后回到钉钉的接收范围列表。

默认助理的普通钉钉连接在发消息前需要你确认。

<a id="dingtalk-blacklist"></a>

要排除群聊或联系人，打开已添加的群聊或私聊范围，或从 **添加接收范围** 进入相应类型，把 **范围规则** 设为 **排除所选**，再搜索并勾选要排除的条目。取消勾选并保存可恢复接收。排除期间已轮询的消息会被过滤，轮询进度继续推进。如果设备离线或来源读取失败，恢复接收后仍可能收到此前未拉取的消息。排除只影响当前助理从该账号和来源类型接收新消息及派发尚未处理的消息。

<a id="dingtalk-group-message-scope"></a>

从 **左侧栏 → 我的助理 → 选择助理 → 助理详情 → 管理助理 → 连接 → 钉钉** 进入来源设置。搜索并勾选具体群后，在该群的接收范围中可以选择 **仅接收 @我**（默认）或 **接收全部消息**；已有的具体群也可以直接修改。私聊没有此选项。修改后点击设置面板的 **保存** 才生效；取消不保存。切换范围后从保存生效时开始接收，不补收此前的历史消息。接收全部消息不代表每条都回复，仍由助理职责、处理方式和发送确认策略决定如何处理。

群中手动发送的“自己 @ 自己”也可以交办工作。在筛选来源中明确选择自己作为私聊联系人并保存后，也可以在与自己的私聊中手动发消息交办助理；仍遵循该来源的处理方式和操作确认策略。仅开启“所有联系人私聊”不会启用这一入口，发给其他联系人的本人消息也不会被当作指令。助理发出的回复始终保留钉钉 AI 代发标记。

接收全部消息的钉钉群按最多 15 分钟的窗口补采。窗口超时后会从同一起点缩到 5 分钟重试。再次超时时，自动补采会跳过最近 5 分钟以前的积压，改用 1 分钟窗口接收近期消息。如果仍然超时，采集会随时间继续向前推进。被跳过的历史消息仍可在钉钉中查看。

排查某条群消息未触发时，在执行设备的 `dsh-core-runtime.log` 中按群 ID 和发送时间查找 `wework-dingtalk-collection`。日志记录轮询时间窗、接口返回的消息 ID 和连接器过滤原因。再按消息 ID 查找 `executor.log` 中的 `DingTalk group intake`，查看订阅过滤原因或入队状态。入队状态 `pending` 表示事件已进入队列。诊断日志只保留定位所需的元数据。

在与自己的钉钉单聊中交办时，助理需要澄清任务范围或缺失信息，会在该单聊中追问，后续回答沿用来源的会话策略接续处理。处理其他人的消息时，需要对方补充的信息在原钉钉会话中询问；需要你本人判断、选择或作出承诺的问题仍在 Wework 的“待你处理”和原工作中向你提出，不会发给对方。业务回答不代替发送审批或账号授权；发送追问失败或结果未知时，助理会在 Wework 中说明实际状态。

钉钉来源采集统一忽略钉钉明确标记为机器人发送或带有 AI 代发标记的消息，不限发送者，避免 Wegent 对话机器人的任务通知再次触发助理并形成循环。其他机器人的业务消息同样不会自动触发处理。人工转发通知或引用通知提问仍可进入处理；历史消息查询仍保留这些通知供理解上下文。

自动收取和主动查阅的每条钉钉消息都附带原始发送时间。助理按发送日期理解消息里的“今天”“明天”，再用本轮开始时的执行设备时间判断事项是否临近或已经过期。若时间或时区缺失，且会影响判断，助理会说明不确定性。

连接来源由 DSH 的统一 EventBus 调度。助理、GitHub／GitLab 侧边栏和任务订阅登记各自的监听来源，宿主合并重复采集，插件按资源读取，Executor 分别保存游标和投递回执。单次来源采集最多等待 15 秒，超时会取消该采集；已经进入会话的模型轮次按原会话管理。

每个来源可分别设置为手动交办、操作前询问，或自动处理。新钉钉连接默认在操作前询问。接入使用执行设备上已安装的钉钉插件及其账号；需要登录时，通过原有钉钉连接入口完成授权。

助理读取已连接会话的截图时，图片随该会话的只读查询下载到系统生成的临时文件，不会为查看图片再次要求操作授权。账号未登录或原有来源权限失效时，仍需恢复对应连接。要求在群聊中 @ 同事时，助理需要取得真实人员 ID 并通过回复工具的提及参数发送；正文里的“@姓名”只是文本。发送回复仍遵循该来源的确认设置，接口接受消息不代表已验证对方收到提醒。

进入 **我的助理 → 助理详情 → 管理助理 → 连接 → 来源详情 → 处理方式**，“处理方式”入口先显示当前策略摘要，点击右侧明确标出的 **配置**（整行均可点击）后展开设置，点击 **收起** 可折叠；保存助理设置后生效：

- **处理方式**：用下拉框选择 **手动处理**、**后台排队** 或 **触发即处理**。后台排队从当前来源首条待处理事件入队时起等待五分钟，再由助理判断需要处理的事件。默认助理的新连接默认后台排队，其他助理的新连接默认触发即处理。
- **每次新建会话**：默认关闭，继续这个来源的同一会话；开启后，每个新事件各用一个独立会话。关闭时，同一助理、同一账号下的同一具体来源使用同一会话，不同群聊、联系人或来源不混用。“全部范围”内的不同具体来源也不合并。明确回复未归档的已有工作仍返回原会话，重复投递不会再建会话。

处理方式和会话方式分别设置。已有工作与消息归属不因修改设置而重组。复用的 Codex 会话正在执行时，新事件可以进入当前轮。等待原生审批时，活跃轮次仍可接收新消息，审批卡继续等待你的选择。没有可投递的活跃轮次时，待审批的会话仍保留新事件。新事件需要更严格的审批设置时，由下一轮处理。来源会话归档后，新消息（包括引用旧消息的回复）会创建新会话，之后继续复用新会话；旧任务和消息保持归档，重复投递的旧消息不会创建新会话或重新执行。若要查看或恢复旧任务，可在 **近期活动 → 查看全部活动 → 对应工作 → 取消归档** 操作，恢复本身不会启动执行。后台仅派发本次选中的消息，不带上此前忽略或延后的消息。协作项目按 Issue 保持独立会话，不跨 Issue 合并；定时交办沿用每项安排的既有会话模式。钉钉来源的 **发送前逐次确认** 单独一行显示，仍通过原有确认流程管理授权。

直接处理不要求先填写职责或偏好。只有一个符合条件的接手助理时，后台统筹的历史失败或待答问题不应阻塞该来源的直接派发；原有问题和失败仍保留，不能因此自动回答审批或重放执行结果不明的命令。后台统筹重试会按实际会话和执行回执恢复，而不是仅凭已有任务记录尝试续聊。

角色任务正常完成或更新常规进度时，后台统筹保持空闲。失败、取消、待回答或待审批的任务状态，以及已安排的跟进，仍可触发统筹。统筹任务本身静默运行，重要发现通过助理会话传达。

协作项目沿用项目成员权限，项目专属智能体不能扩展接收其他项目或钉钉来源。多位助理都能接手同一来源时，由 AI 选择一个接手助理，避免重复执行。

后台按事件处理失败。云端事项读不到时，该事项的事件按实际结果取消或等待重试，已授权的其他来源事件继续派发。

已连接的协作项目显示项目名称，包括有项目访问权限但未加入其所属空间的项目。切换助理执行设备后，已连接项目的名称仍保留，也可以解除连接；只有在当前设备执行时，才能新增本地项目连接。

远程执行设备仍可使用“所有项目”范围，该范围使用所选执行器自己的项目目录，不会把当前电脑未显式连接的本地项目作为远程连接展示。

## 工作归属和操作确认

执行方式按任务需要选择：简单或紧密关联的工作可在默认助理直接完成；内部拆解可使用已有权限允许的 subagent；只有需要独立会话、工作区或长期追踪时才创建工作 thread。“发布新版本时通知我”等未来条件请求使用原生定时／监控安排，不用一次性 thread 或常驻 subagent 替代。安排必须经过现有确认并成功保存后才算生效。选择执行方式不改变来源权限、登录授权或操作确认。

新事件按来源的会话策略归属，不再由模型根据文本相似度自动合并。明确回复已有工作的消息保留原会话。在工作预览中展开关联消息，可以拆成独立工作，或移到同一助理的其他工作；调整归属不会重新执行已处理的消息。

需要确认的操作统一出现在 **待你处理**，从这里进入原会话的审批卡确认或拒绝，无需手动发送“是”。发送钉钉回复时，确认卡展示与该工具调用绑定的待发送正文。选择操作前询问时，写入文件、执行需要提升权限的命令和具有写入性质的 MCP 工具调用使用运行时确认机制。确认只针对当前操作，不提供长期放行规则。该策略目前要求使用 Codex 运行时。

## 统一处理人工判断

助理和普通任务提出的结构化问题共用同一条待处理事项。应用在前台时，通过右上角轻提醒发现问题；简单问题可以展开后直接回复。右上角通知铃铛中的 **待你处理** 打开同名页签，查看对应的原任务或 Issue，并在原界面处理。工作列表和通知条目不再各自提供独立回复表单。

待你处理顶部完整展示所选通知的原问题，并保留实体名称；窄屏隐藏列表后仍可直接阅读问题。待你处理是原实体的容器：任务定位到所选问题的原会话轮次，并展示对应的原生输入卡；Issue 展示已有 Issue 界面，并通过原执行和消息 ID 定位提出问题的 AI 消息及上下文，而非线程起始留言。打开通知时保留阅读位置，主动点击回复后才聚焦输入框。上下文、问题、表单、审批和授权均由原界面展示和处理，不额外抽取或总结对话，不另建回复表单。

容器顶部的 **在原界面中打开** 返回对应任务或 Issue，并保留源评论定位。需要完整工作区的文件、Review、计划和执行详情操作跳转到原任务；子 Issue 打开对应的原详情，不在待你处理内叠加工作区侧栏。

原任务即使未出现在侧栏列表中，打开后也会恢复它的标题、模型和工作区，支持继续对话。打开原任务不会改变侧栏原有的显示范围。

应用在后台时，按通知设置使用系统通知；支持文字回复的简单异步问题可通过系统通知回复。通知渠道在右上角铃铛的设置中统一管理，账号区域不再保留重复的全局 IM 通知菜单。系统通知还受操作系统权限和通知设置影响。

阅读通知、关闭提醒或标为已读不会完成待办。只有回复被接收或原问题已处理，事项才移入历史；发送失败会保留草稿。设备离线时保留上次已知的问题和草稿，重新连接并核对问题后才能回复。执行审批、连接器登录和复杂表单仍在原上下文处理，普通业务回答不能授予操作权限。Issue 问题的回复写入原评论线程后继续对应执行。

需要停止时，按[执行设备与旧档案恢复](#instance-binding-and-stopping)中的路径点击 **停止助理** 并确认。来源读取或启动失败会显示错误，可在修正登录、模型或来源设置后重试。执行器保存消息游标、去重记录和归属信息；重启后不会把已经接收的消息当作新消息重复处理。

来源采集失败不会永久停止接收，也不需要重新保存连接。执行器保留错误和原游标，在下一轮继续尝试；明确要求退避的超时或传输错误会在等待期结束后继续。此前因数据库锁定、配置变化或响应格式错误等原因停住的来源也会恢复采集。每次尝试仍检查当前账号和权限：登录失效、权限拒绝或无效响应的原因未解决时继续显示失败，不会读取未授权内容。成功后清除错误并推进游标，已有消息按原记录去重；自动恢复只针对采集，不会重放发送等操作。

## Issue 的人工介入闭环

Issue 卡片在标题上方已有的编号／状态行右侧，用图标区分智能体处理、助理处理和等人；等人使用人物叠加小钟图标，旁边只显示主体名字，悬停提示“等待某人处理”，不增加独立一行。执行状态确认正在运行时显示对应智能体或助理；有待回复的问题时优先显示接收人。没有运行中的 AI 时由指定的人处理，未指定则由 Issue 创建人接手，不显示“待分派”等第三种处理状态。排队、失败和离线等详情仍在执行详情中展示，业务状态保持独立。

AI 在绑定的 Issue 执行中提出结构化异步问题后，问题会保存到 Issue，包含原线程、执行身份和处理记录。责任人或协作小组负责人负责把问题分给具体的人；尚未指定接收人时仍由责任人承接，没有指定责任人则由创建人承接，不广播，也不自动选择协调人。AI 使用 `list_human_requests` 查询问题，原提问执行可通过 `set_human_request_blocking` 明确标记是否有步骤依赖答案；此操作不转派、不重置等待时间，也不会授予分派权限。责任人使用 `assign_human_request` 指定处理人。

接收人通过统一的“待你处理”和原 Issue 的问题卡作答。定向通知沿用协作通知设置及已配置的通知渠道。回答写入原评论线程，并交回原执行，不授予对方私人会话或设备的访问权限。读通知不等于处理完成；回答仅排队时仍显示等待接收，原执行接收后才解除对应标记。多个问题分别结算，仍有未解决的问题时继续显示“等人处理”。AI 只等待依赖答案的步骤，其他工作继续。

云端上报问题和源执行修改阻塞标记，需要原活动具备可验证的执行记录，准确关联项目、Issue、Runtime、设备及执行所有者。仅有手工任务绑定，或小组活动尚无匹配的执行证据时，会返回冲突（409），不能仅凭同名设备或推测 owner 继续；应先恢复原执行的可信记录。本地项目仍使用所属执行器的原生来源校验。

看板视图设置提供“仅显示待我处理”，按当前查看者匹配，而不是保存视图的人。离线时保留上次问题和草稿，恢复连接后再校验处理权限。执行审批、登录授权继续使用原生流程，业务回答不能代替授权。

项目看板工具栏还提供一键“待我处理”，它只影响当前查看，不会改写保存视图。全局“待你处理”包含原生项目中轮到自己的事项，以及明确向自己提出的项目问题；同一问题不会同时作为普通事项重复出现。选择项目事项后，在原有双栏内打开真实 Issue 详情，不创建虚构的运行任务。

### 等待时长与流程分析

“在你这里”从本轮交接给当前处理人的时点计算，转派给另一个人后重新起算。仅修改问题、阻塞说明、读取通知或保存回答不会重置时钟。普通事项从明确的人类分配、创建人首次接手或本轮 AI 执行结束的可靠时点计算；缺少本轮交接证据的历史记录显示“交接时间未记录”，不用更新时间冒充交接时间。时间按 UTC 保存，界面按自然经过时间展示，不等同于工作日内耗时。

问题保留提出、分派、回复、拒绝送达和执行接收等业务事件，包括事件时间、认证主体、接收人变更和原消息身份，不复制答案正文。以后可按这些证据统计等待分布、跨人交接和成功接续；认证主体不证明实际操作者一定是本人，也不能仅按等待长短、转派次数或回复字数断定个人表现。分析仍须遵循原项目权限，并区分审批职责、外部依赖、AI 执行时间、非工作时间和缺失证据。当前记录是可追溯的业务数据，不是防篡改的人事审计系统；本功能不自动给人贴“瓶颈”或“不干活”等标签。

## Issue 分配接收回执

协作通知会读取本机及支持远程查询的在线执行设备上的助理处理记录。查询失败时，提示会标明失败设备及原因；这表示处理记录未能加载，并不代表 Issue 执行失败。若提示版本不兼容，请更新该执行设备的 Executor，并刷新通知。其他桌面 App 设备不参与远程查询；本机记录仍通过本机执行器读取。

Issue 详情的负责人下拉控件旁用图标显示本次分配的接收情况：白色人形带勾表示**本人已读**，黑色人形带勾表示**助理已接收**；悬停可查看状态和时间。同一 Issue、同一负责人的详情刷新期间，顶部保留已显示的回执，避免中断悬停提示；切换 Issue 或负责人时不显示上一范围的回执。本人成功打开详情后记录已读；助理成功接下任务、准备处理后记录接收，无需等待执行完成。两个回执和各自时间独立保留，不会将 Issue 标为完成。通知预览、全部标为已读和后台读取不产生本人已读回执。

分配人和接收人均可查看回执，详情打开期间会自动刷新。底部分配动态中的最近一次有效分配也显示同一份回执，与顶部负责人控件同步更新，不为历史动态增加轮询。转派后回执只显示在最新分配动态上，取消分配后不再显示旧接收人的回执。转派或重新分配后重新记录；历史分配没有可靠回执时，图标提示“暂无接收记录”。云端回执同步失败会在执行器本地保留并补报，失败后逐步延长重试间隔，最长每小时一次；待发送回执最多保留 30 天。重启不会重置等待时间。本地项目回执保存在所属执行器。

Issue 状态或其他属性刷新不会重建同一次指派的回执图标或中断其悬停提示。重新指派（包括再次指派给同一个人）会立即隐藏旧回执，等待本次指派的结果。

助理接收分配时先保存本人设备上的任务绑定和接收回执，再启动执行；交给后台助理安排的事项在进入待处理队列时即记录接收。接收不代表执行成功，之后启动失败也不会撤销已接收的事实。云端上报仍检查当前分配、本人设备和任务绑定；拒绝原因写入诊断日志，不通过放宽权限补写回执。

云端分配的启动意图保存在所属执行器。偶发云端请求失败后，执行器按退避间隔自动恢复，重启后继续；已有绑定但尚未创建本地任务时，恢复同一个任务，不依赖删除绑定成功。恢复前重新核对服务、账号、当前分配、助理和设备，转派或断开项目后不执行旧分配。已被本地执行器接收的任务不会因启动补偿而重复执行；模型执行失败仍通过原任务的重试入口处理，配置错误需要人工修正。

通知尚未成功交给执行器时，桌面会退避重试，而不是将失败的投递当作已处理。执行器重启并报告云端连接未配置后，桌面按当前登录态重新配置连接和连接器授权；普通网络断连仍由执行器原有的重连机制处理。

## 日历安排与项目负责人

### 项目负责人对话和自动处理

<a id="project-lead-controls"></a>

打开 **设置 → 通用 → 实验性功能** 后，在协作项目中使用 **负责人对话**。这是现有协作小组负责人的条件入口，不是旧版独立“项目 AI 管理者”页面。

| 操作             | 步骤与边界                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------------------ |
| 选择小组和设备   | 打开负责人对话，选择当前项目协作小组及设备；没有小组时点设置小组与负责人                         |
| 与负责人沟通     | 智能体负责人可在私人输入框讨论目标与进展；人工负责人按提示回到原 Issue 协作                      |
| 工作列表 / 设置  | 用顶部工作列表回到具体事项，或用设置调整小组配置；具体执行仍关联原 Issue                         |
| 记忆             | 从负责人对话顶部进入记忆；此面板固定当前项目作用域，不会把私人记忆发布到项目                     |
| 发布到项目       | 顶部发布到项目 → 选择有评论权限的目标 Issue → 填写要公开的指令或结论 → 发布；成功后返回私人对话  |
| 让负责人自动处理 | 在支持的智能体负责人及设备下开启；按原项目权限和操作确认处理共享项目事件                         |
| 接管 / 停止      | 接管前核对原成员与设备并确认；原绑定停止后续派发，已开始工作保留原执行状态；停止不等于删除 Issue |
| 现在查看         | 当前由自己处理时手动触发检查，阅读处理状态或到原 Issue 补充信息；检查成功不代表所有工作完成      |

发布只共享你填写的内容，不附带私人聊天或记忆；没有可评论的 Issue 时返回项目创建或选择可访问的 Issue。等待权限检查或提交期间按钮可能不可用，不通过换设备绕过权限。

在 **我的助理 → 选择助理 → 助理详情 → 管理助理 → 连接 → 日历** 中记录事项和触发时间，支持一次或周期性触发。到时将事项交给所属助理处理，沿用助理当时的职责、设备、模型和工作目录。到期的计划无需等待连接来源的归集窗口。日历事项单独保存，返回或关闭时保护未保存的修改；运行记录可进入对应工作查看结果。

普通日历任务默认使用 Codex 全权限，高危命令和需要审核的外部 MCP 调用由 AI 审核。可在 **日历 → 操作前询问我** 开启并保存人工审批。任务在触发时读取当前策略。旧版已暂停的日历保留安排，可点击 **恢复定时交办** 后保存设置。续跑已有来源会话仍遵循该来源的权限和审批要求。助理记忆整理和周回顾使用各自的审核策略。

在对话中补充或修改已有日程时，助理先查询现有安排，再原地更新内容、名称、时间、时区或启用状态；无需取消后重建。未指定的设置、安排身份和执行历史保留。仅修改内容或名称时，保留尚未领取的原触发时间；更改时间、时区或启用状态时才重新计算。更新仍需原生确认，确认被拒绝、参数无效或版本冲突时，原安排保持不变；版本冲突后需重新读取再修改。

新建周期安排默认使用当前设备时区，已有安排保留保存的时区。需要指定其他时区时，在编辑页展开 **频率右侧齿轮（频率设置）→ 时区**，填写 IANA 名称（例如 `America/New_York`）并保存。任务侧边栏的 **已安排 → 对应任务** 也使用同一入口。**仅一次**的执行时间仍按当前设备本地时间填写。

通过对话交办未来执行时，助理应先查阅已有工作证据，或立即委派只读检查，核实实际流程、工作目录及必要输入。可以从说明和配置中查到的信息不应反复要求你填写；确实缺少业务选择时，通过问题卡确认，未解决前不创建自动执行安排。要求“走现有自动流程”不代表流程已经核实，也不能把“到时再研究怎么做”当作准备完成。

这里的“只读检查”是预查任务的行为要求，不是新增的沙箱或工具权限模式，也不保证预查任务在技术上无法写入。预查沿用既有权限契约、联网能力和工具审批规则；本轮仅约束调度决策，不扩大或收紧已有权限。

执行方案应写入日程说明，保留原要求，不擅自改成提醒。明确要求提醒时，只需确认提醒内容和时间，不需要检查被提醒事项的执行流程。创建成功仅表示安排已保存，不保证指定时间前完成，也不提前批准发布等外部操作；执行时仍需遵循原生权限、审批和必要条件检查。

任务侧边栏的 **已安排**是独立功能，保留原有的目标、运行任务、模型和执行环境设置，无需开启实验性功能。它与连接日历分别管理各自的列表、编辑和运行记录。助理工作列表展示具体工作。

项目页面中的负责人就是原协作小组负责人。对话顶部展示小组与负责人姓名，设置仍使用原小组配置。“自动处理项目事件”是在选定设备上启用该负责人的持续处理能力；每个项目与小组只有一个有效成员／设备绑定，切换必须显式接管。私人聊天与记忆仅自己可见，明确发布后才进入所选 Issue。

## 连接 GitHub 和 GitLab

助理可接收个人事件或仓库全部可订阅事件。插件提供能力，助理设置决定如何处理。仓库 Webhook 由云端暂存，执行设备离线期间不运行；外部写入保留逐次原生确认。详见 [GitHub 与 GitLab 连接](git-connections.md)。

<a id="assistant-settings-recovery"></a>

**设置失败与重试**：执行环境读取失败时，在错误提示旁点击 **重新加载**，只重试该设备的项目与工作区目录，保留当前设置草稿。保存失败后重新加载已保存的配置，会先询问是否放弃未保存修改；选择 **继续编辑** 保留输入，确认放弃后才读取已保存配置。 模型目录加载状态显示在“模型”字段下方；加载失败时点击该处的 **重新加载**，保留已选择的模型和当前草稿。保存期间，默认助理与助理设置的保存按钮显示 **保存中**。

## 首次使用助理

打开 **我的助理** 后，先进入助理首页。首页提供钉钉客服、开发助理、每天检查未完成事项、本地知识整理和每周 AI 会话复盘。点 **更多模板** 可按用途查找其他示例，包括用只读检查分析当前电脑的硬盘空间。选中模板可预览完整请求，再点 **填入对话草稿**。已有可用模型时直接进入默认助理的对话，提示词填入输入框，由你编辑并发送。缺少可用模型时，按提示选择执行设备和聊天模型。点 **高级模式** 可手动设置设备、模型和应用连接。

发送模板后，助理会在对话中核对所需材料和范围。每日检查使用你选定的邮箱和钉钉会话，运行时会重新校验来源是否仍可读取。知识助理只读取你为这项安排选定的会话，并将结果写到选定的本地项目目录。你可以在「已安排」里立即试跑。

如需指定协作项目，在连接页点 **添加接收范围 → 项目和独立事项**，再搜索并勾选项目。在范围详情中展开 **任务标签**，可分别筛选每个指定项目、我参与的事项和独立事项。如果接收全部项目，可为全部项目设置一组标签。新添加的范围默认接收任意标签。点击列表中某条范围的 **移除** 可从草稿删除该项。

配置邮箱时，登录用户名默认使用邮箱地址。服务商要求其他用户名时，点击 **使用不同的登录用户名**。

顶部可在默认助理和你添加的助理之间切换。在 **助理详情** 查看运行状态，在 **管理助理 → 连接** 查看或修改当前身份接收工作的范围。

首次初始化后，顶部显示 **默认助理** 和 **添加助理**。添加后，顶部显示你为助理起的名字。

在助理设置首页打开某个连接，进入接收范围列表。打开已有范围或添加新范围，在详情页点 **保存接收范围** 后回到该列表。返回助理设置首页后，可以选择模型并点 **开始聊天**。关闭引导时，如果有尚未保存的修改，页面会询问是否放弃。需要授权的应用会引导你登录账号。

在会话顶部点 **助理首页** 可随时返回，原会话的草稿会保留。输入框上方的 **对话模板** 可以把示例填入当前会话。钉钉客服模板会与你核对账号、群、执行设备和本地手册，并在对话内展示接收范围和处理规则供你确认。手册能明确回答的问题可按确认的规则在群里回复，一时无法确认的问题会连同拟回复私下交给你。

每周复盘可以在对话中交办，或通过 **助理设置 → 连接 → 日历** 的模板创建。默认时间为每周一北京时间 09:00，回顾本设备上此前七天的工作与对话。可以编辑、暂停或删除，删除后不会自动恢复。
