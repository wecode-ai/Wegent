# 设置与数据

打开 **左下角账户菜单 → 设置** 后，在左侧按分组选择页面。完整入口、显示条件和找不到按钮时的检查步骤见[界面导航与功能位置](./interface-navigation.md)。

## 常用设置

- **通用**：界面语言、启动时是否显示窗口、进入主界面时默认激活的顶部标签页、关闭窗口后是否后台运行，以及从 Codex 或 Claude Code 导入内容。
- **外观**：主题和工作台背景。背景图片及显示参数保存在当前设备。
- **模型**：本机 Codex 登录、本地兼容模型，以及由 Wegent 云端配置并同步到 Wework 的模型。
- **代理**：分别配置本机和云端设备的模型访问代理。
- **编码 → 编码工具**：检测并配置可从桌面工作台直接启动的 OpenCode、Claude Code 和 Kimi Code（实验性功能）。
- **上下文**：管理任务上下文偏好、Codex 个性和默认分身监督原则。
- **快捷短语**：保存经常使用的任务说明。
- **键盘快捷键**：查看、修改或清除本机快捷键。
- **工作树**：设置 Worktree 根目录、自动清理和保留数量。
- **已归档 → 已归档任务**：搜索、恢复或删除历史会话。

固定标签页中的启动项只在主界面从首页启动时生效。通过明确地址或恢复待处理页进入后，后续点击“新建任务”会正常打开任务输入界面，不会再次切换到启动标签。

任务对话输入框旁的上下文指示器会显示当前模型的上下文使用比例。比例按可用于输入的
上下文计算，即模型的最大上下文减去已配置的最大输出；上游把补全预算和输入记在同一个
窗口内，因此这个比例达到 100% 时上下文已无法继续增长。圆环的已用部分和
剩余轨道会随浅色或深色主题自动调整对比度；达到上下文压缩阈值后，指示器会切换为
警示色，并在压缩可用时提供压缩入口。

权限模式入口以当前模式对应的图标显示在输入框左侧工具区，位于快捷短语右边；悬停图标可以查看当前模式，
点击后可以切换“只读”“工作区”和“完整访问”。发送前选择项目空间时，输入区胶囊只显示
看板名称，悬停仍会说明发送后会在该看板创建任务。

在 **设置 → 通用 → 通用** 中，可以选择 Wework 的功能模式：

- **专注模式**：隐藏代码托管和工作树入口，并关闭 Wework 内置 Git 插件，适合不需要
  本地代码开发能力的工作。
- **开发者模式**：启用 Wework 内置 Git 插件并显示完整编码入口。这是默认模式。

模式偏好保存在当前设备。切换模式时 Wework 会自动重启受管 Core DSH 运行时，使插件状态
立即生效；Git 插件的启停由模式统一管理，不能在插件管理页单独修改。

## 通用设置逐项操作

<a id="settings-controls"></a>

<!-- ui-source: src/components/settings/RuntimeConcurrencySettings.tsx -->

从 **左下角账户菜单 → 设置 → 个人 → 通用** 进入。页面按基础配置、运行、AI 辅助、隐私和弹出窗口组织；多数开关选中后立即保存，失败时查看页内提示。

首次使用和隐私设置中拒绝数据收集会立即生效；开启收集以保存成功的全局设置为准，其他窗口保存的拒绝同样有效。保存失败不会阻止使用工作台；尚未保存的选择在下次启动时会回到已保存的偏好，或再次询问。稍后的明确选择优先，较早请求的延迟完成不会重新开启已拒绝的数据收集。

| 功能点                     | 操作与结果                                                                | 条件或注意事项                                                                       |
| -------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 模式                       | 点击专注模式或开发者模式，再确认切换                                      | 会重启受管插件运行时；专注模式隐藏 Git 入口                                          |

| 实验性功能                 | 开启后再查看带实验标识的功能                                              | 不代表授权外部账号，也不解除系统权限限制                                             |

| 任务运行时阻止电脑休眠     | 开启运行期间的防休眠                                                      | 不等于电脑关机、断网后仍能执行                                                       |
| 记录性能数据               | 开启后复现卡顿，再通过问题反馈导出诊断                                    | 采样与保留规则见本节下方                                                             |
| 托盘显示内容               | 分别选择未读任务、进行中任务、Codex 额度和云端额度                        | 本地 Codex 订阅关闭时不显示 Codex 额度选项；云端额度名称可由服务端配置               |
| 使用友好标题               | 开启后选择跟随任务模型或指定模型                                          | 异步生成标题；不会覆盖用户手动改名                                                   |
| 帮助改进 Wework            | 在隐私分组切换数据收集偏好，并阅读页面说明                                | 不要将该开关与问题反馈的主动日志导出混淆                                             |
| 弹出窗口快捷键             | 点击编辑，录入组合键；点击清除移除绑定                                    | 配置的是唤起 Wework 弹窗，不是任务发送快捷键                                         |
| 系统拖拽面板               | 在弹出窗口分组切换该开关                                                  | 按设备和系统提供的能力显示                                                           |

### 系统拖拽面板与暂存区

<a id="system-drag-controls"></a>

1. 在 **设置 → 个人 → 通用 → 弹出窗口 → 系统拖拽面板** 开启功能。
2. 在 Wework 内选中文字，或从支持工作区路径拖拽的文件位置开始拖动；面板出现后移到目标区域松手。不要据此假定任意外部应用拖拽都能唤起面板。
3. **创建新对话** 将内容填入新草稿；**追问** 附加到当前对话，只在当前对话存在时显示。两者均需回到输入区检查后发送，不自动提交消息。
4. **临时暂存** 把文字及附件路径存为快捷短语暂存项。回到输入区打开快捷短语菜单的 **暂存区**，悬停预览、选择插入，或删除单项/清空。清空暂存项不删除原始文件；原文件被移动或删除后，附件路径可能不可用。
5. 用面板关闭按钮或 Esc 放弃此次拖拽；出现添加失败提示时检查目标和错误，不把提示消失当成已发送。

### 开关与运行参数的区别

更改界面开关、任务调度上限和执行文件的生效方式不同。运行中任务的发送策略见[与 AI 协作](./tasks.md)；Node.js 或编码工具要求重启时，应按页面提示完成，不要将“已保存”理解为所有旧进程已更新。

## 记录性能数据

在 **设置 → 通用 → 运行** 中打开 **记录性能数据**，可以为电脑卡顿保留资源占用记录。
开关默认关闭；开启后立即开始采样，此后每轮采样完成约 5 秒后继续，记录整机 CPU、内存、
交换区及 Wework、执行器和子进程的资源占用。偏好保存在当前设备，重启 Wework 后继续生效；
关闭开关会停止记录，已有日志仍保留。

性能日志仅保存在本机，单个文件最多 5 MiB，保留当前文件和 3 个轮转文件，总上限为 20 MiB，
并受[自动存储清理](#自动存储清理)的日志保留策略约束。出现卡顿后，记下发生时间，打开
**问题反馈**，勾选包含 **运行日志** 的标准诊断，预览后选择 **确认导出**。导出的性能日志
可用于对照卡顿时间分析整机压力与各进程占用变化。

## 归档会话与工作树清理

<!-- ui-source: src/components/settings/ArchivedConversationsSettingsPage.tsx -->
<!-- ui-source: src/components/settings/WorktreesSettingsPage.tsx -->

1. 打开 **设置 → 已归档 → 已归档任务**，按标题搜索并找到会话。
2. 需要继续工作时选择恢复；不再需要时选择删除，并检查确认提示。删除与归档不同，会触发设备上的后台回收。
3. 打开 **设置 → 编码 → 工作树**，先选择设备，再检查对应仓库的工作树和关联任务。

| 工作树功能点     | 操作与影响                                                                     |
| ---------------- | ------------------------------------------------------------------------------ |
| 工作树根目录     | 修改输入框后移开焦点保存；不是移动原代码仓库的入口                             |
| 自动删除旧工作树 | 打开自动清理；关闭时阅读保留/停用确认                                          |
| 自动删除限制     | 设置保留数量后按 Enter 或移开焦点保存；仍只回收符合清理条件的工作树            |
| 刷新、删除与恢复 | 刷新所属设备的数据；按工作树记录上的操作删除或恢复，先检查关联任务及未提交改动 |

在 **设置 → 已归档 → 已归档任务** 删除会话时，Wework 先受理请求，再由所属设备在后台删除会话
文件和不再被其他任务引用的托管工作树。列表中的任务消失不代表磁盘回收已经完成。

后台清理失败时，工作台会显示错误提示，归档页会保留具体原因并重新显示任务，便于修复后
重试。失败时不会丢弃工作树管理记录。应用重启后，会继续处理已受理但尚未完成的清理。
**设置 → 工作树** 也会显示失败记录及其错误信息。

有效工作树可以独立于创建它的源目录存在；删除源目录不会阻止回收该工作树。若工作树的
Git 元数据损坏或无法确认仓库身份，清理会保留目录并报告原因，需要修复后重试。

## 本地设备代理

<!-- ui-source: src/components/settings/ProxySettingsPage.tsx -->

操作顺序：打开 **设置 → 个人 → 代理**，先区分本地设备卡片与云端设备卡片，再选择模式或修改代理地址，点击该卡片的保存。保存本地配置不会更新云端设备；云端设备操作需要连接及对应权限。

在 **设置 → 代理** 中，本地设备代理提供三种模式：

- **跟随系统**：按系统代理或 PAC 配置连接。如果当前地址没有使用系统代理，页面显示
  **直连（系统未使用代理）**。
- **强制直连**：忽略系统代理，直接连接目标服务。
- **自定义代理**：使用用户填写的 HTTP、HTTPS 或 SOCKS5 代理地址。

顶部状态展示已保存的代理模式，**当前连接**展示该模式实际使用的连接方式。保存修改后，
按页面提示重启 Codex；正在运行的任务不会被立即中断，新对话会使用新的网络设置。本地
设备代理只保存在当前设备，不会同步到云端。

## Node.js 执行环境

<!-- ui-source: src/components/settings/ExecutionEnvironmentsSettingsPage.tsx -->

在 **设置 → 编码 → 执行环境** 打开环境卡片：查看版本、可执行文件路径及准备状态；Node.js 卡片可选择自定义执行文件或恢复内置版本，Python 卡片可刷新检测。失败时先阅读卡片错误，不要把设置页的环境准备与项目空间的仓库初始化混为一谈。

Wework 桌面端默认使用 Electron Helper 自带的 Node.js 运行 DSH、Skills、MCP 和本地执行器
子进程，不再随安装包附带一份独立 Node.js。macOS 上这些后台进程复用 Helper 的应用身份，
不会因为新建对话或执行 Skill 而在 Dock 中显示额外的 Node 或 Wework 图标。

在 **设置 → 执行环境** 中可以查看当前 Node.js 的版本和路径。默认项显示为
**Electron 内置**；如需使用特定版本，可以选择本机已有的 Node.js 可执行文件，界面会将其
标记为 **自定义**。切换执行文件或恢复内置 Node.js 后需要重启 Wework，新的 DSH、Skills、
MCP 和任务进程才会使用更新后的环境。

## 查看应用信息

### 升级后的版本提示与更新日志

升级后若左侧栏出现版本提示卡，点击卡片的版本/新功能入口可打开 **Wework 更新日志**，阅读该版本说明和链接；用窗口关闭按钮、Esc 或外侧遮罩返回。卡片上的关闭只收起提示，不卸载更新、不回滚版本，也不代替检查更新。

### 账户菜单的额度查询

打开 **左下角账户菜单**，展开 **Codex 剩余额度** 或云端额度行，查看周期与使用状态；加载失败时查看错误后重试。本地 Codex 订阅关闭时不显示其额度入口，云端额度行名称可由服务端配置。这里查看的是额度，不是模型选择器，也不是托盘显示内容开关。

<!-- ui-source: src/components/settings/AboutSettingsPage.tsx -->

在 **设置 → 个人 → 关于** 可切换 **自动更新** 和 **接收 Beta 版本更新**。Beta 开关决定是否接收预发布更新，不代表当前版本立即切换；实际版本以关于页显示为准。更新、重启和诊断导出仍需经过各自的确认流程。

点击 Wework 左下角的账户菜单，选择 **关于**，即可查看当前应用名称、版本号、更新渠道和项目链接。
关于页面的版本号从运行中的 Electron 应用包元数据读取，因此会与 macOS 系统菜单
**关于 Wework** 显示相同的版本。发布构建通过 Electron 配置注入版本时，两处都会使用该值。
从同一菜单下载更新时，下载进度会直接显示在“检查更新”下方，不会与“关于”混在一起。
Wework 会先完成更新包下载，下载过程中不会弹出重启确认；只有下载完成、准备安装并重启时，
才会询问是否“更新并重启”。如果取消，已下载的更新会继续保留，再次点击更新入口会直接
重新打开确认弹窗，不会重复下载。启用自动更新且后台下载已经完成时，点击更新入口也会直接
进入同一个重启确认流程。

## 本地运行工具

<!-- ui-source: src/components/settings/HarnessSettingsPage.tsx -->

桌面端可以把已安装的 OpenCode、Claude Code 或 Kimi Code 作为本地运行工具直接启动。在
**设置 → 编码 → 编码工具** 中可以：

- 启用或隐藏某个工具。只有已启用且检测成功的工具才会出现在新对话的运行工具选择器中。
- 留空可执行文件路径，让 Wework 从当前进程的 `PATH` 和工具的常见安装目录中检测；也可以填写绝对路径。
- 按每行一个参数的方式配置默认参数。Wework 不经过 shell 解析，并会按照工具协议追加本次输入的提示词。
- 按每行一个 `NAME=VALUE` 配置启动环境变量。这些设置只保存在当前设备。
- 为 Claude Code 选择默认、计划模式或跳过权限确认模式。跳过权限确认会传入
  `--dangerously-skip-permissions`，只应在已经理解其风险的受控环境中使用。

在本地项目或开发工作树中输入任务后，打开输入区的运行工具选择器即可启动工具。Wework 按各工具
的命令行协议传入完整提示词，并在当前工作区中通过本地 PTY 运行进程。终端显示在工作台中央，
支持键盘输入和窗口尺寸同步；标题栏、右侧工作区和底部面板仍可使用。可以从右侧或底部面板的
新增入口创建同一工作区的更多运行工具会话，新增入口先打开工具选择器，不会直接铺开所有工具。
从右侧工作区创建的会话会直接成为右侧标签页，不会替换中央主会话；从底部面板创建时仍按中央
附加会话处理。创建弹窗会同时选择运行工具和本次会话使用的模型，确认“创建会话”后才启动。
主会话只能切换，不能从面板关闭；附加会话可以显式关闭。

Kimi Code 以交互 TUI 启动。Wework 在终端附着时通过 bracketed paste 注入首条任务，不使用
执行完成后会退出的 `--prompt` 单次运行模式，因此首轮完成后仍可在同一个终端里继续对话。

会话元数据、所选模型、插件来源、工作区和工具原生会话标识保存在当前设备。刷新主 WebView 或
重启 Wework 后，会话仍保留在所属项目下；重新打开时，OpenCode、Claude Code 和 Kimi Code
分别使用其原生继续/恢复能力接回历史上下文，并恢复有限的终端回滚内容。显式关闭会话会终止进程
并删除该会话记录，已经显式关闭的会话不会在下次启动时恢复。

恢复会话时，Wework 严格使用创建会话时记录的原工作区。如果该目录或临时工作树已被清理，
Wework 不会改用其他目录启动会话，而会明确提示原工作区不存在。请先恢复原工作区，或在当前
工作区中新建运行工具会话。

选择 OpenCode、Claude Code 或 Kimi Code 后，普通 Codex 模型选择器会切换为运行工具模型选择器。
默认项是“不指定模型”：Wework 不传入 `--model`、模型代理地址或模型凭证，由工具读取
自己的原生配置。也可以显式选择“设置 → 模型”中的本地模型接口，或当前已连接 Wegent 账号可访问的
公共、个人和群组模型；该选择会持久化到对应运行工具，并替换默认参数里的 `--model` 或 `-m`。
从右侧或底部面板新建附加会话时，弹窗会带出该默认值，但弹窗中的模型调整只作用于本次新会话，
不会改写运行工具的持久化默认模型。

只有显式选择 Wework 模型时，运行工具才连接 executor 暴露在回环地址上的 Anthropic Messages
兼容路由。此时工具进程只收到固定的本地模型别名和无权限的占位凭证；真实 provider 凭证、云端
登录 token、模型资源身份和本地 HTTP/SOCKS 代理配置都保留在 executor 中。executor 按选中模型
把 Messages 请求平级转换到 Anthropic Messages、OpenAI Responses 或 OpenAI Chat Completions，
上游为 Anthropic Messages 时保留原始请求和响应字段。关闭或退出运行工具会注销对应路由，异常
遗留路由会在空闲超时后回收。

运行工具属于实验性功能；Codex 本身不显示实验性标记。OpenCode、Claude Code 和 Kimi Code
会加载当前 Wework 插件提供的 Agent Plugins 标准 Skill 与 MCP Server，并自动连接
`wework_browser` MCP Server，以便通过受控工具操作 Wework 内置浏览器。插件的数据目录按插件
隔离并在会话恢复时复用；运行工具不会获得 Codex 专属的侧边对话流程。

## 模型可用状态

模型的添加、编辑、测试、视觉代理与 Catalog 入口见[模型设置](./user-guide/model-settings.md#model-controls)。

“我的 CodeX”只展示当前设备已经通过 `auth.json` 配置的官方 Codex 模型。缺少

## 修改 Codex 模型 Catalog

在 **设置 → 模型 → Codex 模型** 中展开模型提供商，可以为当前列表中的 GPT/Codex 模型
选择 **编辑 Catalog**。编辑器使用结构化表单维护最大上下文、说明、推理等级、默认推理等级、
并行工具调用、输入类型、基础提示词和高级模型能力；模型标识和提供商不可修改，也不能在这里
新增、删除或调整模型顺序。

修改只保存在当前设备的 Executor Home 中。executor 只记录与当前基础 Catalog 不同的字段，
并按“上游 Catalog → Wework 内置配置 → 用户覆盖 → 视觉代理派生”的顺序生成最终 Catalog。
因此 Codex 或 Wework 更新未修改的字段时，用户没有覆盖的部分仍会跟随新版本。

保存后，模型显示 **已自定义**。没有任务执行时，Wework 会静默重启 Codex app-server；
存在运行中任务时，Wework 会询问是否立即重启。选择稍后重启会显示
**等待重启执行器**，直到重启完成。选择 **恢复默认** 会删除该模型的整个用户覆盖项，
重新使用当前版本提供的基础 Catalog。

## 使用友好标题

在 **设置 → 通用 → 任务运行** 中打开 **使用友好标题**，并选择一个可用模型后，Wework 会在新建任务
时异步生成简洁的中文标题。创建不会等待标题模型返回：任务先使用用户输入的原始标题创建，
标题生成完成后才替换显示名称并出现短暂扫光效果。

标题生成使用独立的轻量模型调用，不会向任务会话写入消息，也不会改变主任务的运行、完成或
失败状态。手动重命名的任务不会被之后的自动标题覆盖。生成失败时，原始标题会保留，任务仍可
正常创建和运行。

普通新建任务默认是独立会话，不会因为之前打开过项目任务而自动加入远程项目或看板。只有在
发送前明确选择项目空间，或为任务显式关联项目空间时，Wework 才会同步该任务；已关联的任务
在友好标题生成后会将更新后的标题同步到对应的本地或云端看板。

## 自定义 Codex 模型

在“设置 → 模型”中点击“添加模型”后，先选择提供商。Wework 内置 Kimi Coding、Kimi 开放平台、DeepSeek、GLM 和 MiniMax profile；填写对应平台的 API Key 后，可以从提供商的模型列表接口读取可用模型。连接地址、接口协议、工具模式和已知模型的上下文长度由 profile 自动填写，其中 Kimi 开放平台使用中国区 `api.moonshot.cn` 端点。MiniMax 分为“中国大陆”和“Global”两个入口，必须选择与 Token Plan Key 签发平台一致的区域；两者都使用官方 Anthropic 兼容接口，并通过 `X-Api-Key` 读取模型列表。Kimi Coding 的 K3 会自动使用内置的 Codex Catalog profile，包括 256K 上下文和默认 `low` 推理等级。

同一个提供商可以配置多个模型。模型列表中的每一项分别维护模型、显示名称、视觉代理、启用状态和连接测试，共用提供商级的 API Key、分组和技术配置。点击“增加模型”时，Wework 会自动刷新该提供商的可用模型并新增一项，不需要先点击“获取模型”；“获取模型”只用于手动刷新列表。每个模型项的“测试”按钮只测试该项选择的模型，保存后各模型会作为独立选项出现在模型选择器中。

本机自定义接口和云端 Responses 模型默认使用普通 function 工具转换，不依赖提供商 profile ID 或模型名称；缺少工具配置字段的旧配置同样生效。只有显式选择原生 custom 工具、原生 namespace/工具搜索或完整透传时才保留对应原生协议。

Responses 连接测试同时检查工具调用参数；参数缺失、JSON 格式错误或不符合探测要求时会显示失败，可以在原窗口重试。

DeepSeek profile 使用原生 Responses API，展示当前可用于 Codex 的 `deepseek-v4-flash` 和 `deepseek-v4-pro`。两者均使用 1,048,576 tokens 上下文、默认 `high` 推理等级和实时 Web Search。DeepSeek 仅接受名为 `apply_patch` 的 custom tool，因此 Wework 保留 Code Mode，在接口边界将 `exec` 和 freeform 工具转换为 function tool，并将返回结果还原为原生工具调用；连接测试验证 function tool 调用。未显式选择原生工具的已有配置使用同一通用适配，无需重新添加模型；旧版由 Wework 管理的 Chat Completions 配置仍会迁移到 Responses API。当前模型目录声明文本输入且关闭图片生成，因此图片生成和图片理解不会在该 profile 下显示为可用能力。

文本模型可以显式引用另一个明确声明图片输入能力的模型作为“视觉代理模型”。本地模型的引用在 Wework 本地模型设置中维护；云端模型的引用必须在 Wegent Web 管理端配置，Wework 只读取 Backend 下发的 `visionSidecarModel` 引用，不提供云端模型编辑入口，也不会自动选择默认视觉模型。执行时，Wework 在请求主模型前调用视觉模型描述每张图片，再用描述文本替换 `input_image`。配置视觉代理后，executor 从当前基础 catalog 通用派生视觉 catalog，因此任意文本模型都会保留自身的推理、工具、上下文和压缩能力；未配置引用时模型保持纯文本且不会产生额外模型调用。原始图片只发送给视觉模型，不发送给文本主模型。视觉代理支持 OpenAI Responses、OpenAI Chat Completions 和 Anthropic Messages 接口；单轮最多处理 8 个不同图片描述，单张图片最大 20 MB，描述失败时会插入明确的错误文本。远程视觉接口必须使用 HTTPS；仅 `localhost` 和回环 IP 可使用 HTTP，且视觉请求不会跟随重定向，避免凭证被发送到未授权的后续地址。

每个自定义模型都可以设置可选的“分组”，模型选择器会使用该名称组织模型。Kimi Coding 默认填写“Kimi”，用户可以修改或清空；未设置分组的模型统一显示在“自定义模型”下。

选择“完全自定义”可以配置兼容 OpenAI Responses、Chat Completions 或 Anthropic Messages 的接口。模型能力使用结构化表单维护，不需要编辑 Catalog JSON：

- 最大上下文同时用于运行时和 Catalog，不需要重复填写。
- 推理等级、输入类型和布尔能力通过预设选项或复选框配置。
- 基础提示词默认参考 Codex 的 GPT profile，并可单独展开编辑。
- 不常用字段在“高级模型能力”对话框中按“响应与工具”“Catalog 元数据”“提示词模板”分类配置。

自定义 Catalog 由当前设备上的同一个 Codex app-server 读取。保存模型时，如果没有任务执行，Wework 会静默重启 Codex app-server；如果有任务正在执行，则询问是否立即重启。选择稍后重启时，模型显示“等待重启执行器”，并且在重启完成前不会出现在模型选择器中。

## 自动存储清理

Wework 会在后台维护自己创建的可再生成数据，不需要用户手动点击清理：

- 托管工作树默认位于 Executor Home 的 `workspace/worktrees`。启用“自动删除旧工作树”后，系统保留设置中的最新数量，只选择已经归档任务关联的旧工作树；删除前先创建 Git 快照，因此之后仍可恢复。
- 任务运行不会暂停全局清理。系统一次只处理一个工作树，每批间隔 30 秒，并避开正在运行任务使用的工作树、最近更新的工作树以及与运行任务属于同一 Git 仓库的工作树。
- 反馈暂存文件和内置浏览器截图超过 24 小时后可被清理；Wework 日志超过 14 天后可被清理。桌面端启动 5 分钟后开始检查，此后每 30 分钟检查一次，每个目录每轮最多删除 20 个文件。
- 开发版隔离运行目录超过 14 天后可被清理。每个运行中的实例通过文件锁保护自己的目录；维护任务只删除已经停止的实例，每轮最多删除两个实例目录。

临时文件和日志清理只处理 Wework 已知目录的直属普通文件。隔离运行目录清理只处理 `app-runtime` 下名称合法、已经停止的直属实例目录。删除目标必须是已经展开的绝对路径；包含环境变量占位符、以 `~` 开头、包含父目录跳转或符号链接的路径会被拒绝，当前进程日志和所有活跃实例也不会被删除。单个目标校验或删除失败时会被跳过，不会阻塞任务或其他清理目录。
