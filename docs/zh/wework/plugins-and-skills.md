# 插件与 Skills

Skill 为 AI 提供特定任务的操作说明和资源；插件可以组合 Skills、命令、工具和应用入口。

## 查询 Wework 文档

**Wework Docs** 随应用内置并默认安装，无需单独下载或授权。你可以直接询问“Wework 怎么配置模型”“项目和工作区有什么区别”或“内置浏览器怎么用”，AI 会按需使用 `wework-docs` Skill 查询随版本提供的文档；也可以在对话中明确指定该 Skill。

该技能包含同版本的中英文 Wework 文档，离线时也能读取，并在回答中引用文档来源。文档说明产品用法；当前对话能否执行操作仍取决于已提供的工具、设备和权限。查询最新发布信息或账号可用范围时，需要另行核实。

也可以问“代理设置在哪”“怎么打开终端”“为什么找不到工作树”。技能会先查[界面导航与功能位置](./interface-navigation.md)，给出起始区域、点击路径和入口显示条件。

## 使用插件

### 本机安装与其他设备同步

在支持本机执行且账号已启用这项能力的版本中，登录账号并保持网络与本机运行时可用后，即使当前设备尚未连接到云端，也可以安装、卸载、更新插件，以及使用刷新/修复检查本机安装。其他云设备会在后台分别同步，其离线或同步失败不会阻止本机完成。旧版本仍按原来的连接条件操作。

出现“已安装，可在插件详情中完成授权”时，表示插件包已经安装；需要登录的应用仍须在插件详情完成连接后使用。刷新不会替你授权或切换账号。中断后可重新打开插件页并刷新，恢复尚未完成的本机操作。

### 插件页逐项操作

| 想做什么             | 具体界面操作                                             | 生效条件或边界                                           |
| -------------------- | -------------------------------------------------------- | -------------------------------------------------------- |
| 查找和安装           | 左侧栏 → 插件 → 搜索或筛选来源 → 插件详情 → 安装         | 非官方插件先阅读信任确认，取消则不安装                   |
| 试用任务             | 插件详情 → 示例任务 / 立即对话 → 检查输入框后发送        | 填入示例不等于发送或授权                                 |
| 授权应用             | 插件详情 → 应用授权 → 对应应用 → 完成原生登录 → 返回验证 | 各应用、账号和执行设备分别授权                           |
| 启停与卸载           | 插件管理列表 → 对应插件操作                              | 停用保留安装记录；卸载不等于删除已创建内容               |
| 导入 ZIP             | 插件 → 创建 → 导入插件 → 选文件 → 检查预览 → 确认安装    | 标准 ZIP 格式与信任要求见下文                            |
| 分享、继续编辑和删除 | 个人插件详情 → 分享或 … 菜单                             | 以所有权、发布状态和当前版本支持为准，见下文实现状态说明 |
| Codex 在线连接器     | 设置 → 集成 → 插件 → 加载在线连接器                      | Codex 运行配置；不能代替应用登录或插件安装               |

查看安装状态异常时，使用管理页的刷新/修复入口并阅读错误；不要通过反复卸载重装掩盖登录、设备离线或权限问题。

在 **左侧栏 → 插件**，可以浏览已安装插件、查看能力并进入管理页面。启用插件后，新任务可以使用插件提供的能力。

安装插件前，建议查看它包含的工具和权限，确认来源可信并符合当前工作区的数据要求。

安装企业内部、个人创建或外部市场中的非官方插件，以及公开可见的社区投稿时，安装确认窗口会提醒：插件可能执行代码、访问本机文件或向外部服务发送数据。公开可见不代表官方来源。请确认来源可信后再安装；默认焦点位于 **取消**，也可以按 Escape 关闭。未安装插件的试用任务同样需要先确认，确认安装后才会把示例带入新对话。OpenAI 官方和 Wework 官方插件保持原有安装流程。导入个人 ZIP 插件时，预览窗口也会显示非官方来源提醒。

### 对话选择器与应用授权

插件市场、管理插件和聊天选择器共用当前账号、设备的已安装插件清单。聊天选择器保留全部已安装且启用的插件，列表高度固定时可以滚动或搜索；尚未授权的插件仍可选择，不会因为缺少登录态而隐藏。停用插件后，它仍保留在管理列表，但不再出现在新对话的选择器中。

在插件详情的 **应用授权** 中管理对应应用的连接，不能用一个应用的授权替代另一个应用。GitHub 使用执行设备上的 GitHub CLI（`gh`）：先检查现有登录，已连接时可以退出登录，未登录时才开始 GitHub 登录。凭据由该设备的 `gh` 管理；不需要授权 ChatGPT。由环境变量提供的凭据不能通过退出登录删除，需要在执行设备的配置中移除。

GitHub 插件、**设置 → 代码托管** 的 GitHub.com 检测和任务执行使用同一凭据环境。网络、权限或 CLI 执行错误会显示为检测失败，不会直接当成未登录。完成登录、退出或重新切回 Wework 后，打开的设置页和插件详情会刷新状态。设备同步管理的凭据需要通过更新 Git 账号并重新同步来修改；界面登录和退出不会写入同步目录。

设备授权时，请将卡片上的验证码输入 GitHub 授权页面并完成确认。Wework 只有取得有效设备码和 GitHub 授权地址后才提供打开浏览器入口；设备码缺失或授权提示超时会显示错误并允许重新授权。仅完成网站登录不代表 CLI 授权成功。普通 Git 提交、推送和 GitLab 操作不要求 GitHub 登录。

其他 Codex 应用使用其自身提供的授权入口。浏览器打开后，完成该应用的授权，再返回 Wework 点击 **已完成授权，验证连接**；打开浏览器本身不代表授权成功。若应用目录被拒绝、超时或不可用，Wework 会显示简短提示并保留未连接状态，不会把原始 HTML 错误页当作授权结果。

选择插件和发送消息不会预先检查登录状态。实际使用插件发现未登录或凭据失效时，Wework 根据插件返回的准确身份显示本机登录卡片；登录成功后从授权中断处继续任务。取消授权、发送新消息或切换会话后，不会自动继续旧任务，待授权状态不阻塞普通聊天。

卸载云端托管插件以账号卸载记录提交成功为准，本机清理随后异步同步。设备离线或清理失败时，后端保留待清理记录并在后续连接时继续处理，而不是让市场按钮一直等待设备响应。相关行为需要配套更新后端、桌面端和执行器；没有新增数据库迁移。

安装云端托管插件时，账号安装记录先保存，请求只等待当前设备同步，其他在线设备随后在后台同步本次变更，当前设备不会重复执行后台同步，离线设备在下次连接时补装。当前设备同步失败时，账号安装仍保留，界面显示设备待同步并可重试。重复安装已安装的插件会保留启用状态、组件选择和更新策略。支持定向同步的 Runtime 只更新本次变更的插件，保留其他插件的安装状态。设备寻址使用后端在注册时下发的记录路由标识，同一台电脑的历史设备记录不会再造成同步结果歧义。Runtime 在线期间还会按错峰的低频周期自动检查插件差异，作为通知遗漏时的兜底。

切换账号或后端后，请在当前设备完成连接注册后再安装、升级或同步插件。连接就绪前仍可查看账号插件清单和保存启停偏好，设备状态会在连接后同步。

### 刷新并修复安装状态

如果插件顶部的已安装列表与市场卡片状态不一致，或卸载后本机仍显示残留，可以点击插件页面右上角的 **刷新**。页面先刷新插件数据，再异步检查当前账号、当前设备的云端托管插件，并显示检查结果。

检查以云端安装记录为准：恢复应安装但缺失的插件内容和运行时注册，保留该设备选择的版本，并清理云端已卸载的托管残留。其他成员定向分享给你的安装副本也参与对账；你自己创建或导入的插件源文件、独立 Skills 和 MCP 不会被替换或删除。若云端仍有安装记录，刷新会恢复安装；要卸载请使用插件的 **卸载** 操作。

此功能需要配套的后端、客户端和本地执行器。离线、运行时版本不支持或插件数据未完整读取时，页面会提示无法完成检查，不会把读取失败当成空安装清单进行清理。

### 管理 Codex 插件和 Wework 插件

在 Wework 桌面端打开 **插件 → 管理插件**，可以在两个管理面板之间切换：

- **Codex 插件**：管理为 AI 提供 Skills、MCP Server、应用和命令的插件。它们由 Codex 或 Wegent 插件市场安装，并在任务和对话中使用。
- **Wework 插件**：管理直接扩展 Wework 桌面运行时能力的 DSH bundle。Wework 插件是外层交付单元，可以选择携带一个官方格式的 Codex 插件；只有其中的 Codex 能力会进入对话和任务选择器。

在 **Wework 插件** 面板中，可以输入 npm 包、Git 地址或绝对本地目录来安装插件。每次安装或更新前，原生确认窗口都会显示来源及执行风险，因为插件和依赖可能使用当前用户权限执行代码、访问文件和网络。只有选择 **允许安装** 或 **允许更新** 才开始执行；默认选中 **取消**，取消或关闭窗口不会更改插件配置。该策略同样适用于直接调用安装接口，支持任意 npm、Git 或绝对本地目录来源，确认仅对本次操作有效。用户安装的插件支持更新、启用、停用和卸载；Wework 自带的运行时插件只读展示，不能在这里修改或删除。

安装、更新、启停或卸载会先校验新的 DSH profile。校验失败时，Wework 会恢复修改前的依赖和配置，避免留下无法启动的运行时。安装和更新期间保持当前运行实例，不会提前应用尚未完成的变更。操作成功后可以继续批量管理插件，最后点击 **重启插件运行时** 统一生效。重启 Wework 后，插件的启停状态仍会保留。

启动插件开发实例前也会确认所链接的绝对源码目录。取消时不会停止已有开发实例或启动新进程；允许后，该开发会话会执行此目录的源码及后续 HMR 修改。

### 添加自定义插件市场

打开 **左侧栏 → 插件 → 创建 → 添加插件市场**。在 **来源** 输入 GitHub 简写、HTTPS/SSH Git URL 或本地目录；按需要填写 **Git 引用**（默认主分支）和 **稀疏路径**，再点击 **添加市场**。不需要限定分支或子目录时留空选填字段。

来源验证失败时按表单提示修正；取消或关闭不添加市场。添加市场只是添加插件来源，不等于安装其中全部插件；安装仍需检查插件内容、信任提示及执行设备。私有仓库访问沿用该设备的原生授权，不在来源字段粘贴访问令牌。

### 导入个人插件

在 **插件** 页面点击 **创建 → 导入插件**，可以导入符合 `wework-plugins` 规范的标准 ZIP 插件包。ZIP 根目录必须包含 `.codex-plugin/plugin.json`，Skill 和 MCP Server 也需要放在这个插件包内；加密或带密码的 ZIP 无法导入。

如果还没有可用的插件包，可以在导入窗口点击 **下载插件示例包**，基于示例补充清单、Skills 和 MCP 配置。选择 ZIP 后，Wework 会先展示插件名称、版本和包含的能力；包含可执行能力时，还需要确认信任该插件，才能完成导入和安装。包格式不正确时，导入窗口会用中文指出缺少的文件或不支持的 ZIP 类型。

### 本机托管 Python

Wework 桌面端在启动后异步检查本地已安装且启用的插件；存在 Python 适配器、命令、脚本或运行时声明时，后台准备客户端固定的 Python 3.12.12。安装或启用插件后也会检查需求，没有 Python 插件时不自动下载，已有可用环境直接复用。下载和安装不阻塞主界面及普通任务；聊天执行、授权和后台预热共享同一次准备任务。同一次应用启动中的自动准备失败后不会循环下载，用户可在提示或执行环境设置中重试。安装过程中显示真实下载进度及安装、验证阶段。解释器及启动入口保存在应用数据目录的 `managed-runtimes/python/` 中，不修改普通任务的 `PATH` 和 Python 配置。

插件包安装与 Python 准备相互独立：Python 仍在下载或准备失败时，插件包仍可安装。实际执行前由宿主选择解释器，默认等待托管环境就绪；准备失败时返回运行时错误，保留已有任务结果。可以在 **设置 → 执行环境** 查看状态并手动重试。

安装期间可以临时使用经过验证的本机 Python，但插件必须在 `.codex-plugin/plugin.json` 或 `.claude-plugin/plugin.json` 显式声明兼容的本机 Python 小版本，且不依赖额外安装的第三方库：

```json
{
  "runtimeRequirements": {
    "python": {
      "systemFallback": {
        "version": "3.12",
        "dependencies": []
      }
    }
  }
}
```

`version` 是允许临时使用的本机解释器主版本与次版本，不支持版本范围；`dependencies` 必须显式为空。宿主从自身的可执行路径中查找并实际验证解释器版本、基础标准库，以隔离模式检测，不执行插件代码。临时执行使用 `-B -E -s -S` 忽略 Python 环境变量及用户、全局 site-packages，只调整该插件子进程的解释器和路径，不安装任何依赖。聊天脚本、Python 账号适配器和直接 Python 命令可使用此能力；Shell 包装命令继续等待托管环境。缺少声明、依赖不明或校验失败的插件也继续等待。后台安装保持运行，界面说明临时使用的本机版本；已启动的进程不会切换解释器，托管环境就绪后的新调用优先使用托管 Python。

聊天中的 Codex 和 ClaudeCode 会收到宿主的插件执行规则：将插件 Skill 中的 `python`、`python3` 或 `uv` 脚本执行示例改用 `"$WEGENT_EXECUTOR_BINARY" plugin-python /插件绝对路径/scripts/example.py [脚本参数]`；PowerShell 使用 `& $env:WEGENT_EXECUTOR_BINARY plugin-python <脚本路径> <参数>`。入口检查脚本属于包含有效插件清单的包，按需准备托管 Python，并保留任务工作目录、脚本参数、输出和退出码。仅插件子进程清理 Python 环境变量并使用宿主选择的解释器，普通项目脚本继续使用原环境。此路由不拦截任意 shell 命令；安装失败后会停止本次插件执行，用户重试准备成功后可继续请求执行。

后台自动账号同步和吊销只检查托管环境是否就绪；Python 未安装时延后该连接器，后台预热或显式准备完成后再自动同步，再创建短期迁移意图或领取吊销租约；同一插件中的 Python 与非 Python 连接器也分别处理，Python 等待或准备失败不会阻断其他连接器。每轮同步或吊销最多并发执行四个提供方操作，等待环境不占用操作名额；领取操作后仍重新验证身份和插件定义。外部调用者应在 Python 就绪后创建手动迁移意图，避免其五分钟有效期消耗在下载上；等待后已过期的意图会被拒绝，需要重新发起。

托管运行时只提供共享解释器和标准库，不创建全应用共享的虚拟环境，也不自动为所有插件安装第三方库。第三方依赖由插件维护：纯 Python 依赖可以随包携带；需要独立环境的插件应固定完整依赖及校验哈希，携带适配目标系统和 CPU 架构的安装材料，并在插件私有环境中离线准备，不能向共享解释器安装依赖。这是插件交付约定，不表示现有插件都已完成迁移。

### 将收到的插件复制到个人插件

作为分享接收者打开插件详情时，若分享方允许复制，可从 **… → 复制到我的插件** 创建个人副本。操作成功后，Wework 导入副本并打开其详情；这不是复制插件名称或链接到剪贴板。按钮在复制准备期间不可用，失败会在插件页显示原因。没有该入口时，先检查自己是否为接收者、分享是否允许复制，不要把“可使用”视为“可复制”。

### 查看、分享和申请全员发布

> 实现状态（2026-08-29）：以下交互已在当前功能分支实现并通过本地验证。生产发布尚未启用，仍需完成 HTTPS、GitLab 保护规则、原生 Windows/macOS Runner 和新 Release 凭据等外部 P0；因此本节不构成已上线声明。

个人创建或导入的插件详情页保留完整的使用和管理能力：顶部提供 **分享**、**…** 和
**立即对话**；页面中可以查看说明、试试这些任务、可用范围、版本信息、自动更新、应用授权和
包含能力。点击试用任务会把示例带入对话框，但不会自动发送。个人插件所有者还可以从 **…**
选择 **继续编辑**、**卸载** 或 **删除插件**；实际显示项以当前安装状态和权限为准。

点击顶部的 **分享** 后只有两种选择：

- **指定成员或部门**：从通讯录选择成员和部门。组织本身作为通讯录的根部门选择，不另外提供
  “组织可见”。当前版本完成安全扫描后立即生效，不需要管理员审核，插件仍位于「个人创建」。
- **全员可见**：向当前企业全员发布。选择后打开右侧申请面板，依次完成 **确认版本 → 权限与风险
  → 确认提交**。提交后不会立即全员可见。

客户端会同时加载最新成员/部门 ACL 和该插件的完整发布申请状态，两者都就绪后才允许编辑与提交。任一加载失败时不会打开可操作对话框，避免用旧缓存覆盖已有分享或重复申请。

全员发布申请绑定提交时的版本和内容快照。审核期间，个人原件仍可立即对话、继续编辑并向指定
成员或部门分享；后续修改不会替换正在审核的快照。例如申请的是 v1.2.0，个人插件可以继续开发
到 v1.3.0。需要用新内容发布时，应按退回意见修改后提交新的 revision。

在插件详情页可以查看五个阶段：

1. **提交申请**：保存提交版本的不可变快照；
2. **自动检查**：检查包结构、敏感文件和风险声明；
3. **管理员审核**：企业管理员在 Web 审核后台退回或接受；
4. **代码审核**：接受后创建 GitLab MR，并完成风险、Windows 和 macOS 兼容检查；
5. **发布**：代码合入受保护的 master 后，Pipeline 发布企业版本。

管理员接受申请只会进入代码审核，不代表已经发布。普通用户无须离开 Wework 投稿或查看状态；
Web 页面只提供给管理员审核。发布成功后，个人原件继续留在「个人创建」，企业版本作为独立插件
出现在「企业内部」，两者可以有不同版本，也不会互相覆盖。

进度条会区分已完成、进行中和待进行。自动检查失败时会列出需要修复的问题；管理员退回时会
展示原因和风险项，并允许提交新的 revision；代码审核或发布失败不会影响现有企业版本。MR 合入
前可以从详情页撤回申请，进入发布后则由管理员处理企业版本。

详情页保留该个人插件的全部 Request 和 Revision 历史，可切换查看每次提交的检查证据、事件与 GitLab 状态；新申请不会覆盖旧的已发布企业版链接。

### 安装智能工作台

智能工作台目前属于实验性功能。先在 **设置 → 通用 → 实验性功能** 打开开关，顶部标签栏的 **+ → 智能工作台** 以及 **应用** 页中与 **站点**、**小程序** 并列的 **智能工作台** 标签才会出现；关闭开关会隐藏入口、关闭智能工作台标签并停止运行中的智能工作台。

从顶部标签栏的 **+ → 智能工作台** 可直接进入 **应用 → 智能工作台**；也可以先打开 **应用**，再从 **站点 / 小程序 / 智能工作台** 中切换。智能工作台下分为 **市场**、**已安装** 和 **我的创建**：市场用于发现和安装官方工作台及定向分享给自己的工作台；已安装用于绑定模型、运行和卸载本机工作台；我的创建用于创建、导入和发布工作台。

在 **我的创建** 点击 **创建智能工作台**，只需填写工作台名称；用途说明和保存位置可以留空。未指定保存位置时，Wework 会在系统“文档”目录下创建 `WeworkSmartApps/<目录标识>`；目录标识会根据名称自动生成，也可在“高级”中修改。若默认位置不可用或无写入权限，弹窗会提示选择其他目录，已填写的内容会保留。Wework 随后基于 DSH Web 预设生成一份合法的工作台目录，将它直接关联到本机列表，并打开引用“智能工作台开发助手”的新对话。创建和后续开发都使用本地设备与目录，不依赖云端连接。右侧工作区会默认打开独立的开发预览标签页，在同一行显示工作台名称、运行状态、验证结果、**验证**、**添加插件**、**刷新页面** 和 **重新加载 DSH**。验证失败时会显示首个阻断问题的错误码、文件和修复提示，也可展开查看全部问题；源文件改变后，原有验证会标记为过期。启动或重新加载期间只显示 DSH 专用进度，不会出现普通内置浏览器的 URL 空状态；文件改动后可以刷新当前页面，依赖或 DSH 配置变化后可以手动重新加载整个运行时。

工作台不是一次性生成物：无论当前是否正在运行，都可以从预览工具栏或更多操作中选择 **添加 DSH 插件**，输入 npm 包名、Git URL、压缩包地址，或选择本地插件目录。Wework 会在需要时停止工作台，更新 manifest 和插件内容，再自动重新加载；本地目录会复制到工作台的 `plugins/` 目录，因此后续导出的 ZIP 也包含该插件。选择 **开发工作台** 会让开发助手读取同一目录中的 manifest、依赖、源码与 `cordis.patch.yml` 并继续增量修改。**在文件管理器中打开** 可直接编辑目录；启动和刷新列表时 Wework 会重新校验目录内容。

已有源码目录时，点击 **关联文件夹** 可直接使用，不需要先压缩。需要分发时选择 **导出安装包**，Wework 会先要求当前源码通过验证并以匹配的内容指纹重新检查 ZIP，再生成确定性的安装包；过期或失败的验证不能导出。已有 ZIP 时仍可点击 **导入工作台**；导入后的受管目录也可以继续开发。市场下载或他人分享的工作台不能原地修改，需要先选择 **复制为我的工作台**，为副本指定新的名称和目录。删除关联工作台只会移除本机注册，不会删除外部目录。列表中的 **发布** 用于补充市场信息并选择分享的成员或部门；市场下载仍通过原生预览确认版本依赖和绑定模型。

当前 Wework 管理 DeepSeek Harness Runtime `0.1.0-rc.7` 和 `0.1.0-rc.8`。智能工作台安装包的 `plugin-manifest.json` 必须通过 `requirements.dsh` 声明兼容版本；裸版本（例如 `"dsh": "0.1.0-rc.7"`）表示精确绑定，也可以使用 SemVer 范围。启动时 Wework 会选择范围内最高的受支持版本，并只下载和缓存该版本的 Runtime；不同版本的依赖树彼此隔离。

Wework 分别管理 DeepSeek Harness Runtime 和共享 Node.js Runtime，并在启动智能工作台时禁止 Harness 把页面交给系统默认浏览器。工作台页面只会加载到 Wework 内置的原生 WebView 中。新建或关联的空白工作台会直接使用当前可用的 Wework 模型代理，不要求在 DSH 中再次填写 API Key；如果没有显式绑定模型，启动时会使用第一个可用的 Wework 模型。常驻工作台会等待模型恢复完成后再自动启动，避免 Wework 重载期间因模型列表尚未就绪而漏掉恢复。

为兼容需要跨域调用遗留服务的 DSH 页面，Wework 只在智能工作台自己的 Harness WebView 中放宽同源限制；Wework 主界面和普通内置浏览器仍使用默认网页安全策略。Windows 会为这类 WebView 使用独立的 WebView2 数据目录，清除浏览数据时会同时清理普通浏览器和智能工作台的数据。放宽同源限制会降低页面之间的隔离强度，因此只应安装并运行来源可信的智能工作台。

Wework 支持标准 DSH Release ZIP：`plugin-manifest.json` 通过 `packages` 声明各 npm 包的 `name`、`role` 和目标 `path`，ZIP 根目录包含对应的 `.tgz` 文件，其中唯一的 `profile-bundle` 路径必须与 `entry.installPackage` 一致。`entry` 只需要 `installPackage` 和 `profile`，不需要声明 `webUrl`；Wework 会在启动时分配本地地址、安装清单中的全部包，并把用户选择的 Wework 模型绑定到 profile。

从市场安装时需要选择一个 Wework 模型；从“我的创建”导入的工作台可以稍后在 **已安装** 中选择模型。这个模型只绑定到当前智能工作台，其他智能工作台可以分别选择不同模型。工作台会显示版本、绑定模型和 **已安装 / 运行中 / 启动失败** 状态；工作台停止时可以直接修改绑定模型。点击 **打开** 后，Wework 启动隔离的 Harness 实例，并播放工作台进入顶部标签栏的动效，再把智能工作台作为独立工作区标签页打开；点击 **停止** 会关闭对应标签页并回收实例。打开 **常驻** 后，Wework 每次启动主窗口时都会自动启动该工作台并打开它的标签页。

### 删除个人插件

个人创建或导入的插件可以在详情页右上角的 **…** 菜单中删除。若插件已安装，Wework 会先卸载，再删除本地插件源码。

如果插件有尚未合入 master 的全员发布申请，删除前必须先撤回申请；系统会同时关闭或标记取消
已经创建的 MR，再卸载并删除个人源码。已合入或已发布的企业版本不能由个人撤回：此时
删除只影响个人原件和它的成员/部门分享，不会删除「企业内部」的企业版本。企业版的停用、下架
或回滚由管理员处理。

对于仅分享给成员或部门、但尚未形成企业版的个人插件，删除前会检查使用情况。无人使用时可以
直接删除；仍有用户、授权或设备安装时，确认框会列出影响范围，并改为 **停用并删除**：云端将
停止分享和新安装、撤销现有授权，并通知在线设备清理插件，离线设备会在下次连接时清理。已经
开始运行的任务不会被强制中断。若确认期间使用情况发生变化，需要刷新影响范围并再次确认。

### 使用内置应用插件

#### 小程序体验链接与二维码

在 **应用 → 小程序** 列表中，体验能力可用且已有体验链接的条目提供 **查看二维码** 和复制链接操作。打开二维码供受众扫码；复制后检查成功反馈再分享。体验链接不存在或能力不可用时显示空值，不必到站点发布菜单寻找二维码。二维码生成失败时可关闭弹窗并检查链接；分享前确认接收者及小程序自身的访问限制。

#### 编辑站点信息

在 **应用 → 站点 → 对应行 … → 编辑站点** 修改标题或自定义域名前缀，检查后点击 **保存**；取消不保存。前缀会转为小写，按字段提示使用小写字母、数字和短横线；若名称冲突或保存失败，按弹窗错误修正，不要重复点击。入口依赖当前站点的编辑能力，不等于管理协作者或访问权限。

Wegent 云端市场会预先提供 `wegent-sites` 和 `weibo-miniapp-h5-develop-agent`，但不会提前安装到每个用户。打开 **应用** 后，可以在 **站点** 和 **小程序** 两个标签页中查看对应应用；点击 **创建** 并选择应用类型时，Wework 会先检查选定在线设备是否已经安装对应插件，已安装时会直接将插件引用写入新任务输入框。未安装时，Wework 会为当前账号幂等安装并同步插件到该设备。

内置应用插件属于 `visibility=workspace`，站点使用 `plugin://wegent-sites@wegent`，小程序使用 `plugin://weibo-miniapp-h5-develop-agent@wegent`，后者还会带入插件提供的创建提示。安装和同步期间，应用页会显示正在安装插件的提示；重复点击会复用当前设备上已安装的插件，不会创建重复安装记录或重复发起安装。

站点列表同时显示自己拥有的站点和作为协作者参与的站点。站点所有者可以从行末 **… → 管理协作者** 按用户名添加或移除协作者；协作者可以继续开发、编辑、发布、删除、配置环境变量和修改内网站点访问权限，但不能管理协作者。内网站点可在 **… → 访问权限** 中选择所有人免登录、登录用户、仅项目成员，或项目成员及指定成员；项目所有者和协作者始终可以访问。点击列表中的站点 URL 会使用系统外部浏览器打开。点击 **继续开发** 时，Wework 会确保目标设备已经安装 `wegent-sites`，并把插件引用和站点引用一起写入新的任务输入框，让 AI 同时获得站点工作流和目标项目上下文。

在站点行末选择 **… → 环境变量**，可以批量新增、修改或删除 `Plain` 和 `Secret` 变量。Secret 的值不会从服务端回显，已配置的 Secret 留空保存时保持不变；保存后的新版本在下一次部署时生效。静态站点会把变量注入浏览器 bundle，因此其中的 Secret 对站点访问者可见，只适合内部受众。

Wegent 市场发布和上传同时接受包含 `.codex-plugin/plugin.json` 或 `.claude-plugin/plugin.json` 的插件包。Backend 会在入库前补齐缺少的运行时清单，因此每个已安装插件都会同步到设备的 Codex 和 Claude Code 插件目录。

本地模式需要先连接 Wegent 云端。点击输入框中的插件标签会打开相应的 Wegent 云端市场详情页。

### 查询站点访问数据

<a id="site-analytics-controls"></a>

在 **左侧栏 → 应用 → 站点 → 对应站点行末 … → 查看访问数据** 打开统计窗口。只有当前站点提供该能力时才显示入口。

1. 选择开始日期和结束日期，点击 **查询**；也可以直接选择 **最近 7 天** 或 **最近 31 天**。
2. 日期按北京时间（UTC+8）计算，包含两端日期；每次最多 31 天，不能选择未来日期或倒置范围。
3. 查看 **浏览量（PV）**、**区间独立访客（UV）**、每日趋势及明细。区间 UV 独立去重，不是每日 UV 相加。
4. 包含今天时留意“今日数据尚未完整”的提示；暂无记录不等于查询失败。服务未配置时联系管理员，限流、超时或加载失败时按窗口提示重试。
5. 关闭窗口返回站点列表。统计查询不发布站点、不修改访问权限，也不代表访问者身份明细可用。

### 在本地运行工具中使用插件

实验性的 OpenCode、Claude Code 和 Kimi Code 运行工具会读取当前任务选择的 Wework 插件。
Wework 优先使用 [Agent Plugins](https://agent-plugins.org/) 标准的 `plugin.json`、`skills/`
和 `mcp.json`，并兼容现有的 Codex/Claude 插件清单。启动会话时，Wework 为所选运行工具生成
隔离的适配目录，把 Skill 和 MCP Server 转换为该工具的原生配置；插件自己的持久数据保存在
按插件隔离的数据目录中，不会按每个会话重复复制。

每个本地运行工具会话还会自动获得 `wework_browser` MCP Server 和对应 Skill。AI 必须通过这些
受控工具打开、检查和操作 Wework 内置浏览器，不会启动外部浏览器。会话重启或恢复时会继续使用
创建会话时记录的插件集合，因此重启 Wework 不会丢失插件能力。

## 在任务中使用 Skill

在输入框中输入 `/`，从列表中选择 Skill；也可以直接在任务说明中点名需要使用的 Skill。选择后，Wework 会把相应说明提供给 AI。

## 查看与启停单个 Skill

打开 **左侧栏 → 插件 → 插件详情 → 包含能力**，点击 Skill 名称查看说明和调用方式。安装且有管理权限时，可以通过能力行的开关单独启停组件，或在 Skill 详情底部选择禁用/恢复；整插件停用与组件停用不是同一操作。

Skill 已安装、启用且当前没有启动请求时，详情中的 **运行技能** 才可用。点击后按打开的任务流程检查输入并继续，不代表已获得外部服务授权。当前全局设置没有“编码 → 技能”页面；不要按旧版统一目录迁移说明寻找不存在的入口。
