# 插件与 Skills

Skill 为 AI 提供特定任务的操作说明和资源；插件可以组合 Skills、命令、工具和应用入口。

## 使用插件

在顶部或应用入口打开 **插件**，可以浏览已安装插件、查看能力并进入管理页面。启用插件后，新任务可以使用插件提供的能力。

安装插件前，建议查看它包含的工具和权限，确认来源可信并符合当前工作区的数据要求。

### 管理 Codex 插件和 Wework 插件

在 Wework 桌面端打开 **插件 → 管理插件**，可以在两个管理面板之间切换：

- **Codex 插件**：管理为 AI 提供 Skills、MCP Server、应用和命令的插件。它们由 Codex 或 Wegent 插件市场安装，并在任务和对话中使用。
- **Wework 插件**：管理直接扩展 Wework 桌面运行时能力的 DSH bundle。它们属于本机 Wework 运行时，不会作为普通 Codex 插件出现在任务选择器中。

在 **Wework 插件** 面板中，可以输入 npm 包、Git 地址或绝对本地目录来安装插件。安装前会显示信任确认，因为插件及其安装脚本以当前用户权限运行。用户安装的插件支持更新、启用、停用和卸载；Wework 自带的运行时插件只读展示，不能在这里修改或删除。

安装、更新、启停或卸载会先校验新的 DSH profile。校验失败时，Wework 会恢复修改前的依赖和配置，避免留下无法启动的运行时。操作成功后可以继续批量管理插件，最后点击 **重启插件运行时** 统一生效。重启 Wework 后，插件的启停状态仍会保留。

### 导入个人插件

在 **插件** 页面点击 **创建 → 导入插件**，可以导入符合 `wework-plugins` 规范的标准 ZIP 插件包。ZIP 根目录必须包含 `.codex-plugin/plugin.json`，Skill 和 MCP Server 也需要放在这个插件包内；加密或带密码的 ZIP 无法导入。

如果还没有可用的插件包，可以在导入窗口点击 **下载插件示例包**，基于示例补充清单、Skills 和 MCP 配置。选择 ZIP 后，Wework 会先展示插件名称、版本和包含的能力；包含可执行能力时，还需要确认信任该插件，才能完成导入和安装。包格式不正确时，导入窗口会用中文指出缺少的文件或不支持的 ZIP 类型。

### 查看、分享和申请全员发布

> 实现状态（2026-08-29）：以下交互已在当前功能分支实现并通过本地验证。生产发布尚未启用，仍需完成 HTTPS、GitLab 保护规则、原生 Windows/macOS Runner 和新 Release 凭据等外部 P0；因此本节不构成已上线声明。

个人创建或导入的插件详情页保留完整的使用和管理能力：顶部提供 **分享**、**…** 和
**立即对话**；页面中可以查看说明、试试这些任务、可用范围、版本信息、自动更新、应用授权和
包含能力。点击试用任务会把示例带入对话框，但不会自动发送。个人插件所有者还可以从 **…**
选择 **继续编辑**、**卸载** 或 **删除插件**；实际显示项以当前安装状态和权限为准。

点击顶部的 **分享** 后只有两种选择：

- **指定成员或部门**：从通讯录选择成员和部门。组织本身作为通讯录的根部门选择，不另外提供
  “组织可见”。当前版本完成安全扫描后立即生效，不需要管理员审核，插件仍位于「个人创建」。
- **全员可见**：向当前企业全员发布。选择后打开右侧申请面板，依次完成 **确认版本 → 权限与风险
  → 确认提交**。提交后不会立即全员可见。

客户端会同时加载最新成员/部门 ACL 和该插件的完整发布申请状态，两者都就绪后才允许编辑与提交。任一加载失败时不会打开可操作对话框，避免用旧缓存覆盖已有分享或重复申请。

全员发布申请绑定提交时的版本和内容快照。审核期间，个人原件仍可立即对话、继续编辑并向指定
成员或部门分享；后续修改不会替换正在审核的快照。例如申请的是 v1.2.0，个人插件可以继续开发
到 v1.3.0。需要用新内容发布时，应按退回意见修改后提交新的 revision。

在插件详情页可以查看五个阶段：

1. **提交申请**：保存提交版本的不可变快照；
2. **自动检查**：检查包结构、敏感文件和风险声明；
3. **管理员审核**：企业管理员在 Web 审核后台退回或接受；
4. **代码审核**：接受后创建 GitLab MR，并完成风险、Windows 和 macOS 兼容检查；
5. **发布**：代码合入受保护的 master 后，Pipeline 发布企业版本。

管理员接受申请只会进入代码审核，不代表已经发布。普通用户无须离开 Wework 投稿或查看状态；
Web 页面只提供给管理员审核。发布成功后，个人原件继续留在「个人创建」，企业版本作为独立插件
出现在「企业内部」，两者可以有不同版本，也不会互相覆盖。

进度条会区分已完成、进行中和待进行。自动检查失败时会列出需要修复的问题；管理员退回时会
展示原因和风险项，并允许提交新的 revision；代码审核或发布失败不会影响现有企业版本。MR 合入
前可以从详情页撤回申请，进入发布后则由管理员处理企业版本。

详情页保留该个人插件的全部 Request 和 Revision 历史，可切换查看每次提交的检查证据、事件与 GitLab 状态；新申请不会覆盖旧的已发布企业版链接。

### 安装智能工作台

智能工作台目前属于实验性功能。先在 **设置 → 通用 → 实验性功能** 打开开关，顶部标签栏的 **+ → 智能工作台** 以及 **应用** 页中与 **站点**、**小程序** 并列的 **智能工作台** 标签才会出现；关闭开关会隐藏入口、关闭智能工作台标签并停止运行中的智能工作台。

从顶部标签栏的 **+ → 智能工作台** 可直接进入 **应用 → 智能工作台**；也可以先打开 **应用**，再从 **站点 / 小程序 / 智能工作台** 中切换。智能工作台下分为 **市场**、**已安装** 和 **我的创建**：市场用于发现和安装官方工作台及定向分享给自己的工作台；已安装用于绑定模型、运行和卸载本机工作台；我的创建用于创建、导入和发布工作台。

在 **我的创建** 点击 **创建智能工作台**，填写名称和保存位置后，Wework 会基于 DSH Web 预设生成一份合法的工作台目录，将它直接关联到本机列表，并打开引用“智能工作台开发助手”的新对话。创建和后续开发都使用本地设备与目录，不依赖云端连接。右侧工作区会默认打开独立的开发预览标签页，在同一行显示工作台名称、运行状态、**添加插件**、**刷新页面** 和 **重新加载 DSH**。启动或重新加载期间只显示 DSH 专用进度，不会出现普通内置浏览器的 URL 空状态；文件改动后可以刷新当前页面，依赖或 DSH 配置变化后可以手动重新加载整个运行时。

工作台不是一次性生成物：无论当前是否正在运行，都可以从预览工具栏或更多操作中选择 **添加 DSH 插件**，输入 npm 包名、Git URL、压缩包地址，或选择本地插件目录。Wework 会在需要时停止工作台，更新 manifest 和插件内容，再自动重新加载；本地目录会复制到工作台的 `plugins/` 目录，因此后续导出的 ZIP 也包含该插件。选择 **开发工作台** 会让开发助手读取同一目录中的 manifest、依赖、源码与 `cordis.patch.yml` 并继续增量修改。**在文件管理器中打开** 可直接编辑目录；启动和刷新列表时 Wework 会重新校验目录内容。

已有源码目录时，点击 **关联文件夹** 可直接使用，不需要先压缩。需要分发时选择 **导出安装包**，Wework 会从当前目录生成确定性的 ZIP。已有 ZIP 时仍可点击 **导入工作台**；导入后的受管目录也可以继续开发。市场下载或他人分享的工作台不能原地修改，需要先选择 **复制为我的工作台**，为副本指定新的名称和目录。删除关联工作台只会移除本机注册，不会删除外部目录。列表中的 **发布** 用于补充市场信息并选择分享的成员或部门；市场下载仍通过原生预览确认版本依赖和绑定模型。

当前 Wework 管理 DeepSeek Harness Runtime `0.1.0-rc.7` 和 `0.1.0-rc.8`。智能工作台安装包的 `plugin-manifest.json` 必须通过 `requirements.dsh` 声明兼容版本；裸版本（例如 `"dsh": "0.1.0-rc.7"`）表示精确绑定，也可以使用 SemVer 范围。启动时 Wework 会选择范围内最高的受支持版本，并只下载和缓存该版本的 Runtime；不同版本的依赖树彼此隔离。

Wework 分别管理 DeepSeek Harness Runtime 和共享 Node.js Runtime，并在启动智能工作台时禁止 Harness 把页面交给系统默认浏览器。工作台页面只会加载到 Wework 内置的原生 WebView 中。新建或关联的空白工作台会直接使用当前可用的 Wework 模型代理，不要求在 DSH 中再次填写 API Key；如果没有显式绑定模型，启动时会使用第一个可用的 Wework 模型。常驻工作台会等待模型恢复完成后再自动启动，避免 Wework 重载期间因模型列表尚未就绪而漏掉恢复。

为兼容需要跨域调用遗留服务的 DSH 页面，Wework 只在智能工作台自己的 Harness WebView 中放宽同源限制；Wework 主界面和普通内置浏览器仍使用默认网页安全策略。Windows 会为这类 WebView 使用独立的 WebView2 数据目录，清除浏览数据时会同时清理普通浏览器和智能工作台的数据。放宽同源限制会降低页面之间的隔离强度，因此只应安装并运行来源可信的智能工作台。

Wework 支持标准 DSH Release ZIP：`plugin-manifest.json` 通过 `packages` 声明各 npm 包的 `name`、`role` 和目标 `path`，ZIP 根目录包含对应的 `.tgz` 文件，其中唯一的 `profile-bundle` 路径必须与 `entry.installPackage` 一致。`entry` 只需要 `installPackage` 和 `profile`，不需要声明 `webUrl`；Wework 会在启动时分配本地地址、安装清单中的全部包，并把用户选择的 Wework 模型绑定到 profile。

从市场安装时需要选择一个 Wework 模型；从“我的创建”导入的工作台可以稍后在 **已安装** 中选择模型。这个模型只绑定到当前智能工作台，其他智能工作台可以分别选择不同模型。工作台会显示版本、绑定模型和 **已安装 / 运行中 / 启动失败** 状态；工作台停止时可以直接修改绑定模型。点击 **打开** 后，Wework 启动隔离的 Harness 实例，并播放工作台进入顶部标签栏的动效，再把智能工作台作为独立工作区标签页打开；点击 **停止** 会关闭对应标签页并回收实例。打开 **常驻** 后，Wework 每次启动主窗口时都会自动启动该工作台并打开它的标签页。

### 删除个人插件

个人创建或导入的插件可以在详情页右上角的 **…** 菜单中删除。若插件已安装，Wework 会先卸载，再删除本地插件源码。

如果插件有尚未合入 master 的全员发布申请，删除前必须先撤回申请；系统会同时关闭或标记取消
已经创建的 MR，再卸载并删除个人源码。已合入或已发布的企业版本不能由个人撤回：此时
删除只影响个人原件和它的成员/部门分享，不会删除「企业内部」的企业版本。企业版的停用、下架
或回滚由管理员处理。

对于仅分享给成员或部门、但尚未形成企业版的个人插件，删除前会检查使用情况。无人使用时可以
直接删除；仍有用户、授权或设备安装时，确认框会列出影响范围，并改为 **停用并删除**：云端将
停止分享和新安装、撤销现有授权，并通知在线设备清理插件，离线设备会在下次连接时清理。已经
开始运行的任务不会被强制中断。若确认期间使用情况发生变化，需要刷新影响范围并再次确认。

### 使用内置应用插件

Wegent 云端市场会预先提供 `wegent-sites` 和 `weibo-miniapp-h5-develop-agent`，但不会提前安装到每个用户。打开 **应用** 后，可以在 **站点** 和 **小程序** 两个标签页中查看对应应用；点击 **创建** 并选择应用类型时，Wework 会先检查选定在线设备是否已经安装对应插件，已安装时会直接将插件引用写入新任务输入框。未安装时，Wework 会为当前账号幂等安装并同步插件到该设备。

内置应用插件属于 `visibility=workspace`，站点使用 `plugin://wegent-sites@wegent`，小程序使用 `plugin://weibo-miniapp-h5-develop-agent@wegent`，后者还会带入插件提供的创建提示。安装和同步期间，应用页会显示正在安装插件的提示；重复点击会复用当前设备上已安装的插件，不会创建重复安装记录或重复发起安装。

Wegent 市场发布和上传同时接受包含 `.codex-plugin/plugin.json` 或 `.claude-plugin/plugin.json` 的插件包。Backend 会在入库前补齐缺少的运行时清单，因此每个已安装插件都会同步到设备的 Codex 和 Claude Code 插件目录。

本地模式需要先连接 Wegent 云端。点击输入框中的插件标签会打开相应的 Wegent 云端市场详情页。

### 在本地运行工具中使用插件

实验性的 OpenCode、Claude Code 和 Kimi Code 运行工具会读取当前任务选择的 Wework 插件。
Wework 优先使用 [Agent Plugins](https://agent-plugins.org/) 标准的 `plugin.json`、`skills/`
和 `mcp.json`，并兼容现有的 Codex/Claude 插件清单。启动会话时，Wework 为所选运行工具生成
隔离的适配目录，把 Skill 和 MCP Server 转换为该工具的原生配置；插件自己的持久数据保存在
按插件隔离的数据目录中，不会按每个会话重复复制。

每个本地运行工具会话还会自动获得 `wework_browser` MCP Server 和对应 Skill。AI 必须通过这些
受控工具打开、检查和操作 Wework 内置浏览器，不会启动外部浏览器。会话重启或恢复时会继续使用
创建会话时记录的插件集合，因此重启 Wework 不会丢失插件能力。

## 在任务中使用 Skill

在输入框中输入 `/`，从列表中选择 Skill；也可以直接在任务说明中点名需要使用的 Skill。选择后，Wework 会把相应说明提供给 AI。

## 管理本地 Skills

在 **设置 → 编码 → 技能** 中可以查看本地 Skills。需要同时使用 Codex 和 Claude Code 时，可以启用统一管理，将两者的技能目录统一到 `~/.agents/skills`。

重名 Skill 会保留并使用来源后缀区分。迁移完成后，新任务的自动补全会显示统一目录中的 Skills。
