# 项目与工作区

项目用于把同一份代码目录下的多次任务组织在一起。每个项目可以关联一个或多个执行设备上的目录。

## 使用现有目录

本机项目选择 **使用现有目录** 后，Wework 会打开系统目录选择器。再次添加同一目录时，Wework 会复用已有项目；如果项目曾被移除，则会恢复项目及其历史会话。

在本地模式中，点击 **本地项目** 后，可以在系统目录选择器里同时选择多个目录。该入口始终使用本机执行设备，即使当前还连接了云设备或远程设备；如需选择其他设备上的目录，请使用 **云端项目**。选完目录后，创建项目弹窗会默认使用第一个源目录的文件夹名作为项目名称，你也可以修改名称或继续添加、移除源目录；确认后，Wework 会把这些目录保存为同一个 Codex 项目，并使用第一个目录作为项目列表和新任务的默认工作区。项目列表只显示一条项目记录，不会展开全部源目录。通过项目菜单中的 **编辑项目** 可以重命名项目、添加或移除源目录，以及调整主目录。该能力目前仅支持本机 Codex 项目，云端和远程项目仍按单目录添加。

如果连接的云端设备和当前 Wework 本机执行器指向同一个工作区，随后再把该目录添加为本地项目时，项目列表会把本地和云端记录合并为一条。合并以执行器身份、规范化后的工作区路径、工作区类型和 Worktree 为依据；重启 Wework 后仍保持一条项目记录，云端已有任务也会继续显示在该项目下。

从项目列表移除本机项目不会删除磁盘目录。

## 关联项目空间

开启 **设置 → 通用 → 实验性功能** 后，可以在本地项目的 **编辑项目** 对话框中设置 **自动加入项目空间**。本地项目是代码与执行工作区，项目空间是任务跟进与协作看板；两者是关联关系，不会互相替代，也不会移动或复制项目文件。

为本地项目选择项目空间后，从该项目开启的新对话会继承这个默认值。发送第一条消息前，输入框底部会显示 **加入看板 · 项目空间名称**；发送后，Wework 会在对应的本地或云端项目空间中创建任务并关联当前对话。重复同步同一对话不会创建重复看板任务。

默认项目空间是本地项目自身的设置，保存在对应设备的本地项目状态中，不需要项目空间保存反向关联。也可以在发送前通过输入框的 **+** 菜单为当前对话临时选择、切换或取消项目空间。

云端项目空间中的看板任务被另一名成员指派给你时，已连接该云端且允许系统通知的 Wework 桌面端会发送一条系统通知。重复指派给同一负责人或自己指派给自己不会重复提醒。

## 项目空间自动化

项目空间看板提供 **自动化** 页签，用于统一管理机器人成员和执行队列。

### 机器人成员

拥有项目权限的成员可以添加机器人（AI 成员），并为每个机器人配置名称、模型、系统提示词、可见范围、执行环境（本机或云端）和执行模式。指派给机器人的任务会由对应机器人自动执行。

### 执行队列

执行队列按列展示等待执行和执行中的任务：

- **我的待办**：指派给当前用户且尚未完成的任务。
- **每个机器人一列**：指派给该机器人的执行任务。

队列支持按执行状态筛选（待审批、排队、已领取、执行中、失败）和按标题搜索；执行中的任务显示旋转状态图标。设置为人工审批的机器人，任务会先进入待审批状态，审批通过后开始执行。

### 自动化规则与 AI 托管

自动化规则可以按时间表运行，也可以由新任务等项目事件或 Webhook 触发。规则支持启停、立即运行、查看运行历史和取消尚未完成的运行；时间表由服务端调度，因此不要求 Wework 客户端持续在线。

每条规则只选择一种分配方式：

- **手动选择**：固定选择一个项目机器人。规则触发后，原始看板任务立即指派给该机器人，并完整复用普通任务指派给机器人的现有执行流程。
- **AI 托管**：AI 调度员通过受限 MCP 读取原始任务，以及当前可用项目成员和项目机器人的能力说明，选择最合适的对象后直接完成指派；没有合适对象时保持未分配。调度员不会执行原始任务，也不会成为任务负责人，最终文本只作为判断记录，不参与指派。

AI 托管可以使用两种调度员来源。**自定义 AI** 选择模型和本地或云端设备，通过 Wework 的现有运行通道调用“读取任务、读取候选人、指派任务”三个 MCP 工具；**Wegent 智能体** 使用当前用户可访问且配置完整的智能体，由 Backend 创建标准 Task/Subtask，并提供同样受当前项目、任务和自动化运行约束的 MCP。选择项目机器人时，真正执行任务的是该机器人；选择项目成员时，系统只完成负责人指派。

选定机器人后，系统调用与人工指派完全相同的看板分配链。项目机器人继续使用自己的当前模型、设备、代码工作区和执行模式；本地设备离线时任务保持“排队中”，设备上线后由 Wework 领取，云端任务由 Backend 分发。执行记录不保存模型凭据，开始运行时才从机器人或调度规则的当前配置中读取。

AI 调度员的判断保存在一条独立父评论中；选中的项目机器人开始工作后，会另建自己的执行评论。只有项目机器人的完成结果才能把原始任务推进到待验收，调度员完成选择本身不会改变任务完成状态。

自动化页签仅对本地、GitHub 和 GitLab 项目空间开放；钉钉多维表格项目空间的数据在外部表格中维护，不显示该页签。

## 从输入区创建项目

在新对话输入框上方打开项目选择器，可以新建空白项目或添加现有目录。创建完成后，新项目会同时出现在左侧项目列表和输入框上方，并立即成为当前新对话的项目工作区。

如果先切换到不使用项目的普通对话，再点击左侧对应项目的 **新对话**，Wework 会创建一个新的项目对话并重新选中该项目，不会复用普通对话的输入或会话状态。

## 创建 Git 项目

1. 新建项目并选择 **Git 仓库**。
2. 选择执行设备。
3. 选择仓库和默认分支。
4. 确认项目名称和目标目录。
5. 等待克隆完成。

如果仓库列表为空，在设置中检查 Git 服务连接和 Token 权限。目标目录已存在时，请选择现有目录，或更换新项目的目标目录。

## 查看拉取请求和合并请求状态

任务使用 GitHub 或 GitLab 工作区时，环境面板会根据当前分支查询已关联的拉取请求（PR）或合并请求（MR）。请求编号和标题保持单行显示；左侧主图标用颜色区分开放、关闭等请求状态，右下角的小图标显示检查中、检查通过或检查失败。存在合并冲突时，红色冲突图标会优先于检查结果显示。GitHub PR 进入 merge queue 后，即使分支检查已经全部通过，Wework 仍显示中性的“合并队列中”等待状态，直到 PR 退出队列或完成合并。GitHub 同一个工作流检查存在多轮运行时，Wework 使用最新一轮结果，已被后续运行替代的取消或失败结果不会覆盖当前状态。点击该条目可以在浏览器中打开对应的 PR 或 MR。

查询命令在任务实际使用的执行设备和工作区中运行：GitHub 使用 `gh`，GitLab 使用 `glab`。单机使用 Wework 时由本机执行器直接运行命令，不要求额外配置云端 Git 服务连接，但需要在本机安装并登录相应 CLI：

```bash
gh auth login
glab auth login
```

可在 **设置 → 代码托管** 中查看本机 `gh` 和 `glab` 的安装、登录状态，打开安装指引或复制登录命令。该页面还提供 **显示 PR / MR 状态** 开关；关闭后 Wework 不再执行状态查询，但仍保留创建 PR/MR 的入口。Wework 只读取 CLI 返回的状态，不保存访问令牌。

如果 `glab` 配置了多个 GitLab 实例，只要至少一个实例认证成功，设置页就会显示 GitLab CLI **已就绪**；某个失效或未登录的实例不会掩盖其他可用实例。具体仓库的 MR 查询仍根据该工作区的 Git 远端选择对应的 GitLab 实例，因此仓库所属实例也必须保持有效登录。

如果当前分支还没有 PR/MR，环境面板继续显示创建入口。如果 CLI 未安装、未登录或查询暂时失败，创建入口也会保留，并显示对应的处理提示。提交并推送或仅推送后，Wework 会刷新环境信息；重新打开环境面板也会重新查询最新状态。

## 普通工作区与 Worktree

- **普通工作区**：任务直接使用项目目录，适合串行处理和小规模修改。
- **Worktree**：每个任务使用独立的 Git 工作树，适合并行开发和需要隔离分支的任务。

使用 Worktree 时，文件树、终端和内置开发工具都会打开当前任务的工作树路径。归档任务前应先提交或保存仍需保留的修改。

## 在不同设备上使用项目

同一个项目可以关联本机、云设备或远程设备上的不同目录。新建任务时选择实际存放代码的设备。复制任务到另一台设备时，需要为目标设备选择对应的项目目录。

## 从终端打开项目

macOS 桌面版会安装 `wework` 命令。可以在终端中运行：

```bash
wework .
wework /path/to/project
```

Wework 会打开指定目录；应用已经运行时会复用现有窗口。
