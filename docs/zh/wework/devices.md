# 设备与云端工作

<!-- ui-source: src/components/settings/ConnectionsSettingsPage.tsx -->

## 设备卡片逐项操作

打开 **左侧栏 → 云端工作** 查看设备；点击右上角 **连接设置** 进入 **设置 → 个人 → 云端连接**。不是项目空间内的执行环境配置。

| 功能点                | 操作路径与结果                                 | 条件与边界                                     |
| --------------------- | ---------------------------------------------- | ---------------------------------------------- |
| 连接/断开 Wegent      | 云端连接页按提示授权并连接；断开用该连接的操作 | 不删除本机项目与会话；模型与设备清单随连接变化 |
| 添加设备              | 添加设备 → 设备类型 → 完成引导                 | 远程 Docker 命令含凭据，只在目标机器安全执行   |
| 状态、资源和版本      | 查看设备卡片，展开所需信息                     | 离线与加载失败不同；失败先看错误               |
| Terminal / IDE / 桌面 | 在支持该能力的设备卡片选择对应操作             | 启动在所选设备，不是当前电脑的任意目录         |
| 连接信息              | 设备操作菜单 → 连接信息                        | 不把连接凭据复制到聊天或公开文档               |
| 升级版本 / 重启设备   | 在设备操作菜单选择并检查确认                   | 设备短暂离线，等待进度及恢复；不要重复提交重启 |
| 删除设备              | 设备菜单 → 删除设备，核对目标并确认            | 不等于备份或删除远程项目目录                   |
| 新建项目              | 云端工作 → 新建项目 → 设备及其目录             | 云端登录不会自动选择云端执行                   |

## 本机工作

Wework 启动后会管理本机执行环境。本地项目、会话、Codex 和本地模型可以直接在本机使用。关闭窗口并进入系统托盘后，正在执行的本机任务会继续运行；完全退出应用会停止 Wework 管理的本机执行进程。

### 登录页和授权回跳

按部署配置，授权过程可能显示账号/密码登录或组织的 OIDC 登录按钮；只有服务端确需首次管理员初始化时才显示设置管理员密码表单。使用自己的已授权账号，不要把普通用户当成管理员初始化。

选择对应登录方式后按页面引导继续；OIDC 回调由应用处理，不需要手填 code、state、Token 或回调地址。看到 **授权成功，请返回 Wework 应用继续** 后回到客户端；仅打开网站或登录成功还不代表设备连接已完成。失败时从原连接入口重新发起，保留准确错误，不在聊天中粘贴含凭据的链接。

1. 点击侧边栏中的 **连接云端**。
2. 输入团队提供的 Wegent Backend 地址。
3. 点击 **授权并连接**。
4. 在授权页面完成登录并确认授权 Wework。

连接后，工作台会显示服务端模型、云设备和远程设备。断开连接不会删除本地项目和本地会话。

## 云设备

桌面端打开 **左侧栏 → 云端工作** 后，设备区域同时提供本机处理说明：本机执行环境由当前 Wework 管理，不会混入云端与远程设备卡片。遇到本机版本不兼容时，点击 **查看本机版本** 进入 **设置 → 个人 → 关于**，使用现有更新入口检查版本并按提示升级、重启，再从云端工作左侧栏的 **我的分身** 返回并重新加载。该入口在没有云设备或未连接云端时仍可用；网页端不显示。点击入口只导航，不会自动安装或重启。

云端连接可用后，点击侧边栏的 **云端工作** 会进入独立的云端工作页面，不再跳转到通用设置。这个页面集中展示：

- 云设备和远程设备的在线状态、executor 版本，以及终端、IDE 等设备操作。
- 云设备的 CPU、内存和磁盘使用率，以及连接信息、版本升级、重启和删除等管理操作。版本升级通过重启云设备完成，Executor 会在启动时自动更新；升级或重启期间设备会短暂离线，页面会持续显示进度并在恢复后提示。
- 关联云设备或远程设备的项目。点击项目会返回标准任务工作台，并选中对应项目。

页面右上角的 **连接设置** 才会进入 **设置 → 连接**。**添加设备** 也会进入连接设置并直接打开添加设备流程；**新建项目** 会回到标准项目创建流程，由用户选择设备和设备上的项目目录。

创建项目或任务时，可以选择在线的云设备。代码目录、终端和任务命令都位于所选设备。设备处于忙碌、离线或需要升级状态时，界面会给出相应处理入口。云连接不可用时，云端工作页面仍保留设备和项目空状态，并提供连接设置入口。

## 远程 Docker 设备

在 **设置 → 连接 → 添加设备** 中选择远程 Docker 设备，复制生成的启动命令并在目标机器执行。设备上线后可为其选择项目目录并运行任务。

启动命令包含设备凭证，应通过安全渠道保存和使用。

### 设备侧 Backend 地址解析

启动命令会把 Backend 地址写入设备的环境变量（`WEGENT_BACKEND_URL`、`WEGENT_SOCKET_URL`）。Executor 运行时只读取设备自己的配置，不再访问 Backend 的配置。`backend_url` 的解析优先级为：

1. 设备环境变量（启动命令中的 `export` 或 `docker run -e`）。
2. 设备配置文件 `$WEGENT_EXECUTOR_HOME/device-config.json`。
3. 自愈推导：当 `backend_url` 指向 loopback（`localhost`、`127.0.0.1`、`::1`）而 `socket_url` 不是时，Executor 从 `socket_url` 推导 `backend_url`（`ws`→`http`、`wss`→`https`，保留端口）。设备能建立 Socket 连接即证明该地址可达，因此早期烧入 `http://localhost:8000` 的设备在 Executor 升级后无需重新生成启动命令。

部署自建 Backend 时，应把 `WEGENT_BACKEND_PUBLIC_URL`（以及需要时的 `WEGENT_SOCKET_URL`）配置为设备可达的地址，让新生成的启动命令直接携带正确地址。

## 在其他设备继续任务

使用任务菜单中的 **复制到其他设备**，选择目标设备和项目目录。正在运行的任务会先停止当前回复，再创建目标设备上的副本。
