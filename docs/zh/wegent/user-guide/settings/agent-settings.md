## 🎯 概念概述

### 核心关系

```
智能体 (Agent/Team) = 机器人(Bot) + 协作模式
机器人 (Bot) = 执行器 (Shell) + 模型 (Model) + 提示词 (Prompt) + MCP 工具 + Skills
```

### 术语对照

| 代码/CRD 层 | 前端界面（中文） | 前端界面（英文） | 说明                   |
| ----------- | ---------------- | ---------------- | ---------------------- |
| **Team**    | **智能体**       | **Agent**        | 用户直接交互的 AI 助手 |
| **Bot**     | **机器人**       | **Bot**          | 组成智能体的构建块     |

### 架构图

```
┌─────────────────────────────────────────────────────────┐
│                    智能体 (Agent/Team)                   │
│  ┌─────────────────────────────────────────────────┐   │
│  │                   协作模式                        │   │
│  │              (Solo / Pipeline / Coordinate)            │
│  └─────────────────────────────────────────────────┘   │
│                          │                              │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐             │
│  │ 机器人 1  │  │ 机器人 2  │  │ 机器人 N  │             │
│  │  (Bot)   │  │  (Bot)   │  │  (Bot)   │             │
│  └──────────┘  └──────────┘  └──────────┘             │

```

## 🧩 协作项目中的智能体

Wegent Web 与 Wework 的协作项目使用同一套智能体新建表单。表单中的配置分为四个彼此独立的维度：

| 维度           | 说明                       | 示例                       |
| -------------- | -------------------------- | -------------------------- |
| **智能体来源** | 智能体定义保存在哪里       | 当前项目、共享智能体       |
| **托管方式**   | 智能体由哪一类运行环境承载 | 设备执行、Wegent 托管      |
| **执行器类型** | 智能体使用哪一种运行时     | Codex、Claude Code         |
| **能力来源**   | Skill、插件和 MCP 如何获得 | 跟随运行设备、手动选择能力 |

这四个维度彼此独立。**Wegent 托管是一种托管方式，不是智能体来源，也不是执行器类型。** 共享智能体保留自身定义的托管方式、执行器和能力配置；项目只保存对该智能体的引用。共享智能体既可以下发到满足要求的设备执行，也可以由 Wegent 托管。当前项目中创建的智能体则由表单直接保存执行器、模型、系统提示词和能力要求。

### 能力来源

- **跟随运行设备**：任务在哪台设备运行，就使用该设备上当前用户可用的插件、Skill、MCP 和本地能力。智能体不会固定绑定创建时使用的设备。
- **手动选择能力**：插件、Skill 和 MCP 随智能体保存。任务开始前，系统会选择或准备满足要求的执行设备，并将这些能力同步到执行环境。

系统提示词编辑器与任务输入框使用相同的引用交互，可以通过 `@` 或 `/` 插入支持的能力引用。引用只表达智能体需要使用的能力，不会把智能体隐式绑定到当前电脑。

## 🚀 创建智能体

### 步骤 1：进入设置页面

1. 登录 Wegent Web 界面
2. 点击左侧边栏的 **设置**
3. 选择 **智能体** 标签页

### 步骤 2：创建新智能体

1. 点击 **创建智能体** 按钮
2. 填写基本信息：

| 字段         | 必填 | 说明                                      |
| ------------ | ---- | ----------------------------------------- |
| **名称**     | 是   | 智能体的唯一标识符                        |
| **显示名称** | 否   | 用户友好的显示名称                        |
| **描述**     | 否   | 智能体的功能描述                          |
| **绑定模式** | 否   | 可用于哪些任务类型（Chat/Code/Knowledge） |

### 步骤 3：添加机器人成员

1. 在 **成员** 部分，点击 **添加成员**
2. 选择一个已配置的机器人
3. 为该成员设置：
   - **成员名称**：在团队中的标识
   - **角色**：Leader（领导者）或 Member（成员）
   - **成员提示词**：该成员在团队中的具体职责

### 步骤 4：选择协作模式

从以下模式中选择：

| 模式           | 说明                                 | 适用场景           |
| -------------- | ------------------------------------ | ------------------ |
| **Solo**       | 单个机器人独立工作                   | 简单任务、问答     |
| **Pipeline**   | 顺序执行，前一个的输出是后一个的输入 | 开发流程、内容生产 |
| **Coordinate** | 领导者协调并行执行，汇总结果         | 市场调研、代码审查 |

Web 界面当前在新建或编辑智能体时提供 Solo、Pipeline 和 Coordinate。

### 步骤 5：保存智能体

点击 **保存** 完成创建。智能体将出现在列表中，可以在聊天中使用。

## 🧰 通用基础能力

简单创建智能体时，**使用通用基础能力**默认开启。它让自建智能体沿用系统默认智能体已经配置的通用 Skill、MCP 工具和插件，同时保留自建智能体自己的名称、系统提示词、模型和执行器。

- 适用于 Chat、Claude Code、Codex 等执行器，不要求改用 Chat Shell。
- 系统只会把基础能力与当前智能体配置合并，然后发起一次模型执行；不会先调用默认智能体、再调用自建智能体。
- 当前智能体中同名的 MCP 或插件配置优先；Skill 会去重合并。
- 只支持一层基础能力继承，避免形成复杂继承链。
- 启用后会增加可用能力，也可能增加上下文长度、工具发现和工具调用消耗。只需要纯对话或极简执行时可以关闭。
- 选择 **跟随运行设备** 时，以执行设备上的当前用户能力为准，不加载 Ghost 中固定保存的基础能力。

保存后，界面会继续展示该智能体可用的 Skills。任务运行时会复用同一次请求内已经读取和合并的能力配置，不会因为提示词、Skill、MCP 或插件分别取值而重复查询。

## 🔧 配置机器人

### 步骤 1：进入机器人设置

1. 在设置页面，选择 **机器人** 标签页
2. 点击 **创建机器人** 或编辑现有机器人

### 步骤 2：基本配置

| 字段         | 必填 | 说明               |
| ------------ | ---- | ------------------ |
| **名称**     | 是   | 机器人的唯一标识符 |
| **显示名称** | 否   | 用户友好的显示名称 |
| **描述**     | 否   | 机器人的功能描述   |

### 步骤 3：选择执行器

选择机器人的运行环境：

| 执行器         | 说明                                    | 适用场景           |
| -------------- | --------------------------------------- | ------------------ |
| **ClaudeCode** | Claude Code SDK，支持代码执行和文件操作 | 代码开发、文件处理 |
| **Dify**       | 外部 Dify API 代理                      | Dify 工作流集成    |
| **Chat**       | 直接 LLM API（无 Docker）               | 轻量级对话         |

### 步骤 4：绑定模型

**方式一：从下拉列表选择（推荐）**

1. 保持 **高级模式** 关闭
2. 从下拉列表中选择已配置的模型

**方式二：高级模式（自定义配置）**

1. 开启 **高级模式**
2. 选择模型协议（OpenAI/Claude/Gemini）
3. 输入 JSON 配置

### 步骤 5：配置提示词

在 **系统提示词** 字段中输入机器人的角色定义：

```
你是一位专业的软件开发工程师，擅长使用 TypeScript 和 React 开发前端应用。

你的职责包括：
1. 编写高质量、可维护的代码
2. 遵循最佳实践和设计模式
3. 提供清晰的代码注释和文档
```

### 步骤 6：配置 MCP 工具（可选）

添加 MCP（Model Context Protocol）服务器以扩展机器人能力：

1. 点击 **添加 MCP 服务器**
2. 配置服务器信息：
   - **名称**：服务器标识
   - **命令**：启动命令（如 `docker`）
   - **参数**：命令参数
   - **环境变量**：所需的环境变量

### 步骤 7：添加 Skills（可选）

为机器人添加技能扩展：

1. 在 **Skills** 部分，点击下拉选择
2. 选择要添加的技能
3. 如需让技能在任务开始时就生效，勾选已选技能旁边的预加载选项
4. 技能将在任务执行时按需加载；预加载技能会在任务启动时提前注入或部署

**预加载 Skills**：

- 简单配置界面和完整配置界面都支持配置预加载 Skills
- **Chat** 和 **ClaudeCode** 执行器支持预加载 Skills
- 对于 ClaudeCode，预加载 Skill 会在任务启动时部署到 Claude Code 的 skills 目录
- 只有确实希望机器人优先使用的核心能力才建议预加载，其他技能可保持按需加载

### 步骤 8：保存机器人

点击 **保存** 完成配置。

## 🤝 协作模式

### Solo 模式

最简单的模式，单个机器人独立处理任务。

```
用户请求 → 机器人 → 响应
```

**适用场景**：

- 简单问答
- 单一任务处理
- 快速原型

### Pipeline 模式

机器人按顺序执行，形成处理流水线。

```
用户请求 → 机器人1 → 机器人2 → 机器人3 → 响应
```

**适用场景**：

- 代码开发流程（开发 → 审查 → 测试）
- 内容生产（写作 → 编辑 → 发布）
- 数据处理管道

### Coordinate 模式

领导者分解任务，并行分配给多个专家，然后汇总结果。

```
用户请求 → 领导者(分解) → [专家A, 专家B, 专家C] → 领导者(汇总) → 响应
```

**适用场景**：

- 市场调研（竞品分析 + 用户研究 + 趋势分析）
- 代码审查（安全 + 性能 + 质量）
- 综合报告生成

## ✨ 最佳实践

### 1. 提示词设计

**好的提示词结构**：

```
1. 角色定义：你是一位 [角色]...
2. 职责说明：你的职责包括...
3. 输入描述：你将收到...
4. 输出要求：请以 [格式] 输出...
5. 质量标准：确保 [质量要求]...
```

### 2. 机器人专业化

- 每个机器人专注于单一领域
- 避免创建"万能"机器人
- 通过团队协作组合能力

### 3. 协作模式选择

| 任务特点       | 推荐模式   |
| -------------- | ---------- |
| 简单、单一     | Solo       |
| 有固定流程     | Pipeline   |
| 需要多角度分析 | Coordinate |

### 4. 团队规模

- **Solo**：1 个机器人
- **Pipeline**：3-6 个机器人
- **Coordinate**：1 个领导者 + 3-5 个专家

## ⚠️ 常见问题

### Q1：智能体和机器人有什么区别？

**答**：

- **机器人（Bot）**：单个 AI 工作单元，包含执行器、模型和提示词
- **智能体（Agent/Team）**：由一个或多个机器人组成的"工作团队"，是用户直接交互的对象

### Q2：如何选择执行器？

**答**：

- **ClaudeCode**：需要代码执行、文件操作、Git 集成时使用
- **Dify**：需要与 Dify 平台集成时使用
- **Chat**：只需要简单对话，不需要工具调用时使用

### Q3：为什么我的智能体没有出现在聊天选择器中？

**答**：检查以下几点：

1. 智能体状态是否为"可用"
2. 绑定模式是否包含当前任务类型
3. 智能体是否至少有一个机器人成员

### Q4：如何让机器人使用特定工具？

**答**：

1. 在机器人配置中添加 MCP 服务器
2. 或者添加包含工具的 Skills
3. 在提示词中说明何时使用这些工具

### Q5：协作模式可以在任务执行中切换吗？

**答**：不可以。协作模式在智能体创建时确定，任务执行期间保持不变。如需不同模式，请创建新的智能体。

### Q6：开启通用基础能力会调用两次模型吗？

**答**：不会。系统读取当前智能体和基础 Ghost，合并 Skill、MCP 与插件后，只提交一次最终模型请求。基础 Ghost 的系统提示词不会覆盖当前智能体的人设。
