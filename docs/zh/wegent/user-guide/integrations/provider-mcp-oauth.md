# 提供方 MCP 的 OAuth 授权

部分提供方（例如钉钉）同时提供两种接入 MCP 的方式：

- **个人 StreamableHttp URL**：URL 自带一份个人凭据，有效期最长 30 天，到期后需要重新到提供方页面复制。
- **OAuth 2.0 授权**：提供方给出一个 OAuth 地址，客户端完成一次授权后可以持续刷新，不再受个人 URL 有效期限制。

Wegent 支持第二种方式，并代为完成授权和刷新。

## 切换到 OAuth 2.0

1. 打开 **设置 → 集成**，找到对应提供方（例如钉钉）的服务卡片。
2. 打开 **启用** 开关。
3. 在 **认证方式** 中选择 **OAuth 2.0 授权**。
4. 在 **MCP OAuth 地址** 中粘贴提供方页面给出的 OAuth 地址，例如 `https://mcp-gw.dingtalk.com/oauth/server/aitable`。
5. 保存后点击 **连接并授权**，在打开的页面完成提供方授权。
6. 授权完成后卡片会显示 **已连接**；需要重新授权时可以点击 **断开连接**。

钉钉的文档、表格、AI 表格和知识库是四个独立的服务地址，需要分别配置。

## 行为说明

- Wegent 从 OAuth 地址发现提供方的受保护资源元数据和授权服务器元数据，注册一个公开客户端并使用授权码加 PKCE 完成授权。
- Access Token 和 Refresh Token 按用户加密保存，任务开始前自动刷新即将过期的 Access Token，因此不再需要每隔 30 天重新复制 URL。
- 任务中的提供方 Skill、钉钉文档导入和自动同步都会使用对应服务的授权；表格和 AI 表格导出分别使用各自的凭据。
- 同时触发多个操作时，刷新会复用最新凭据；后台刷新不会取消正在进行的重新授权。
- 断开连接或保存服务配置后，之前尚未完成的授权失效，需要重新发起授权。
- 个人 StreamableHttp URL 模式保持不变；切换回该模式会清除已保存的 OAuth 凭据。
- 如果 Refresh Token 失效或被撤销，请在集成页面重新连接并授权。
