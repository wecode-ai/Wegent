# 分享令牌安全升级

新链接使用随机 opaque 令牌和 SHA-256 索引，显式标记为版本 2。
已有版本 1 的 AES 链接保留原 URL，但只作为资源定位符：必须登录，
并且当前仍有对应资源的读取权限。未记录、撤销和过期的链接失效。
原来仅收到 URL、没有资源权限的用户需要先由资源管理员授权。

统一 Task 分享的版本 2 链接使用 `/shared/task/access`，仅展示元信息并通过
现有 `/api/share/join` 申请访问；审批前不读取正文。旧版本 1 链接仍使用原来的
`/shared/task` URL，新的公开只读 TaskShare 链接也保持该路径，两者的权限规则不变。

## 数据兼容

迁移保留 `share_token`、状态、有效期和所有权，回填规范化后的 hash。
数据库的 `token_version` 默认值保持为 1，`token_hash` 允许 NULL，
因此旧实例在迁移后写入多个链接不会失败，也不会被误标为版本 2。
新版只通过已记录令牌的规范化 SHA-256 值定位这些无 hash 的旧记录，
仍执行登录与资源权限检查。缺少 hash 的版本 2 或未知版本不能使用此路径。
新版签发始终写入 hash 和版本 2；hash 的唯一约束仍然生效。
查询参数只传 hash，不把原始令牌放入数据库错误日志。

## 发布与回滚

存储兼容不代表旧实例的鉴权代码已经安全。不能让旧版本继续对外提供
分享读取、附件读取或加入接口。

1. 备份数据库，停止旧版本分享相关流量与写入，等待在途请求完成。
2. 执行 Alembic `upgrade head`，或等价的 Rust 迁移。
3. 启动新版 Python 与 Rust Backend，确认有效路由使用相同权限策略。
4. 验证有记录的旧 URL：匿名 401、无权限用户 403、有权限用户成功；
   验证新只读链接可以公开读取，不能用于审批或邀请。
5. 恢复流量，确认旧实例不再提供这些接口。

迁移支持 downgrade，移除两个新增字段与 hash 唯一索引，不改写 URL。
但回滚到旧鉴权代码会重新引入漏洞；回滚期间必须继续关闭相关接口，
或者使用已经回补同等权限策略的版本。不要把数据库回滚当成安全回滚。
