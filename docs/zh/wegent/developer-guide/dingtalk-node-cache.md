# 钉钉目录节点缓存

`dingtalk_synced_nodes` 缓存用户通过 MCP 同步的目录，不保存文档正文。

- 身份、来源、名称、父节点和已有分类字段继续作为常规列，用于查询和目录展示。
- `raw_metadata` 是单个节点的原始 JSON，在规范化 ID、补充父节点和构造知识库根目录之前保存，包括上游未知字段。它不是该 ID 所有接口返回值的汇总。
- 每次成功同步整体替换该节点的 JSON，不合并历史字段。上游删除的字段也随之删除。
- API 的 `extension` 从 JSON 读取并转为小写；原始 JSON 不向普通客户端返回。导入权限和格式校验不变。
- 历史缓存的 `raw_metadata` 可以为空。用户手动刷新目录后补齐，不根据 `node_type` 推断格式，也不增加自动修复任务。

## 未发布迁移

本分支尚未发布的 `d6e7f8a9b0c1` 迁移直接改为新增可空的 `raw_metadata JSON`，不再新增独立的 `extension` 列；前置版本为 `c5d6e7f8a9b0`。

尚未应用该迁移的数据库正常执行 `uv run alembic upgrade head` 即可。若开发库已经执行过旧版迁移，必须先用旧版迁移代码降级到 `c5d6e7f8a9b0`，再切换新代码执行升级；不能仅修改版本号，也不能在旧表结构上直接运行新版降级。降级会删除对应缓存字段，重新同步可补齐。

迁移测试验证实际 Alembic 升级、JSON 往返和回滚保留节点行。同步测试覆盖个人文档和知识库、原始 ID 与父节点边界、字段删除以及 API 投影。
