# 设备产物规则迁移：人工确认与回滚

`a9c4e7b2d610` 是数据迁移，不执行 DDL。它将公共内置 Ghost 的旧文件交付规则替换为“生成文件后声明产物”，不上传文件内容。**合并代码、CI 通过和本地迁移通过都不代表生产数据变更已获批准。**

## 生产变更门槛

在人工审核完成前，不得对生产运行包含该修订的 `alembic upgrade head`，也不得通过自动启动迁移间接执行它。部署负责人应先关闭该次部署的 `DB_AUTO_MIGRATE`，完成下面的预检、备份和审批，再由具备写权限的操作者执行迁移。本 PR 的生产审批不能由测试报告或笼统的“修复 review”指令替代。

迁移仅选择同时满足以下条件的行：

| 字段 | 条件 |
| --- | --- |
| `user_id` | `0` |
| `kind` | `Ghost` |
| `namespace` | `default` |
| `name` | `wegent-wework` |
| `is_active` | 真 |
| `json.spec.systemPrompt` | 两个已知旧段落各出现一次 |

不是按固定数据库 ID 覆盖。自定义、不完整、重复出现的旧段落不匹配，均保留原状。ID、技能、MCP、标签及其他配置不变；不得为了扩大命中范围而直接覆盖整份 Ghost。

## 只读预检与审批材料

使用目标环境的只读连接，通过环境配置提供 `DATABASE_URL`，不要把口令写在命令行、日志或 Git 文件中。在仓库根目录运行：

```bash
cd backend
uv run scripts/preflight_wework_file_delivery.py
```

脚本只执行 `SELECT`，不启动服务、不运行迁移、不输出提示词或连接串。输出每个候选行的 ID、活动状态、分类和 SHA-256，以及整份清单的指纹。分类含义：

- `legacy_exact`：活动行是本次升级候选。
- `migrated_exact`：带本修订标记、可由降级程序识别的段落。
- `current_seed`：新安装规则，没有迁移标记，不由降级程序还原。
- `custom_or_unrecognized`：需人工分析，不自动更新。

提交审批时记录环境、当前 Alembic revision、完整候选 ID/指纹、预期更新数量、操作者、变更窗口、备份位置及回滚条件。零命中不能当成“旧配置已经修好”；多个活动同身份行必须先人工查明。**操作者和审核人必须确认生产实际输出，不得用单元测试样本代替。**

## 升级与并发配置更新

1. 在变更窗口暂缓该公共 Ghost 的人工编辑，保存目标行及当前 revision 的受控备份。备份可含业务提示词，只能存放在批准的备份系统中，不能提交 Git。
2. 再次运行只读预检，与获批 ID、指纹和数量比较；任何差异均应停止并重新审核。
3. 用写连接执行该修订，避免顺带执行未经审批的其他迁移：

   ```bash
   uv run alembic upgrade a9c4e7b2d610
   ```

4. 更新语句再次核对资源身份、活动状态及读取时的**完整 JSON**。若编辑、重命名、归属变化、停用或其他 JSON 更新发生在读取之后，比较更新影响行数为零，迁移抛出错误并回滚事务。不得删除比较条件或通过反复重试覆盖并发修改。
5. 核对 revision 和只读清单，确认仅预期旧规则变成 `migrated_exact`，并比对备份，确认技能、MCP 等非目标配置不变。用独立任务验收“生成、声明、完成事件、卡片、下载”链路。

迁移只解决已识别的旧规则；自定义规则的人工修订属于另一项明确审批的配置操作。

## 回滚

前置 revision 为 `f3a7c9e1b2d4`。只有当前环境仍处于 `a9c4e7b2d610`、没有后续修订需要保留、并且回滚已获批准时，才执行：

```bash
uv run scripts/preflight_wework_file_delivery.py
uv run alembic downgrade f3a7c9e1b2d4
uv run scripts/preflight_wework_file_delivery.py
```

降级仅还原仍带本修订标记、且两个新段落均未被改写的配置。新安装规则和迁移后自定义段落不会被覆盖；并发修改同样触发比较失败。若段落已被定制，降级可能保留它们，不能只根据 Alembic revision 宣称提示词已经恢复。应比对受控备份并发起单独的人工恢复审批，不要强制覆盖。

本流程不删除任务文件、产物上下文、任务记录或设备，不执行 DDL，也不改变协作权限模型。
