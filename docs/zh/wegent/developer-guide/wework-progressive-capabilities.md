# Wework 渐进式能力加载

Wework 默认使用 Codex 原生 Code Mode。内置工具与 MCP 工具保留原生注册、执行、权限和结果处理，通过 `ALL_TOOLS` 的名称与描述按需发现。模型请求中的 `exec` 保留执行接口与发现说明，不预先附带整个嵌套工具目录；发现结果提供实际调用签名。明确设置为 `direct` 的自定义模型仍按其设置执行。

原生模型保留 Codex catalog 自带的基础指令和 `model_messages`，Wework 不再覆盖或复制通用编码规范，也不再提供 coding skill。第三方及自定义模型默认继承随当前 Codex 发布的默认模型指令，按原生选择器的可见性和优先级选取，不维护另一份提示词。仅精确匹配已退役默认值的旧配置会改为继承；用户显式编写的指令和模型目录覆盖仍保留。Wework 平台路由、权限及安全要求通过 developer instructions 补充。

普通仓库操作、文件检查或进程诊断无需读取通用工作流文件。浏览器、桌面、GitHub、连接器授权、会话与计划、可视化和产物交付等专项工作流仍由对应 skill 承载。初始上下文保留 skill 元数据；仅在任务需要时读取正文及相关参考，压缩后按需重新读取。

Goal 功能可用与创建 Goal 是不同的状态。普通会话不因此创建目标；用户在创建入口选定目标时，宿主通过原生 Goal 接口设置它。相关工具可经原生发现获取，不把完整 Goal 工具定义提前展开到普通会话。

原生 Responses Lite 保留 `input.additional_tools`。兼容 Responses、Chat Completions 和 Anthropic Messages 使用对应协议的工具声明与调用格式。适配层保留命名空间和 custom 工具的原始字符串输入；增量目录按顺序应用新增、重定义和原生撤销通知。当前顶层工具目录不能因历史 `additional_tools` 被重新引入已撤销定义。

宿主规则由原生 developer instructions 统一承载。每轮提供有界版本引用；策略更新或上下文恢复时加载对应不可变策略文件，不复用旧版本，也不替代独立应用上下文或原生权限。

独立 Backend Task 保留原有产物声明约定内联，通过与任务环境相同的 Backend 身份判断区分；Wework 会话继续通过 artifact skill 按需读取。纯文本辅助请求不加载这类操作指令，且会移除顶层及 Lite 历史中的工具定义。

## 验证门槛

现有桌面 `model-routing` 矩阵覆盖 10 种模型配置 × 本地/云端执行，共 20 项。Core 分片执行 3 项本地自定义模型；Cloud 分片执行其余 7 项本地执行配置和全部 10 项云端执行配置。协议切换只修改上游协议字段，保留插件和 MCP 配置。

每项验证实际模型边界的完整请求：首次输入必须是 `hi`，未读取的 skill 正文及未发现的 MCP 定义不能提前出现；内置调用签名不能预先展开。使用固定 `tiktoken JS/WASM 1.0.22`、`o200k_base` 对完整 JSON 请求估算 token，严格要求小于 12,000，为恢复原生基础指令保留预算。这是统一回归口径，不是供应商计费 token。

`codex-native-catalog` 检查点通过独立进程的模型 Mock 捕获实际 HTTP 请求，保留请求正文及审计报告，断言原生基础指令仅出现一次、宿主规则没有重复、无关专项 skill 正文未加载。认证请求头不写入证据。

模型服务使用脚本桩，其余链路真实运行。每项实际完成工具发现、MCP 调用、Goal 状态读取、skill 文件读取、再次发现及文件修改回环；检查受测能力未丢失、未加载无关 skill，并保留完整请求和独立报告。某项失败后继续其他组合，最终统一报错，不能把用于结束失败回合的桩响应计为调用成功。
