# Wework 我的替身

“我的替身”属于个人。协作导航默认展示启用状态、连接项目数量，以及按项目分组的实际处理记录；点击记录打开执行任务。通过二级“设置”管理替身，默认只有一个替身，多个时才显示切换。界面统一使用“替身”，存储中的 `roles` 是这些个人替身的配置列表，不是另一层需要用户理解的角色。

项目工具栏打开“项目替身”：优先选中已连接本项目的替身，否则选中第一个可用于本项目的个人替身。已有替身只读展示智能体、已有处理要求和自动处理状态，“用于此项目”只建立连接，不修改共享执行配置。设置链接明确跳转到“个人替身设置”，说明修改会影响其他使用此替身的项目；保存或取消后返回原项目，并保留明确保存的执行设备选择。首次连接尚未启用协作来源的替身时，只连接当前项目，不自动扩大到所有项目。选择失败的重试入口只在个人设置中提供，重试不导航离开，也不建立项目连接。

“为此项目新建替身”仍创建个人替身，默认名称为项目名，保存后只连接当前项目，也会出现在“我的替身”的设置列表。处理要求默认展开，更多设置默认收起；二级设置始终编辑当前替身，不再切换。可选择通用助手、个人智能体或项目智能体；项目智能体自动连接其所属项目，替身仅处理该项目。未登录时不请求云端个人智能体目录，也不显示登录或加载失败提示，通用助手和可用的项目智能体保持可选。真实目录请求失败保留重试入口。

处理要求复用普通 composer、技能、插件和 Goal 模式。设备、模型与代码工作区收在更多设置。保存个人设置不依赖云端目录、项目设备绑定或模型就绪；执行时再校验当前用户、Issue 权限及智能体设备和模型约束。

所有编辑（包括自动接单）均为草稿，保存后才生效。处理要求和执行字段以函数式更新合并到当前替身，composer 的延迟回写不能覆盖开关、设备或工作区的新值。保存失败保留草稿，版本冲突不会覆盖其他编辑。关闭或 Esc 遇到未保存修改时需要明确放弃；二级页面返回会撤销该页面草稿。停用只影响新接单，正在运行的普通 Runtime 任务继续。

每个角色可接入所有参与的协作项目（包括以后加入的项目）并排除个别项目，也可选择具体项目；可选标签用于缩小任务范围。项目数量增加不需要重复设置执行配置。配置按账号保存在所选 Executor 的 SQLite 中；不同设备的配置独立，离线设备不能编辑。本地项目只在拥有其数据的设备展示。

存储只有一个个人设置文档，包含版本、角色顺序和全局自动选择选项；角色包含名称、执行配置、开关及来源范围。旧项目配置在事务内迁移为角色，并保持原项目范围、启用时间和原智能体的使用边界。旧项目寻址 RPC 仅是个人文档的视图，不再写入另一份项目设置。

## 角色调度

先做确定性范围和标签匹配；有标签的匹配角色优先于未限定标签的角色。只有一个候选角色时直接执行，不调用选择模型。多个候选角色默认使用角色调度页中靠前的角色；用户可调整顺序。每次分配只执行一个角色。

“多个角色都适用时，让替身自动选择”是所有角色共用的个人选项，位于独立的角色调度页。开启后只在多个角色匹配时调用模型，产生模型用量；来源采集、去重和标签匹配不消耗 Token。选择模型使用受限、无工具的临时请求，返回候选角色 ID 和原因；不能执行任务或选择范围外角色。选择结果按分配和配置版本缓存，失败不会在每轮轮询中反复调用。选择失败展示在个人设置中，调整配置或点击重试后重新选择。单个任务选择失败不阻止同项目其他任务继续接单。

选定设备的 Executor 定期检查启用后的本人分配，过滤历史、他人、未分配以及已关联执行的任务，然后复用 `runtime.tasks.create`、普通任务绑定、会话和结果入口。手动委托可在自动接单关闭时执行；未指定角色时使用同样的匹配策略。原有任务来源记录实际角色与选择原因。

云端项目沿用现有项目 API 和个人执行权限；本地项目不要求云端连接。Executor 停止期间不触发，启动后继续检查。创建失败回滚 Issue 绑定；已有失败执行保留原任务供重试，不重复创建。跨设备竞争仍受现有任务绑定语义约束，没有新增服务端队列或分布式锁。

## 协作通知中的处理反馈

协作通知直接读取现有 Runtime 执行列表，通过项目、Issue 和本次分配标识关联替身任务。已有分配通知内展示面具图标、处理中、等你回复、处理完毕或失败状态；没有分配通知的本地或手动执行，也能在协作通知中找到。点击任务标题进入对应执行会话，不重新派发任务。

通知按来源、事件和时间、任务正文、轻量操作组织，不再增加“新任务”标题。创建通知时直接保存真实分配人姓名或负责人智能体名称，列表直接读取通知，不跨表反查。没有姓名的通知省略分配人信息，直接展示任务标题和时间，不显示占位文案。替身接手后在同一条通知更新身份和状态。

处理区域可以直接补充要求、回复真实的 Runtime 问题，或重试失败的替身任务。普通补充输入在点击“回复”后展开；需要你回答的问题直接显示。快捷回复继续原会话；Runtime 拒绝发送时保留草稿并显示错误。问题选项沿用会话中的原始问题和请求标识，不根据结果文本猜测可执行操作。

完成、失败和需要回复时重新显示未读，并更新列表排序。桌面提醒遵循协作通知的设置，正在查看该执行时不重复弹出。状态和通知关联由桌面前端完成，不新增后端 API 或 Executor 协议。

替身状态的已读标记和桌面提醒去重记录按账号保存在当前设备，不跨设备同步；原有分配通知仍使用已有的已读接口。两类辅助记录各保留 90 天、最多 1000 条，在读取和写入时清理，过期清理不删除真实通知、任务或执行历史。

完成状态的事件标识使用 Runtime 执行轮次 ID，不使用会随摘要补齐而变化的时间戳；同一轮的状态与任务摘要先后到达时，不会重复提醒或把已读结果重新标为未读。旧的时间戳标记在匹配当前状态时更新为轮次标记。恢复任务列表时，首次读到的已有结束状态只建立提醒基线，保留通知及其未读状态，不补弹历史桌面提醒；后续新一轮执行完成仍正常提醒。

聚焦测试覆盖设备设置持久化与版本、多配置及标签规则、历史分配过滤、已有关联过滤、设备切换，以及侧栏状态合并和保存更新。桌面 `stand-in`、`stand-in-workspace`、`stand-in-cloud`、`stand-in-controls` 和 `stand-in-notifications` 场景均注册至现有 CI，仅替换模型响应；其余存储、任务执行、云端 API 和设备连接使用真实实现。

## 验证计划

使用隔离 Electron、独立项目与 Executor 数据。云端检查点使用真实后端及设备连接，只替换模型响应。证据截图保留在仓库外，具体运行结果记录在 PR 中。

| 场景         | 操作                                         | 预期                                           |
| ------------ | -------------------------------------------- | ---------------------------------------------- |
| 个人首页     | 从协作导航进入                               | 展示替身状态和按项目分组的执行记录，设置在二级 |
| 项目入口     | 从项目工具栏进入                             | 默认选中已连接或首个可用替身，已有配置只读     |
| 项目新建     | 选择为项目新建替身并保存                     | 个人拥有，默认只连接当前项目                   |
| 全局设置跳转 | 点击修改替身设置，保存或取消                 | 进入个人设置并返回原项目，提示跨项目影响       |
| 草稿与取消   | 修改开关和要求，访问插件页后返回，取消或 Esc | 草稿保留，保存前不生效，明确放弃后关闭         |
| 失败恢复     | 保存旧版本或断开 Executor                    | 错误可见，草稿保留，重新加载可恢复             |
| 批量连接     | 接入所有项目，排除一个项目                   | 统一配置覆盖新项目，排除项目不执行             |
| 多替身       | 添加替身并重新打开                           | 独立配置保留，二级更多设置不切换替身           |
| 确定性选择   | 分配同时匹配多个标签的任务                   | 按顺序选择一个替身，不调用选择模型             |
| 自动选择     | 开启选项并分配重叠任务                       | 模型只选一个候选，实际执行与来源一致           |
| 单匹配       | 自动选择开启时分配单匹配任务                 | 直接执行，不额外调用选择模型                   |
| 去重与权限   | 检查历史、他人、未分配及已有关联             | 不产生新执行，不改变负责人                     |
| 旧数据迁移   | 读取多个旧项目配置                           | 范围、启用时间、权限边界保持，旧行删除         |
