# Wework 项目内会话使用单一最近活动排序

## 状态

已接受

## 背景

Wework 同时维护手动会话顺序、未排序会话优先、置顶移出、队列位置替换和可见会话追加，导致新会话、已回复会话和当前会话可能出现在用户意料之外的位置。旧的人工顺序还会在刷新或缓存合并后继续影响排序。

## 决策

项目内普通会话只按最近活动从新到旧排列。新增会话和收到用户消息的会话立即推进活动时间；置顶会话移出普通列表并显示在全局置顶区。项目和置顶会话仍保留各自现有的用户顺序。

Wework 移除项目内会话拖拽，不再读取或写入任务级 `sidebarOrder`。Codex 兼容状态中的既有 `threadIds`、`sidebarOrder` 等字段保持原样，但不再影响 Wework 排序，避免破坏性迁移。

当前会话、运行中、未读和等待中的会话只影响可见性，不参与排序。若特殊会话超出默认预览范围，列表自动展开到其真实位置。

`queuePosition` 只决定运行时排队任务的执行先后。侧栏可以显示“排队中 / 第 N 个”等提示，但不得使用队列位置替换、插入或重排侧栏列表。执行顺序归执行队列，侧栏排序归最近活动，两者完全解耦。

## 后果

- 新会话和时间更新的会话自然位于普通会话前部，不需要额外的人工顺序槽位。
- 失效的人工顺序、空 `threadIds` 和缓存中的旧 `sidebarOrder` 不再影响侧栏。
- 用户不能再在项目内手动排列会话；项目级排序不受影响。
- 当前会话位于较深位置时，项目可能展开较多会话以保持可见。
- 排队位置推进时只有状态提示变化，会话不会在侧栏中跳动。
