# Interface navigation and feature locations

To continue a task when a connected resource changes, describe the condition in the **task composer**. AI subscribes through tools; the source and wait state appear above the composer. Select **Wait condition** on the same row for details. The left task sidebar also shows event status. Goals can wait too. See [Ask AI to wait for connection events](./tasks.md#connection-event-waits).

Use this page to find an entry point, then follow the linked usage guide. It describes the desktop main window; popup, narrow-window and operating-system layouts may differ. Paths below are click sequences, not commands to enter.

For home, search, device filters, and conversation entry points on iPhone and Android, see [Wework Mobile](./mobile.md).

Mobile files: **Conversation → top-right More → Files / Changes (更多 → 文件 / 更改)**,
available when an accessible workspace is selected. Reply file links, attachments, and expanded change
paths also open previews. See [Mobile file previews](./mobile-file-preview.md) for controls and limits.

Mobile project and conversation management: **Wework ▾ → New project / Archived conversations**; project row **… → Pin, Rename, Archive all chats, Remove**; conversation row **swipe left → Archive** and **long-press → Pin, Rename, Copy ID, Archive**. Removing a project preserves files and conversations. Permanent deletion requires confirmation in Archived conversations. See [Wework Mobile](./mobile.md).

## Know the interface

| Area                | Location                               | Purpose                                                                                                       |
| ------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Left sidebar        | Left edge of the main window           | Create tasks, search, open projects and previous conversations; the account menu at the bottom opens settings |
| Top tab bar         | Top of the main window                 | Switch between open Tasks, Collaboration (project spaces) and Agent pages; use + to add a tab                 |
| Conversation        | Center of a task page                  | Read replies, inspect tool activity and answer confirmation requests                                          |
| Composer            | Below the conversation                 | Enter tasks, attach files, select models, permissions, plugins or Skills                                      |
| Right workspace     | Right of the conversation; collapsible | Files, review, built-in browser and other workspace tabs                                                      |
| Bottom panel        | Below the conversation; collapsible    | Terminal and other auxiliary sessions                                                                         |
| Settings navigation | Left side after opening settings       | Select pages grouped under Personal, Integrations, Coding and Archived                                        |

On macOS, the default shortcuts are `Command+B` for the left sidebar, `Option+Command+B` for the right workspace and `Command+J` for the bottom panel. For other systems or customized bindings, check **Settings → Shortcuts**.

## Where do I go?

For in-conversation model switching and continuity, see [Model settings](./user-guide/model-settings.md#model-controls).

To access this computer's tasks from a phone or another computer on the same account, open **Account menu at the bottom of the left sidebar → Settings → Connections → Allow remote access to tasks on this computer**. This entry appears only in the desktop client. It defaults to off and saves immediately on this computer; other devices cannot change it. Failed reads show **Retry** beside the error. Remote access requires this computer to remain running and connected to the cloud. Turning the switch off revokes subsequent access. See [Devices and remote access](./devices.md).

For clone authentication failures, execution-environment device errors or Git authentication cards in conversations, use **Configure Git account** at the original entry to open the current cloud Web settings. It edits a matching account or prefills a new one. Desktop **Account menu → Settings → Coding → Git hosting → Device Git configuration** provides manual sync and separately confirmed clearing when accounts are empty. These entries apply to ClaudeCode cloud or remote devices; native local Git / SSH stays local, and an unresolved Web address never redirects to Backend. See [Repository access configuration and device sync](./git-connections.md#device-git-configuration).

Select **Continue in a new conversation** on a task's conversation history error card to open a draft with a reference to the original conversation. See [Recover a conversation](./tasks.md#recover-conversation-history).

Prepare a voice input model: **bottom-left account menu → Settings → Personal → General → Voice input**. This section appears when the official voice plugin has loaded; prepare a model, then record from the task composer. See [Voice input model](./settings.md#voice-input-model).

To report a problem or export runtime logs, select **Report a problem** in the upper-right corner of any Wework desktop page. Plugins, My assistants, Scheduled and Settings use the same entry; task pages can also include task context. See [Getting help](./troubleshooting.md#getting-help).

If the page error or startup error screen appears, select **Copy debug info** next to **Refresh page**. See [Getting help](./troubleshooting.md#getting-help).

Pending business questions offer **Talk it through** on the task question card or in **Needs your input** question details. It opens a discussion tab alongside browser and files in the original task's right sidebar. See [Handle AI questions](./workbench.md#ai-questions) for its purpose and restrictions.

At the bottom of a business question card, **Skip** hides asynchronous questions without sending a message. Blocking questions receive empty answers to end their wait. **Collapse** keeps text and attachment drafts available for later. See [Answer AI questions](./tasks.md#question-answers) for input and attachment controls.

Dismiss pending work: **Needs your input → cross beside an entry (Dismiss item)**, or **Needs your input → above the left list → Dismiss all**. These actions archive locally without answering questions or changing Issue state. See [Questions and project work](./workbench.md#ai-questions).

When a question is already handled but a notification reply was not sent, **Needs your input → above the left list → Unsent replies** retains selectable text and offers **Discard this draft**. See [Handle AI questions](./workbench.md#ai-questions).

From **Projects → New project → Cloud project** in the sidebar, you can add a device while choosing the remote host. See [Projects and workspaces](./projects.md#add-device-from-project).

Edit Agent definitions from **Project settings → AI configuration**. Project Maintainers can edit non-private project definitions; shared source definitions retain their original permissions. Imported and manually created Agents share the same entry. See [Agent configuration](./projects.md#agent-capabilities) for device-conflict recovery.

In cloud projects, use **Add agent → Connect external agent** to configure a hook or Worker. See [Connect an external agent](./projects.md#external-agents).

## Sidebar feature entries

Project settings in narrow windows collapse the sidebar into **Collaboration navigation** above the page. Expand it for Home, projects and other collaboration entries; choosing a location collapses it again. See [Project settings](./projects.md).

For an initial task load or load failure, check the status below **Tasks** in the desktop sidebar; use **Retry** after a failure. In priority view, the status appears above the list. See [Sidebar task management](./tasks.md#sidebar-task-management).

If the Issue summary above the composer cannot read its task count, use its retry action. See [Add a conversation to a project-space board](./tasks.md#task-board-association).

## When an entry is missing

1. Confirm that you are in the desktop main window and the relevant sidebar or panel is expanded. Hover over icon buttons to read their names.
2. Check context: the task model selector, a project's settings and global application settings are different surfaces.
3. Check feature mode and experimental features in **Settings → General**. Focus mode hides Git hosting and Worktrees and disables the built-in Git plugin. Experimental entries may also be hidden. Finding ordinary features does not require full-access permissions.
4. For cloud features, check connection and device status; for project management, check your project role; for plugin features, check installation, enablement and authorization for that particular app. A missing entry does not by itself mean you are signed out.
5. Check the version in **About** and report your OS, current page, goal and visible controls. Documentation ships with the app version; report a documentation gap if it still does not match, rather than guessing menu locations.

## Coverage and maintenance

This page indexes locations; linked topic guides own detailed procedures to avoid duplicate instructions. Automated checks compare settings pages and registered sidebar entries against real DSH declarations in both languages, including names, groups and visibility flags. Additions, removals and renames must update this page in the same change.

Composer controls, project menus and account menus still require manual code-review checks. Automated tests cannot prove that every button is documented or that the running layout matches. See repository `wework/AGENTS.md` for maintenance rules. Builds copy both documentation trees into bundled wework-docs; repository edits do not instantly update older installed versions.

For recovery-center and local-service notices during launch, see [Startup recovery](./getting-started.md#startup-recovery). **Check Codex configuration → Retry** appears while configuration reading is pending or has failed, and reads the status again.

Independent and project Issues are available from **Collaboration → My issues → Needs my action / Created by me / Participating**. Start an independent Issue from **Collaboration → My issues → New Issue**. Open **More settings** at the bottom left to set status, priority and due date. Existing catalogs are under **Collaboration → Collaboration management → Execution devices / Templates / Agents / Teams**. See [Independent Issues and My issues](./projects.md#independent-issues). The collaboration Home retains its existing composer, Issue list and assistant workspace.

Use **Personal group → … → Group settings** to manage the actual personal space owned by the current account. The Projects heading and project rows no longer show plus buttons. See [Project navigation](./projects.md#workspace-resource-controls).

Images, Markdown and file links in Issue activity open attachment previews with retry and original-file download. See [Attachment and document previews](./projects.md#issue-resource-preview).

Default execution devices and device grants from new Issues are described in [Collaboration device settings](./devices.md#collaboration-device-defaults): **Collaboration → Collaboration management → Execution devices → Personal default environment**. **Collaboration → New Issue → More settings → Runtime (optional) → Personal default environment → Save personal default device** explicitly saves personal preferences. For a selected project, **Project device access (applies immediately) → Choose or add a device** manages project grants. See [Independent Issues](./projects.md#independent-issues) for participant selection, the persistent action bar and unsaved-change protection.

Issue **Participants → +** supports search and multiple selections. The assignee picker also searches outside the project; confirmation grants management of that Issue only. See [Issue collaboration](./projects.md#project-controls).

Link an existing task: **Collaboration → Issue details → Linked tasks → Link existing task**. See [Projects and Issues](./projects.md).

Create a child from a comment: **Collaboration → Issue details → top-level comment action row → Create child Issue beside Reply**. Thread replies retain their own action. See [Create child Issues from comments](./projects.md#comment-child-issues) for availability and steps.

Choose **Share as issue** above the task composer, or select text in the conversation and choose **Share with others**. Use **Add attachment** or **+** at the left of the attachment row to upload files, use the arrows to browse attachments, or open **More settings** on the left side of the dialog footer. See [conversation sharing](./tasks.md#share-conversation-as-issue).
