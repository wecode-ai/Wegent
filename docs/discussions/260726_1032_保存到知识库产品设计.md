# “保存到知识库”MVP 产品设计

## 文档信息

| 项目 | 内容 |
|------|------|
| 状态 | MVP 讨论稿 |
| 创建时间 | 2026-07-26 |
| 最后更新 | 2026-07-26 |
| 适用范围 | Wegent 已登录用户可见的 AI 对话 |
| 核心动作 | 将一条 AI 文本回答编辑后保存为知识库文档 |

## 一、结论

“保存到知识库”首先是一项全局内容沉淀能力，不是 Notebook 的专属笔记能力。

MVP 只打通以下闭环：

```text
已完成的 AI 文本回答
        ↓
选择目标知识库
        ↓
修改标题和 Markdown 正文
        ↓
创建 KnowledgeDocument
        ↓
进入现有索引流程并支持查看
```

Notebook 只提供目标知识库的合理默认值；普通对话即使没有使用知识库，也可以把回答保存到任意有写权限的知识库。

MVP 不建立消息与文档的持续关系，不做来源追踪、重复保存检测、笔记模型或 Artifact 生成。

## 二、第一性原理

### 2.1 用户真正需要保存的是结果

对话负责生成内容，知识库负责长期沉淀和复用。

用户需要的不是保存完整对话过程，而是把一段已经确认的结果变成可管理、可编辑、可检索的知识文档。

因此，保存前用户最终确认的标题和正文是新文档的唯一事实源。保存完成后：

- 原消息继续属于对话；
- 新文档独立属于目标知识库；
- 修改文档不会影响原消息；
- 原消息变化也不会同步到文档。

### 2.2 输入来源不等于输出目的地

一次对话使用了哪些知识库、附件或外部资料，只决定 AI 如何生成回答，不决定回答必须保存到哪里。

因此：

- 未选择知识库进行对话，也可以保存到知识库；
- 使用了某个知识库进行对话，不代表必须保存回该知识库；
- Notebook 当前知识库可写时，可以默认作为保存目标；
- 用户始终可以改选其他有写权限的知识库。

### 2.3 只为最小闭环增加必要复杂度

Wegent 已经有：

- AI 对话消息；
- 知识库及其权限；
- 文本知识文档；
- 文档目录；
- 文档索引和编辑能力。

因此 MVP 只需要连接现有对象，不新增 Note、Artifact、消息文档关系表或其他持久化模型。

重复保存的结果只是一篇额外文档，容易发现和删除，其损失不足以支撑重复检测或幂等机制的复杂度。

## 三、问题与目标

### 3.1 当前问题

用户在对话中获得有价值的回答后，只能：

1. 复制回答；
2. 离开当前对话；
3. 打开知识库；
4. 新建文档；
5. 粘贴、修改并保存。

操作路径长，导致有价值的回答停留在对话历史中，无法进入后续检索和复用链路。

### 3.2 MVP 目标

1. 用户可以从任意已登录对话保存已完成的 AI 文本回答。
2. 用户可以选择自己有文档创建权限的知识库。
3. 用户可以在保存前修改标题和 Markdown 正文。
4. 保存后创建普通知识库文档并进入现有索引流程。
5. 保存动作不改变当前对话的知识库、上下文或页面状态。
6. 用户保存成功后可以直接查看新文档。

### 3.3 非目标

MVP 明确不做：

- 手写空白笔记；
- 未发布草稿；
- 私人笔记与共享知识分离；
- 独立 Note 或 Artifact 数据模型；
- 消息与文档的关系表；
- 任务 ID、子任务 ID等来源追踪；
- 原回答引用继承和可信溯源；
- 重复保存检测和阻止；
- `idempotency_key`；
- 文档版本、审核和发布流程；
- 独立协作权限；
- PPT、Word、PDF、脑图等 Artifact 生成；
- 图片、音频、文件和交互卡片的内容转换；
- 自动将目标知识库加入当前对话；
- 保存结果与原消息的双向同步；
- 复杂的索引进度轮询；
- 匿名用户和公开分享页访客保存。

## 四、目标用户与使用场景

目标用户是拥有至少一个可写知识库的已登录用户。

### 4.1 普通对话

用户在没有选择知识库的普通对话中获得一段有价值回答，希望将其保存到个人或团队知识库。

系统不预设目标，用户必须选择知识库。

### 4.2 使用知识库的对话

用户在对话中使用了一个或多个知识库作为上下文，并希望保存回答。

对话使用的知识库不自动成为保存目标。MVP 不推断用户的保存意图，仍由用户选择目标。

### 4.3 Notebook

用户在某个知识库的 Notebook 中对话，希望将整理后的结果保存为该知识库文档。

- 当前知识库可写：默认选中当前知识库；
- 当前知识库只读：不默认选中，并提示用户选择其他可写知识库；
- 用户可以切换到其他可写知识库。

### 4.4 共享知识库

用户把内容保存到其他成员可访问的知识库。

系统在选择器和确认区域中展示目标知识库的所属空间，并提示内容将遵循该知识库现有权限。

## 五、MVP 功能需求

### 5.1 保存入口

在满足以下条件的 AI 消息操作区展示“保存到知识库”：

- 当前用户已登录；
- 消息角色为 AI；
- 消息生成已完成；
- 消息包含非空、可序列化的 Markdown 或纯文本正文；
- 消息不是错误占位、取消状态或仍在流式生成。

以下内容不单独保存：

- 用户消息；
- 系统消息；
- 模型推理过程；
- 工具调用日志；
- 纯图片、纯音频或纯附件消息；
- 无稳定文本表示的交互组件。

混合消息只提取用户当前可见且可序列化的正文；附件本身不进入新文档。

### 5.2 保存弹窗

点击入口后打开弹窗，包含：

1. 目标知识库；
2. 文档标题；
3. Markdown 正文；
4. 取消和保存操作。

弹窗必须明确展示“内容将保存到哪个知识库及其所属空间，并对该知识库现有成员可见”。

关闭弹窗视为放弃本次编辑，不创建草稿。

### 5.3 目标知识库

- 只展示当前用户有文档创建权限的知识库；
- Notebook 当前知识库可写时默认选中；
- 其他场景默认不选中；
- 如果用户没有任何可写知识库，展示空状态并禁止保存；
- 提交时后端必须再次校验目标知识库写权限。

前端筛选只用于改善体验，不作为安全边界。

MVP 统一保存到目标知识库根目录，不提供目录选择。保存后用户可以使用现有知识库能力继续整理文档。

### 5.4 默认标题

标题优先级：

1. 使用上一条用户消息的首行文本；
2. 去除多余空白并截断到系统允许长度；
3. 无法生成时使用“对话保存内容”。

MVP 不额外调用模型生成标题。

### 5.5 默认正文

- 使用当前消息最终完成版本的用户可见正文；
- 保留 Markdown 标题、列表、表格、代码块、链接等结构；
- 不包含模型推理过程、内部调试信息和工具日志；
- 不自动拼接历史消息；
- 不自动附加来源说明；
- 用户可以在保存前任意修改。

弹窗中最终确认的正文是新文档的唯一事实源。

### 5.6 创建文档

用户点击保存后：

1. 校验目标知识库、标题和正文；
2. 在目标知识库根目录创建普通文本 `KnowledgeDocument`；
3. 文档格式为 Markdown；
4. 复用现有文档索引和摘要链路；
5. 不保存原消息 ID、任务 ID、子任务 ID或引用列表；
6. 不改变当前对话上下文。

用户对同一回答重复执行保存时，每次都创建一篇新文档，不检测或阻止重复。

### 5.7 结果反馈

保存成功后：

- 关闭弹窗；
- 提示“已保存到「知识库名称」”；
- 提供“查看文档”操作；
- 用户留在当前对话；
- 文档进入现有异步处理流程。

这里的成功表示“文档已创建并已进入现有处理流程”，不表示异步索引已经完成。

保存失败后：

- 弹窗保持打开；
- 保留用户已编辑的标题、正文和目标选择；
- 展示明确失败原因；
- 允许用户修改后再次保存。

## 六、核心用户故事与验收标准

### 6.1 从任意对话保存

作为已登录用户，我希望把已完成的 AI 文本回答保存到知识库，从而不需要复制粘贴和切换页面。

验收标准：

- 未使用知识库的普通对话也显示保存入口；
- 生成中的消息不显示或禁用保存入口；
- 非空文本回答可以进入保存弹窗；
- 保存后当前对话上下文不发生变化。

### 6.2 选择有权限的目标

作为用户，我希望只选择自己能写入的知识库，从而避免保存后才发现没有权限。

验收标准：

- 选择器只展示可写知识库；
- Notebook 仅在当前知识库可写时默认选中；
- 权限在提交时被服务端再次校验；
- 权限失效时保存失败且保留编辑内容。

### 6.3 保存前修改

作为用户，我希望在保存前修改标题和正文，从而只沉淀自己确认过的内容。

验收标准：

- 弹窗预填标题和完整可保存正文；
- 标题和正文可以修改；
- 空标题或空正文不能提交；
- 最终保存内容与弹窗提交内容一致。

### 6.4 查看保存结果

作为用户，我希望保存后能够确认目标并打开文档，从而继续编辑或管理。

验收标准：

- 成功提示包含目标知识库名称；
- “查看文档”打开新创建的文档；
- 新文档可以使用现有知识库编辑能力继续修改；
- 新文档进入现有索引流程。

## 七、权限与安全

后端必须校验：

```text
用户有权向目标知识库新增文档
+ 标题和正文满足文档约束
```

安全要求：

- 不信任前端传入的权限结果；
- 不返回或保存模型推理、内部日志等不可见内容；
- 不在知识文档中写入原任务和子任务标识；
- 明确提示保存内容将遵循目标知识库现有权限；
- 用户只读但不可写的知识库不能成为保存目标。

## 八、交互状态

| 状态 | 产品表现 |
|------|----------|
| AI 正在生成 | 不允许保存 |
| 没有可保存文本 | 不展示保存入口 |
| 正常可保存 | 展示“保存到知识库” |
| 无可写知识库 | 弹窗展示空状态，保存按钮禁用 |
| 正在提交 | 保存按钮进入加载状态 |
| 保存成功 | 关闭弹窗，提示目标并支持查看文档 |
| 保存失败 | 保留弹窗内容，展示原因并允许重试 |

保存按钮启用条件：

```text
已选择可写知识库
+ 标题非空
+ 正文非空
+ 当前没有提交中的请求
```

## 九、实现边界

### 9.1 应复用

- 现有 AI 消息正文提取逻辑；
- 现有知识库列表和权限判断；
- 现有文本知识文档创建能力；
- 现有索引、摘要、查看和编辑能力；
- 现有消息操作区和弹窗组件模式。

### 9.2 不应新增

- Note、Artifact 等领域对象；
- 消息与文档的关系表；
- 专门用于来源追踪的数据结构；
- 重复保存检测逻辑；
- 独立索引任务监控系统；
- 为该功能复制一套知识库权限规则。

是否新增薄接口属于研发实现选择，不构成产品能力。无论采用复用接口还是新增编排接口，都必须遵守本文件的数据与权限边界。

## 十、MVP 验收清单

### 功能

- [ ] 任意已登录对话中的已完成 AI 文本回答可以发起保存；
- [ ] 未选择知识库进行对话时也可以保存；
- [ ] Notebook 当前知识库可写时默认选中；
- [ ] Notebook 当前知识库只读时不默认选中；
- [ ] 用户可以选择可写知识库；
- [ ] 用户可以修改标题和 Markdown 正文；
- [ ] 保存后在目标知识库根目录创建普通文本知识文档；
- [ ] 保存后不改变当前对话上下文；
- [ ] 重复保存允许创建多篇文档；
- [ ] 保存成功后可以查看新文档；
- [ ] 保存失败时保留编辑内容。

### 权限与数据

- [ ] 服务端校验目标知识库写权限；
- [ ] 只保存用户可见的最终正文；
- [ ] 不保存消息、任务、子任务和来源引用关系；
- [ ] 保存弹窗展示目标知识库所属空间和权限提示；
- [ ] 新文档正常进入现有索引流程。

### 回归

- [ ] 原有复制、下载、反馈和重新生成操作不受影响；
- [ ] 知识库文档创建、查看和编辑链路不受影响；
- [ ] 保存操作不会把目标知识库加入当前对话；
- [ ] 保存操作不会引起页面或任务切换。

## 十一、成功指标

MVP 上线后优先验证闭环是否可用：

| 指标 | 定义 |
|------|------|
| 保存发起用户数 | 使用过“保存到知识库”的去重用户数 |
| 保存完成率 | 创建文档成功次数 / 保存提交次数 |
| 保存失败率 | 创建文档失败次数 / 保存提交次数 |
| 保存后查看率 | 保存成功后点击“查看文档”的次数 / 保存成功次数 |
| 后续复用率 | 保存文档在后续被查看、编辑或检索使用的比例 |

具体目标值在获得基线数据后设定，MVP 不为指标体系引入额外产品流程。

## 十二、发布条件

满足以下条件即可发布 MVP：

1. “入口—选择—编辑—创建—查看”完整闭环通过验收；
2. 普通对话、知识库对话和 Notebook 三类场景行为一致；
3. 目标知识库写权限由后端保证；
4. 不保存原消息的敏感来源信息；
5. 文档创建和索引主链路没有回归。

## 十三、后续评估方向

以下能力只有在 MVP 数据证明存在真实需求后再评估：

- 图片、附件等非文本内容转换；
- 更智能的标题和正文整理；
- 保存历史和重复内容提醒；
- 文档与原对话之间的可控追溯；
- 精确引用和可信研究闭环；
- PPT、脑图等 Artifact 生成。

这些方向不影响 MVP 的数据模型和交付范围。
